# 纯 LIF 脉冲语言模型（TinyStories 预训练，CPU）

一个**只由 LIF 神经元组成的有状态计算流**，在 TinyStories 上从零预训练，用来做英文故事的文本补全。

## 0. 项目目标与原则

**目标**：在网络结构保持纯粹由脉冲神经元构成的前提下，用任何方式尽可能提升模型性能，最终目标是**推理性能**匹配 Transformer。

**原则**：
- "脉冲神经网络规模小"是一种刻板印象，不是这个项目的约束。扩大规模，极端情况下扩大到比 Transformer 还大，是合理的选择，
  甚至可能是必须的。
- "追平 Transformer"是一个大致的目标：最终成果只要能在某种合理的意义上解释为达到了 Transformer 的水平即可，
  不预先限定是哪一个 Transformer、哪一项指标。
- 衡量标准是训练好的脉冲网络在推理时的表现（验证集 loss、回看能力、生成质量），和 Transformer 的推理表现比。
  **怎么训练出来的不重要**：训练数据用多少、训练多久、是否用 Transformer 等模型当老师做蒸馏，都不受限制，照常记录即可。
- 参数量、训练和生成速度、状态大小也照常记录，它们是实际算力预算要考虑的因素，但不作为否定一个改进方向的理由。
- "纯粹由脉冲神经元构成"按目前的约定是指：所有状态和非线性都在 LIF 神经元里，神经元之间只通过脉冲经突触传递
  （突触可以是普通突触、低秩分解的突触、带延迟的突触、调节漏电的突触）；不使用注意力、归一化层或非脉冲的非线性单元。
  双室神经元暂不采用。

**硬件目标**：
- 当前的硬件实现候选是 **FPGA** 和**数据流加速器**（权重常驻片上、按数据流动计算的芯片，如 Groq、Tenstorrent、SambaNova、
  Cerebras、IBM NorthPole）。
- **类脑芯片**（Loihi 2、SpiNNaker2、达尔文 3 等）暂不作为目标，原因有两条：现在的网络层与层之间传的是实数总线；
  每个神经元的连接数远多于这类芯片的设计（我们的网络每个神经元约对应 2,400–3,500 个参数，Hala Point 平均每个神经元约 110 个突触）。
  移植上去，要么突触数增加几十倍，要么总线变成普通的矩阵乘法。
- "追平 Transformer"分两层来说：
  - **长期目标：同参数量打平。** 脉冲网络和参数量相同的 Transformer 推理质量相当。在 FPGA 上，这意味着各种场景下都更省
    （每个 token 只需读约一半的权重，也不用保存随文本变长的历史）；在数据流加速器上，短文本大致持平，长文本更省。
  - **近期可以主张的：多路并发、长文本时每个 token 的成本。** 按现在"257M 脉冲网络约等于 30M Transformer"的水平，
    只有在这个场景下脉冲网络读显存的量更少；前提是长文本上的质量得到验证。
- 每批实验除了验证 loss 和回看能力，同时报告硬件代价（`hw_cost.py`，口径见 5.20 节），并和同样算法下的 Transformer 对照。

## 1. "纯 LIF"具体指什么

| 部件 | 在神经元层面是什么 | 代码 |
|---|---|---|
| 输入编码 | 每个词表项对应一个"输入神经元"。读到 token `x_t`，该神经元在第 t 步发放 1 个脉冲，经突触注入电流（数学上等于 embedding 查表） | `SpikingLM.embed` |
| 隐藏层 | 8 个 LIF 神经元群，每群 1536 个，共 12,288 个 LIF 神经元 | `LIFPopulation` |
| LIF 动力学 | `V[t] = β·V[t-1] + I[t]`；`s[t] = [V[t] ≥ θ]`；硬复位 `V ← V·(1-s)`。β（泄漏）和 θ（阈值）每个神经元各自可学习。后续实验里也用部分复位 `V ← V·(1-γ·s)`，γ 每个神经元各自可学习（第 5 节） | `lif_kernel.cpp` |
| 神经元之间的连接 | 只传 0/1 脉冲，突触是线性加权求和（外加一个常数背景电流，即偏置） | `w_in`, `w_out` |
| 跨层连接 | 第 l 群从输入神经元以及之前所有群接收脉冲。这些跳跃突触经过一条 384 维的"电流总线"做了低秩分解：`bus_l = embed[x_t] + Σ_{k<l} W_out_k·s_k`，`I_l = W_in_l·bus_l + b_l`。总线只是脉冲的线性加权和，**没有状态，也没有非线性**；它起的作用相当于 Transformer 的残差流 | `SpikingLM.forward` |
| 输出解码 | 词表大小的一组"读出神经元"，只积分、不发放（β=0），膜电位 = `W_head·bus_L` 就是 logits，经 softmax 后采样出下一个 token | `SpikingLM.head` |
| 记忆 | **只存在于膜电位里**。生成时每一步只携带 12,288 个膜电位，不保存、也不回看历史 token | `SpikingLM.generate` |

**不包含**：注意力、LayerNorm/RMSNorm/BatchNorm、门控或任何乘法交互、层内循环矩阵。
（第 5 节的实验里试过两种可选扩展：低秩的同层连接，以及"调节漏电的突触"。它们默认关闭，正式模型里都没有。）

时间步约定：每个 token 对应一个模拟时间步；在同一时间步内，脉冲逐层向上传播完毕（这是深度 SNN 训练中常用的离散时间约定）。
第九批起可以让每个 token 模拟多个时间步（`--steps_per_token`，5.21 节）。

## 2. 训练方法

- 代理梯度 + 沿时间反向传播（BPTT）：前向用阶跃函数，反向用 fast-sigmoid 代理导数 `1/(1+α|z|)²`，其中 `z=(V-θ)/θ`，α=4。
- LIF 的时间循环写成了 C++/OpenMP 内核（`lif_kernel.cpp`），前向和反向都是手写的，并与纯 PyTorch 参考实现逐项核对过（`test_lif.py`：独立神经元、同层连接、可变漏电三种内核各 12 种配置，相对误差都在 1e-5 以内）。
- 矩阵乘法用 bf16（这颗 CPU 带 AMX，能跑到约 3 TFLOPS），膜电位用 fp32 计算和保存。
- 分词：在 TinyStories 上训练的 4096 词表字节级 BPE（平均约 3.95 字符/token）。

## 3. 消融实验（每组 400 步 × 8192 token ≈ 330 万 token，验证 loss）

| 配置 | 验证 loss | 现象 |
|---|---|---|
| 软复位、sigmoid 代理梯度、截断复位梯度、lr 2e-3（base） | 3.141 | 梯度范数常冲到 100 以上；前 4 层几乎不发放（<1%） |
| base + 改用"缩小权重"做初始化 | 3.198 | 梯度范数冲到 800 |
| base + fast-sigmoid | 2.969 | 各层发放率恢复到 2%–16% |
| **base + 硬复位** | **2.819** | 梯度稳定，所有层都在工作 |
| 硬复位 + fast-sigmoid | 2.779 | |
| 硬复位 + 复位梯度不截断 | 2.736 | |
| 硬复位 + lr 4e-3 | 2.703 | |
| 硬复位 + fast-sigmoid + 不截断 + lr 4e-3 | 2.721 | 梯度最稳（0.38），各层发放率约 3% |
| *参照：同规模 Transformer（12.4M，5 层，lr 2e-3）* | *2.707* | |

几点解读：
1. **硬复位是最关键的一项**。发放即清零，等于让神经元"由输入决定何时遗忘"（类似 Mamba 这类模型的选择性），同时把反向传播在发放时刻截断，梯度不会沿长时间链条累积。
2. **阈值法初始化**：慢神经元（β→1）会累积很大的膜电位。与其缩小它们的输入权重，不如把阈值 θ 调高到 `1/sqrt(1-β²)`。两种做法的前向计算完全等价，但后一种让 Adam 对所有权重的相对更新幅度一致，训练初期更平稳。
3. 同样 330 万 token 时，纯 LIF 网络和同规模的 Transformer 基本持平。这只是训练早期的单次对比，Transformer 的超参数也没有专门调。

## 4. 正式训练结果

配置：8 层 × 1536 LIF（共 12,288 个神经元，12.62M 参数），硬复位 + fast-sigmoid 代理梯度 + 复位梯度不截断，
batch 32 × 256，14,000 步 = 1.15 亿 token（约占训练集的 1/5，每条数据最多见一次），学习率峰值 3e-3、余弦衰减，
4 核 CPU 训练 2 小时 45 分钟（约 11,500 token/s）。

| 指标（完整验证集，557 万 token） | 数值 |
|---|---|
| 验证 loss | **1.912 nats/token**（困惑度 6.76） |
| 每字符比特数 | **0.696 bits/char**（与分词方式无关，可横向比较） |
| 平均发放率 | 训练末期约 4%（每个 token 约 500 个神经元发放，共 12,288 个） |
| 流式生成速度 | 约 610 token/s（batch 1，单 CPU；每步只携带膜电位，代价不随上下文变长而增加） |

验证 loss 随训练的变化（每 1000 步）：2.71 → 2.55 → 2.46 → 2.39 → 2.31 → 2.27 → 2.20 → 2.15 → 2.09 → 2.04 → 1.99 → 1.95 → 1.93 → 1.91。
训练结束时曲线还在下降，没有饱和，继续训练应该还能变好。

**样例**（温度 0.8，top-k 50；前缀部分为人工给定）：

> **Once upon a time**, there was a little girl named Mia. She had a pet dog named Max. ... One sunny day, Mia and Max went to the park. ...
> In the end, they were not grumpy anymore. They both had a great time and were very happy.

> **Lily wanted to go to the park, but** she did not know how. "Look, Ben, I found a big box!" Ben said. Lily opened the box and found many colorful balls. ...
> "Help, help, dog!" Lily shouted. "We can't get out!" They pulled and pulled, but the dog did not come.

> **One day, a little bird could not fly. It** was so very high. The bird was sad. ... A girl named Lily wanted to help the bird. She had an idea. ...
> The bird and Lily became good friends. They sang together every day.

完整样例见 `runs/main/final_eval.json`。

**观察到的现象**
1. **时间常数的分布主要来自初始化，不是训练学出来的**（`figs/time_constants.png`）：时间常数初始化为 0.5–200 token 之间对数均匀分布。
   重建初始权重后逐个神经元对比，训练前后的相关系数是 0.976，整体只略向慢的方向移动（中位数约从 10 token 变为 12 token）；
   阈值 θ 的变化大一些（相关系数 0.758）。早先版本的 README 把图中的形状解读为"快慢神经元自发分化"，这是误读，特此更正。
2. **稀疏发放**（`figs/raster.png`）：各层发放率约 4%–6%。故事开头（"Once upon"）会出现一次大范围的同步发放，之后转为稀疏活动。
3. **主要弱点：精确复述上文中的罕见词**。人名前后不一致（"Tom and Tom"、he/she 混用），给一个罕见名字（如 "Bolt"）它很快就记丢了。Transformer 能用注意力直接回看原文，这个网络却必须把身份信息压进膜电位再还原出来，对 1 比特/步的 LIF 群体来说很难。偶尔还会陷入重复（"You are mean. You are rude..."）。

**和 Transformer 对照组的比较**：330 万 token 时两者都约 2.70；1230 万 token 时 Transformer 已明显领先（2.046 对 2.31–2.37）。
相同 1.15 亿 token 预算的对照见 5.7 节。

## 5. 后续实验：复位方式、同层连接、扩大规模、神经元参数的学习率

正式训练之后，模型最明显的弱点是"记不住上文里的具体内容"（人名前后不一致等）。
这一节的实验都围绕一个问题：**这个网络能在多大程度上借助膜电位回看上文，怎样能让它回看得更好。**

除特别说明外，短实验都是 1500 步 × 8192 token = 1230 万 token、12.6M 参数（8 层 × 1536），
"验证 loss"是固定的 40 个验证 batch（约 33 万 token）上的平均值。
同一设置换随机种子重跑（第四阶段测了两组）：验证 loss 相差 0.001–0.004；测量 B 的回看收益相差 0.03–0.10，
测量 A 的上文收益相差约 0.003。所以短实验之间验证 loss 0.01 以上的差别是可信的，回看收益要差 0.1 左右才算明显。

### 5.1 两种测量"回看能力"的方法

**测量 A：截断上文**（`probe_memory.py`）。取验证集里足够长的故事，只看第 128–191 个 token 上的 loss；
让模型从第 128 个 token 之前 k 个 token 处开始读（脉冲网络从静息状态开始）。k 从 8 增加到 128 时 loss 降了多少，
就是 8 个 token 以外的上文对它的帮助（表中记作"上文收益"）。

**测量 B：重复出现的词**（`probe_recall.py`）。找出故事中重复出现的内容词（排除最常见的 150 个词，
剩下的主要是人名、物品名），比如第 30 个 token 是 "Lily"，第 110 个 token 又要预测 "Lily"，两次相距 80。
对这个词比较两种条件下的 loss：读了整篇故事 / 只读最近 16 个 token（早先那次出现被截掉）。
两者之差就是"早先的内容对预测这个词的帮助"，按距离分组。差值 1 表示正确词的概率平均提高到约 e ≈ 2.7 倍。
对照组是故事里第一次出现的内容词：它们不可能靠"回忆同一个词"受益，上文只能通过故事大意帮忙，约 0.2。

**净回看收益（第七批之后补充）。** 测量 B 的差值有一个弱点：如果一个模型在"只读最近 16 个 token"时变差了
（比如它不太会从故事中间冷启动），差值也会变大，看起来像是回看能力变强了，实际上记忆并没有变好。
对照组（第一次出现的词）同样受冷启动的影响，所以用"重复词的收益 − 第一次出现的词的收益"可以扣掉这部分，
剩下的才是"回忆同一个词"本身带来的帮助，记作净回看收益。5.18 节起两种数字都列出，比较时以净回看收益为准；
`slurm/recall_gains.py` 也同时打印两者。

### 5.2 第一阶段：复位方式和同层连接（各 1230 万 token）

| 配置 | 验证 loss | 训练速度（token/s） | 上文收益（测量 A） |
|---|---|---|---|
| 基线：硬复位（γ = 1） | 2.366 | 14,100 | 0.066 |
| 部分复位，γ 可学习，初值 0.9 | 2.350 | 13,500 | 0.072 |
| 同层连接（低秩，秩 128） | 2.350 | 8,400 | 0.072 |
| 部分复位 + 同层连接 | 2.333 | 8,500 | 0.075 |
| **部分复位，γ 初值在 0.05–1 之间均匀铺开** | **2.313** | 13,800 | **0.086** |
| *参照：Transformer（12.4M，5 层）* | *2.046* | *10,800* | *0.178* |

- 让一部分神经元"发放后只清掉一小部分膜电位"（γ 小）是最划算的改动：不增加计算量，loss 和回看都有改善。
- 同层连接有一点帮助，但让训练慢了约 40%，按相同时间算并不划算，后面没有再用。按第 0 节的原则（以相同训练数据下的效果为准），它值得在更大规模上重新评估。
- 和 Transformer 的差距，大约 70% 出在 8 个 token 以内的局部预测上（k = 8 时差 0.29，k = 128 时差 0.41）。

### 5.3 第二阶段：扩大规模（1.15 亿 token）

配置：10 层 × 2048 个 LIF 神经元（共 20,480 个），总线 512 维，25.25M 参数；γ 初值铺开；峰值学习率 2.5e-3（正式模型是 3e-3）；
其余和正式训练相同。4 核 CPU 约 5 小时 20 分钟（中途容器重启一次，从第 6000 步的存档接着训练）。

| 指标（完整验证集） | 正式模型（12.6M） | 大模型（25.25M） |
|---|---|---|
| 验证 loss | 1.912 | **1.793** |
| 每字符比特数 | 0.696 | **0.653** |
| 上文收益（测量 A） | 0.148 | 0.169 |
| 流式生成速度（batch 1） | 610 token/s | 326 token/s |

同一步数下大模型的验证 loss 始终低约 0.09–0.13；第 10,000 步时已和正式模型训练完的结果持平。
样例（温度 0.8，top-k 50）：

> **Once upon a time**, there was a little girl named Mia. Mia was very upset because she lost her toy car. She looked everywhere, but it was not there.
> Mia's mom saw her crying and asked her what was wrong. Mia told her mom that she lost her toy. Her mom hugged her and said, "Don't worry, Mia. We will find your toy car."
> Mia and her mom found the toy car under her bed. Mia was so happy that she hugged her mom. ...

局部更通顺了，但角色身份混淆仍然常见（同一段里 "wise old man" 和 "wise owl" 来回切换，"Sam and Sam went back to their homes"）。

### 5.4 第三阶段：神经元参数的学习率

前面发现，β、θ、γ 这些每个神经元自己的参数在 1500 步里几乎不动（训练前后相关系数 ≥ 0.98）。
这里把它们的学习率单独放大 10 倍或 30 倍（其余参数不变）：

| 配置 | 验证 loss | τ 前后相关 | θ 前后相关 | γ 前后相关 | 上文收益（测量 A） |
|---|---|---|---|---|---|
| γ 铺开，×1 | 2.313 | 0.999 | 0.987 | 0.998 | 0.086 |
| γ 铺开，×10 | **2.295** | 0.959 | 0.693 | 0.898 | 0.087 |
| γ 铺开，×30 | 2.303 | 0.866 | 0.529 | 0.687 | 0.091 |
| γ 统一 0.9，×1 | 2.350 | 0.999 | 0.979 | — | 0.072 |
| γ 统一 0.9，×30 | 2.341 | 0.863 | 0.561 | — | 0.082 |

学习率放大后这些参数确实动起来了，而且学到的变化有规律。以"γ 统一从 0.9 出发、×30"为例：

| 初始时间常数 τ | γ 平均值（训练前 → 后） | γ < 0.5 的比例（训练后） |
|---|---|---|
| < 2 token | 0.90 → 0.78 | 17% |
| 2–10 | 0.90 → 0.65 | 29% |
| 10–50 | 0.90 → 0.66 | 31% |
| > 50 | 0.90 → 0.62 | 38% |

也就是**时间常数越长的神经元，学到的复位越轻**（发放时保留更多膜电位），越靠前的层降得越多。
这说明 γ 的梯度虽然每一步都很嘈杂（Adam 的 |m|/√v 中位数约 0.15，和纯噪声差不多），但里面有一个微弱、稳定的方向；
学习率为 ×1 时步子太小，1500 步里积累不出来。不过即使学动了，它也没追上"一开始就把 γ 铺开"的效果（2.341 对 2.313）。

### 5.5 回看能力随距离的变化（测量 B）

| 早先出现的距离 | γ=1，1230 万 | γ 铺开，1230 万 | γ 铺开 ×30，1230 万 | 正式模型 12.6M，1.15 亿 | 大模型 25.25M，1.15 亿 | Transformer，1230 万 |
|---|---|---|---|---|---|---|
| 17–32 | 0.52 | 0.69 | 0.79 | 1.80 | 2.17 | 2.09 |
| 33–64 | 0.39 | 0.48 | 0.56 | 1.33 | 1.59 | 1.66 |
| 65–128 | 0.29 | 0.35 | 0.39 | 0.87 | 0.97 | 1.14 |
| 129–256 | 0.24 | 0.31 | 0.32 | 0.52 | 0.68 | 0.77 |
| 对照：首次出现 | 0.16 | 0.16 | 0.17 | 0.21 | 0.25 | 0.20 |

1. **能回看，但距离越远越弱。** 正式模型对 17–32 个 token 前出现过的词，把正确词的概率平均提高到约 6 倍；129–256 个 token 时只有约 1.7 倍。
2. **训练量影响最大。** 同样结构，训练量增加 10 倍，各距离上的回看收益都翻了一倍以上。训练量少时，连 1–4 个 token 前刚出现过的词也抄得很差（loss 3.48，首次出现的词是 4.10；训练充分后是 2.09 对 3.39）。
3. **规模有帮助，远距离也在涨**（大模型对正式模型：129–256 从 0.52 到 0.68），但比较慢。
4. **放大神经元参数的学习率只改善了近距离**（17–64），最远的一档基本没变。
5. 即使是只训练了 1/10 数据量的 Transformer，在 65 个 token 以外仍然领先，而且距离越远，脉冲网络的相对差距越大。

### 5.6 为什么越远越弱：结构上的原因

- **漏电速度固定，和内容无关。** 膜电位每一步乘以固定的 β，重要和不重要的信息按同样速度消失。
- **读出会擦除。** 神经元把信息传出去的唯一方式是发放，而发放会复位。γ 铺开之所以有效，和"让一部分神经元发放时不清空"是一致的。
- **信息叠加在固定数量的膜电位里**，不同 token 的信息混在一起；Transformer 则每个 token 单独存放。

前两条由方程本身决定，靠训练改变不了。为此加入了可选的**调节漏电的突触**（`--leak_rank`）：
除了注入电流的普通突触，再加一组来自同样突触前脉冲的低秩突触，它们不注入电流，而是改变神经元当前这一步的漏电速度：
`β[t] = sigmoid(β_logit + U·bus[t])`。这样网络可以在读到重要内容时让某些神经元几乎不漏电，在话题切换时让它们快速清空。
U 初始为零，所以训练开始时和原网络完全相同。这和神经科学里的电导型突触思路一致；
不过这里的调节是双向的（既能减慢也能加快漏电），而生物上的电导型突触通常只能加快漏电。

### 5.7 公平对照：同样 1.15 亿 token 的 Transformer

Transformer 对照组：5 层，d_model 384，6 个注意力头，12.39M 参数（和正式模型的 12.62M 基本相同），
数据、batch、步数、学习率调度都和正式模型一样（`runs/tf_full`）。

| 测量 A：完全没有上文时（k=0） | 2.402 | 2.286 | **2.024** |

测量 B（"读整篇 / 只读最近 16 个 token"的 loss 差）：

| 早先出现的距离 | 脉冲网络 12.6M | 脉冲网络 25.25M | Transformer，1230 万 token | Transformer，1.15 亿 token |
|---|---|---|---|---|
| 17–32 | 1.80 | 2.17 | 2.09 | **3.05** |
| 33–64 | 1.33 | 1.59 | 1.66 | **2.63** |

| 129–256 | 0.52 | 0.68 | 0.77 | **1.39** |

1. **差距很明显。** 同样的参数量和训练量，Transformer 的验证 loss 低 0.43；脉冲网络参数翻倍只追回了其中 0.12。
2. **差距不只在远距离。** 完全没有上文时（测量 A 的 k=0），Transformer 也领先约 0.38；读整篇时，对 1–4 个 token 前刚出现过的词，
   Transformer 的 loss 是 1.04，脉冲网络是 2.09。也就是说，脉冲网络在"处理眼前几个词"上就已经落后，不能全部归因于记忆距离。
3. **远距离的相对差距更大。** 129–256 个 token 之外的回看收益，Transformer 是脉冲网络（12.6M）的约 2.7 倍；17–32 时约 1.7 倍。
   而且 Transformer 的回看收益随训练量增长得也很快（从 1230 万到 1.15 亿 token，129–256 一档从 0.77 涨到 1.39），差距并没有随训练缩小。
4. **脉冲网络的长处在状态大小。** 生成时它只需要保存 12,288 个膜电位，和上文多长无关；Transformer 要保存每个已读 token 的键和值，
   读到第 256 个 token 时是 5 层 × 2 × 384 × 256 ≈ 98 万个数，并随上文线性增长。
   （`final_eval.json` 里 Transformer 的生成速度约 61 token/s，脉冲网络约 610 token/s，但这里的 Transformer 生成没有做键值缓存，
   每一步都把整段上文重算一遍，所以这个速度比较对 Transformer 不公平，不能作为结论。）

### 5.8 第四阶段：调节漏电的突触

配置和 5.2 节最好的一组相同（γ 初值铺开，1230 万 token），只是加上调节漏电的突触（5.6 节），并换随机种子重跑。

| 配置 | 参数量 | 验证 loss（种子 0 / 种子 1） | 上文收益（测量 A） | 训练速度（token/s） |
|---|---|---|---|---|
| 无（γ 铺开） | 12.63M | 2.313 / 2.312 | 0.086 / 0.083 | 约 12,200 |
| **调节漏电的突触，秩 64** | 13.62M | **2.234 / 2.230** | **0.102 / 0.102** | 约 6,500 |
| 调节漏电的突触，秩 256 | 16.56M | 2.233 | 0.098 | 约 5,800 |

测量 B（"读整篇 / 只读最近 16 个 token"的 loss 差）：

| 早先出现的距离 | 无，种子 0 | 无，种子 1 | 秩 64，种子 0 | 秩 64，种子 1 | 秩 256 |
|---|---|---|---|---|---|
| 17–32 | 0.69 | 0.73 | 0.76 | 0.84 | 0.76 |
| 33–64 | 0.48 | 0.52 | 0.59 | 0.66 | 0.56 |
| 65–128 | 0.35 | 0.38 | 0.46 | 0.52 | 0.48 |
| 129–256 | 0.31 | 0.34 | 0.37 | 0.47 | 0.43 |
| 对照：首次出现 | 0.16 | 0.18 | 0.17 | 0.20 | 0.19 |

1. **验证 loss 降低约 0.08，远大于换种子的差别（0.001–0.004）。** 作为比较，γ 铺开相对 γ = 1 的改善是 0.05。
2. **远距离回看也变好了。** 65–256 个 token 这两档平均提高约 0.1（约 30%），大于换种子的差别，但幅度不算大；
   这是第一个在远距离上明显起作用的改动（5.4 节放大学习率时，最远一档基本没变）。
3. **秩 256 并不比秩 64 好**，虽然它对漏电的调节幅度大得多（见下）。
4. **代价是训练变慢。** 每一步都要为每个神经元算一次新的漏电系数，第四阶段时整体训练速度约为原来的一半（约 6,500 对 12,300 token/s）。
   早先估计"只慢 10% 左右"是测量时 CPU 被其他任务占用导致的误判，特此更正。
   之后把这部分计算合并进了 C++ 内核（结果逐位相同）：单层单独计时是普通层的 1.86 倍（之前 2.16 倍），
   整个模型训练时约 9,900 对 11,500 token/s（第六阶段实测），只慢约 15%。

**网络学到了怎样调节漏电**（`leak_stats.py`，64 个验证故事；"慢神经元"指静息时间常数超过 20 个 token 的神经元）：

- **调节用得很多。** 秩 64 时，同一个神经元的时间常数随 token 变化，标准差相当于 4–16 倍（以 10 为底的对数 0.6–1.2）。
  平均而言时间常数变长了（多数层约 2–7 倍）：50%–65% 的时刻比静息值长 2 倍以上，20%–35% 的时刻短 2 倍以上。
- **越深的层越常"清空"。** 慢神经元的时间常数瞬间降到 2 个 token 以下的比例，从第 0 层的约 1% 增加到第 7 层的约 17%。
- **第 0 层只看当前这个 token，可以直接看出它对哪些词怎么反应。** 读到逗号、句号、the、to、and 这类虚词时，
  慢神经元的时间常数拉得最长（约 13–25 倍）；1500 步时，人名（Mom、Ben、Tom、Anna）和物品（boat、slide、door）拉长得最少，
  甚至略微缩短。**但这一点随训练变了**：训练到 5000 步时（5.10 节），Lily、Tim 等人名已经排在拉长最多的词里，
  只有 slide、paper、boat 等少数物品词仍让记忆变短。所以稳定的规律只是"虚词和标点让慢神经元保持记忆"，
  "内容词让记忆更新"是训练早期的现象，不能当作结论（早先的汇报里我把它当成了结论，特此更正）。
  近年的选择性状态空间模型（如 Mamba）也是让"保留多少旧状态"随输入变化，思路相近。
- **神经元本身的静息漏电几乎没变**（训练前后相关系数 0.999），调整都由漏电突触完成。

**变化本身是否重要**（`leak_ablate.py`，64 个验证窗口）：把每个神经元逐步变化的漏电换成它自己的平均值，
loss 从 2.17 变为 3.30；全部换回静息漏电是 2.84，都比没有漏电突触、正常训练出来的网络在同样窗口上的 2.25 差得多。
这说明训练好的网络确实在大量依赖"漏电随内容变化"，而不只是把时间常数整体调长了。
（这个检查是在训练好之后才把变化拿掉，网络来不及适应，所以只能说明它"用了"这种变化；
要回答"静态漏电如果初始化得更长，能否达到同样效果"，还需要单独训练对照。）

### 5.9 第五阶段：参数量对照和突触延迟

**参数量对照。** 调节漏电的突触（秩 64）多了约 100 万个参数。为了排除"只是参数多了"，
把每层神经元从 1536 个加到 1696 个，使总参数量同样是 13.62M，其余不变：验证 loss 2.306，只比 2.313 好 0.007，
远小于漏电突触带来的 0.08。各距离的回看收益也和不加宽时基本一样（129–256 一档 0.26）。所以改善来自"漏电可以随内容变化"，不是参数量。

**突触延迟（方向 C）。** 加上延迟 1 和 2 个 token 的低秩突触（秩 64，13.81M 参数，见 `model.py` 开头的说明），
让神经元能直接对"现在这个词和前一两个词"的组合作出反应：

| 配置 | 验证 loss（种子 0 / 种子 1） | 上文收益（测量 A） | 回看收益 65–128 / 129–256 | 训练速度（token/s） |
|---|---|---|---|---|
| 无（γ 铺开） | 2.313 / 2.312 | 0.086 / 0.083 | 0.35–0.38 / 0.31–0.34 | 约 12,200 |
| 加宽到 1696 | 2.306 | 0.086 | 0.37 / 0.26 | 约 11,500 |
| 突触延迟 1–2 步 | 2.310 / 2.306 | 0.082 / 0.082 | 0.35–0.36 / 0.30–0.35 | 约 10,500 |
| *参照：调节漏电的突触，秩 64* | *2.234 / 2.230* | *0.102 / 0.102* | *0.46–0.52 / 0.37–0.47* | *约 6,500* |

突触延迟几乎没有带来改善。但网络确实用上了它们：训练好以后把延迟突触去掉，loss 从 2.245 升到 2.76。
也就是说，网络把一部分"前一两个词是什么"的信息改走延迟突触，而不是额外多学到了什么；
原来靠膜电位也能拿到这些信息。由此看，**脉冲网络和 Transformer 在近距离上的差距，瓶颈不在"拿不到前一两个词"。**

### 5.12 第八阶段：训练方法（GPU 上训练满 1.15 亿 token）

网络固定为 12.6M 脉冲网络（γ 铺开 + 调节漏电的突触，秩 64），学习率 3e-3，每种方法都训练 14000 步（1.15 亿 token），
只改训练方法（`gpu1.sh` 的 (c) 组）。对照组 `g1_s_base` 的验证 loss 是 1.752
（不加漏电突触、不铺开 γ 的正式模型是 1.912）。

| 训练方法 | 验证 loss | 相对对照组 |
|---|---|---|
| 蒸馏：老师是 12.4M Transformer（`g1_tf_full`），老师占比 0.9 | **1.672** | **−0.080** |
| 蒸馏，老师占比 0.5 | 1.684 | −0.069 |
| 权重滑动平均（0.998），用平均后的权重评估 | 1.720 | −0.033 |

| Transformer | 104.6M | 1e-3 | 1.156 | 0.365 | 2.12 / 1.70 |

1. **两种网络都随规模稳定变好。** 脉冲网络参数每翻一倍，验证 loss 大约下降 0.065；Transformer 在小规模时下降得差不多快，
   到 55M 以上开始变慢。
2. **差距用参数量来衡量，目前大约是十倍。** 117M 的脉冲网络（1.391）比 12.4M 的 Transformer（1.357）还差 0.034。
   按上面的斜率推算，脉冲网络大约要 170M 才能追平 12.4M 的 Transformer。
3. **记忆能力的差距在缩小。** 129–256 个 token 的回看收益，12.6M 脉冲网络训练 1.15 亿 token 时只有 0.52，
   而同等训练量的 Transformer 是 1.38；现在 117M 脉冲网络达到 1.29，12.4M Transformer 是 1.56。
4. **数据量本身很重要。** 同样是 12.4M 的 Transformer，训练 5.49 亿 token（1.357）比训练 1.15 亿 token（1.480）好 0.12；
   26.9M 的脉冲网络从 1.709 降到 1.529，好了 0.18。
5. 两个最大的模型都是较低的学习率更好，说明大模型的学习率还可以再往下调。

### 5.14 第三批：三种训练方法能否叠加

网络、数据量和对照组都和第八阶段相同（12.6M 脉冲网络，1.15 亿 token，对照组 1.752；`gpu3.sh`）。
蒸馏的老师仍是 12.4M Transformer（`g1_tf_full`，1.480），老师占比 0.9、温度 1；用了权重滑动平均的，都用平均后的权重评估。
回看收益是 129–256 个 token 一档（测量 B，用的是未平均的权重；事后用平均后的权重补测过，
三个用了滑动平均的组合变化都在 0.03 以内：三者一起 0.95，蒸馏 + 滑动平均 0.98，滑动平均 + 神经元学习率 0.90）。

| 对照组 | 1.752 | | | 0.77 |

### 5.16 第五批：神经元个数（状态大小）是不是远距离回看的瓶颈

**问题。** 脉冲网络对过去的全部记忆都存在膜电位里，所以它能记住多少，取决于神经元的个数（每层神经元数 × 层数），
而不直接取决于参数量。第二批扩大规模时，层间总线（d_model）和每层神经元是一起加宽的，参数涨得比神经元快
（27M → 117M：参数 4.4 倍，神经元只有 2.4 倍），129–256 一档的回看收益也只从 1.17 提高到 1.29。
所以要单独检验：参数量不变、只增加神经元，远距离回看会不会变好？

**做法。** 以第二批的 117M 网络为基准（总线宽 1024，每层 4096 个神经元，12 层，共 49,152 个神经元），
把总线变窄、每层神经元加多，让参数量基本不变：神经元翻倍（总线 512，每层 8192 个），和神经元变成三倍（总线 384，每层 12288 个；
这一组参数多了 17%）。都不用三种训练方法，数据、步数、学习率调度和第二批完全相同（5.49 亿 token，`gpu5.sh`）。

| 网络 | 总线宽 | 每层神经元 | 神经元总数 | 参数 | 学习率 | 验证 loss | 上文收益（测量 A） | 回看收益 17–32 / 33–64 / 65–128 / 129–256 |
|---|---|---|---|---|---|---|---|---|
| 基准 | 1024 | 4096 | 49,152 | 117.1M | 8e-4 | **1.391** | 0.270 | 2.65 / 2.28 / 1.73 / 1.29 |
| 基准 | 1024 | 4096 | 49,152 | 117.1M | 1.2e-3 | 1.411 | 0.266 | 2.64 / 2.29 / 1.68 / 1.21 |
| 神经元 ×2 | 512 | 8192 | 98,304 | 118.6M | 8e-4 | 1.416 | 0.261 | 2.55 / 2.17 / 1.61 / 1.08 |
| 神经元 ×2 | 512 | 8192 | 98,304 | 118.6M | 1.2e-3 | 1.426 | 0.257 | 2.56 / 2.22 / 1.64 / 1.25 |
| 神经元 ×3 | 384 | 12288 | 147,456 | 136.4M | 8e-4 | 1.432 | 0.249 | 2.56 / 2.12 / 1.49 / 1.05 |

1. **神经元多了，验证 loss 没有变好，反而略差。** 在相同学习率下比较：8e-4 时，神经元翻倍差 0.025，变成三倍差 0.041
   （尽管参数还多了 17%）；1.2e-3 时，神经元翻倍差 0.015。整个训练过程中，验证 loss 曲线都比基准略高一点，并没有后来居上的迹象。
2. **远距离回看也没有变好。** 129–256 一档：8e-4 时从 1.29 降到 1.08（×2）和 1.05（×3）；1.2e-3 时从 1.21 变成 1.25，
   基本持平。这一档的数字本身有一定波动（同一个 ×2 网络，两种学习率之间差了 0.17），但方向很一致：没有一组明显变好。
   近距离（17–32）各组都比基准低 0.09 左右；上文收益（测量 A）也随神经元增多从 0.27 降到 0.25。
3. **多出来的神经元确实在工作。** 训练结束时三种网络的平均发放率差不多（2.7%、2.7%、2.4%），
   所以每层每个 token 发出的脉冲数从 111 个增加到 223 个和 298 个。不是"多出来的神经元一直沉默"造成的。
4. **需要注意的一点：** 这个实验在加神经元的同时把总线变窄了（参数量要保持不变，只能这样换）。
   总线是层与层之间传递信息的通道，它变窄可能抵消了状态变大的好处。所以严格地说，这一批证明的是
   "在参数量固定时，用总线宽度去换神经元个数没有好处"，而不是"神经元再多也没用"。
   不过第四批从 117M 到 257M 时，总线和神经元都变大了（神经元 49,152 → 73,728），129–256 一档同样没有提高
   （普通训练 1.29 → 1.29，加三种方法 1.51 → 1.49）。两个方向的证据合在一起，说明在 256 个 token 的范围内，
   单纯把网络做大或者把状态做大，都不能直接提高远距离回看。
5. **速度：** 神经元越多，每个 token 的计算越慢，神经元 ×2 的网络在 A100 上每秒约 6.5 万 token，训练用了 2.3 小时。

**结论：远距离回看主要卡在"学不学得会"，而不是"装不装得下"。** 要记住远处的词，网络至少需要三样东西：
有地方存（神经元个数）、有连接把信息存进去和取出来（参数）、以及训练过程能教会它在该存的时候存、该取的时候取。
目前看，前两样都不是瓶颈：状态翻倍、变三倍，参数翻倍，129–256 一档都不提高；而网络大小完全不变、只加上蒸馏，
117M 网络就从 1.29 提高到了 1.51（第四批；按 5.1 节后来补充的净回看收益是 0.93 → 1.10，结论不变）。
蒸馏改变的只是训练信号，所以瓶颈更可能在训练这一边。
这也回答了"参数量是不是应该匹配回看窗口"的问题：至少在 256 个 token 以内，现在的网络并不缺参数或状态，
缺的是让它学会长距离存取的训练信号。更长的窗口（比如上千个 token）是否会需要更大的状态，这一批还回答不了。

### 5.17 第六批：在训练集上多过几遍

**问题。** 第四批里，脉冲网络从 117M 加到 257M，验证 loss 只改善了 0.036，比第二批"参数每翻一倍改善约 0.065"小得多。
一个可能的原因是 257M 的网络数据不够：它只看了 5.49 亿 token，平均每个参数约 2 个 token。
如果是这样，多给数据时 257M 应该比 117M 受益更多。

**做法。** 把第四批两个加了三种方法的网络在训练集上过两遍（134000 步，11.0 亿 token），117M 再加一个过三遍的（16.5 亿 token）；
105M Transformer 也过两遍，作为对照。训练集只有 5.52 亿 token，所以多出来的训练量是把同一批故事再读一遍。
其余设置和第四批完全相同（`gpu6.sh`）。用了滑动平均的网络，表中所有数字都用平均后的权重。

| 模型 | 参数 | 训练量 | 验证 loss | 上文收益（测量 A） | 回看收益 65–128 / 129–256 |
|---|---|---|---|---|---|
| 脉冲 + 三种方法 | 117.1M | 1 遍（5.49 亿 token） | 1.278 | 0.297 | 1.88 / 1.51 |

| 脉冲 + 三种方法 | 117.1M | 3 遍（16.5 亿） | 1.226 | 0.315 | 1.92 / 1.54 |

   第三遍只再改善 0.012，重复使用同一批故事的收益在快速变小。
2. **"257M 特别缺数据"的猜测不成立。** 如果 257M 比 117M 更缺数据，第二遍对它的帮助应该明显更大，实际只多了 0.003。
   过两遍时，117M → 257M 的改善是 0.039，和过一遍时的 0.036 差不多。所以参数加倍收益变小，原因不在数据量。
   剩下的可能有两个：一是 257M 的学习率不合适（只试过 5e-4）；二是网络的形状——117M 到 257M 只是把每层加宽
   （总线 1024 → 1536，层数都是 12），而 27M 到 48M 时层数也从 10 层加到了 12 层。第八批检验这两点。
3. **同样多的数据下，和 Transformer 的差距没有缩小。** 105–117M 这个量级，过一遍时差 0.141，过两遍时差 0.147。
4. **远距离回看随数据增加略有提高。** 257M 在 129–256 一档从 1.49 提高到 1.57，表面上超过了 12.4M Transformer（1.56）；
   117M 从 1.51 提高到 1.55，第三遍不再提高（1.54）。但按后来补充的净回看收益（5.1 节，扣掉对照组），

   多读一遍对远距离回看帮助不大，257M 已经很接近 12.4M Transformer，但还没有超过。
5. **目前最好的脉冲网络。** 257M、蒸馏、过两遍：验证 loss 1.199，好于只训练一遍的 29.9M Transformer（1.245），
   接近只训练一遍的 55.1M Transformer（1.190）；远距离回看接近 12.4M Transformer。按项目原则，训练方式不同是允许的，
   比的是推理时的表现。但也要说清楚：Transformer 用同样多的数据也会变好（105M 好了 0.045），
   如果 29.9M Transformer 也过两遍、同样改善 0.04 左右，大约是 1.20，和这个脉冲网络差不多。
   也就是说，在训练量相同的公平比较下，257M 脉冲网络大约相当于 30M 的 Transformer，参数量相差 8 倍多，这个比例和第四批一样。
6. 速度：257M 两遍在 H200 上每秒 17.3 万 token，约 1.8 小时；117M 三遍超过了 3 小时的限制，续跑了一次。

### 5.18 第七批：加长训练片段

**问题。** 5.16 节的结论是瓶颈在训练信号，而训练数据本身有一个特点：TinyStories 的故事很短
（平均 202 个 token，中位数 179，只有 13% 达到 256 个 token），训练时又是从整个文本里随机截取 256 个 token 的片段，
片段通常从某个故事的中间开始。在训练数据上统计：一个位置在片段内能看到本故事前文超过 128 个 token 的，只占 17.9%；
超过 192 个 token 的只占 3.6%。网络在训练中很少有机会练习"回看 129–256 个 token"，这会不会是远距离回看弱的原因？
片段加长到 512 个 token，这两个比例会提高到 27.1% 和 9.2%。

**做法。** 第二批的 117M 网络（学习率 8e-4，不用三种方法），训练片段从 256 加长到 512 和 1024 个 token，
批大小相应减到 16 和 8，每步的 token 数（8192）、总步数和学习率调度都不变（`gpu7.sh`）。验证 loss 仍然在 256 个 token 的片段上测。
另外在较长的故事上（至少 513 个 token，约占 2%）把回看测量延伸到 512 个 token（`probe_recall.py --length 512`），
新增 257–512 一档；用 256 个 token 训练的网络从没在第 256 个 token 以后运行过，这一档也顺带检验它们能不能接着往下读。
表中"净"是 5.1 节的净回看收益（扣掉第一次出现的词的收益）；"冷启动 loss"是测量 A 中 k=0（从故事中间、静息状态开始读）的 loss。

| 训练片段 | 验证 loss | 冷启动 loss | 上文收益（测量 A） | 129–256 回看收益 / 净 | 长故事上的净回看 129–256 / 257–512 | 长故事 257–512 处重复词的 loss |
|---|---|---|---|---|---|---|
| 256（第二批） | **1.391** | **1.914** | 0.270 | 1.29 / **0.93** | 0.61 / 0.20 | 2.74 |
| 512 | 1.408 | 1.955 | 0.295 | 1.28 / 0.86 | 0.63 / 0.27 | 2.65 |
| 1024 | 1.425 | 1.995 | 0.310 | 1.33 / 0.86 | 0.65 / 0.30 | 2.65 |
| （对照）256，117M + 三种方法 | 1.278 | 1.798 | 0.297 | 1.51 / 1.10 | 0.69 / 0.33 | 2.39 |
| （对照）256，257M + 三种方法 | 1.242 | 1.761 | 0.306 | 1.49 / 1.06 | 0.71 / 0.37 | 2.27 |

1. **验证 loss 变差了。** 片段 512 差 0.018，1024 差 0.034。冷启动明显变差（1.914 → 1.955 → 1.995）：
   256 个 token 的片段，每个片段都要从静息状态开始读一次；片段越长，这样的练习越少，而验证正是在 256 个 token 的片段上、从静息状态开始测的。
   上文足够长时（k=128）也差了 0.014 和 0.031，可能还因为每步只有 16 或 8 段不同的文字，每步的样本不如原来多样。
2. **256 个 token 以内，远距离回看并没有变好。** 未扣对照组的回看收益看起来持平或略升（1.29 → 1.28 → 1.33），上文收益也升了
   （0.270 → 0.310），但这主要是因为"只读最近 16 个 token"那一边变差了（冷启动变差）。扣掉对照组以后，净回看收益从 0.93 降到 0.86；
   读了整篇时，重复词本身的 loss 也从 2.06 升到 2.18 和 2.21。所以"长距离例子太少"不是远距离回看弱的主要原因：
   超过 192 个 token 的例子增加到约三倍，129–256 一档却没有提高。
3. **256 个 token 以外，加长片段有帮助。** 长故事上 257–512 一档的净回看从 0.20 提高到 0.27 和 0.30，重复词的 loss 从 2.74 降到 2.65。
   这主要是"在更长的时间里保持正常工作"的能力：用 256 个 token 训练的网络从没在第 256 个 token 以后运行过。
   不过，加了三种方法、只用 256 个 token 训练的网络在这一档做得更好（117M 0.33，257M 0.37），
   说明训练得好的网络本身就能接着往下读到 512 个 token，并不需要专门用长片段训练。
4. **小结。** 到目前为止，增加神经元（第五批）、增加参数（第四批）、多读几遍（第六批）、多给长距离例子（这一批），
   对 129–256 一档的净回看收益都只有很小的帮助，甚至略有损害；唯一明显有效的是蒸馏（117M：0.93 → 1.10）。
   老师给的概率分布是目前最有效的"长距离记忆"训练信号，下一步值得在这个方向上多想办法。

### 5.19 第八批：网络形状、学习率和老师

**问题。** 第六批排除了"数据不够"，剩下两个可能的原因：257M 的学习率不合适，或者网络形状不对
（117M → 257M 只加宽、没加深）。另外顺带问：老师变好，学生能不能跟着变好？

**做法。** 都加三种方法、过一遍训练集，和第四批的 257M（12 层，总线 1536，学习率 5e-4，老师是过一遍的 105M Transformer）比较（`gpu8.sh`）：

### 5.20 硬件代价和低精度模拟：怎么算

目前考虑的硬件实现是 FPGA 和数据流加速器（权重常驻片上、按数据流动计算的芯片）。从这一节起，除了验证 loss 和回看能力，
也报告网络在这类硬件上的代价，并用同样的算法给出 Transformer 的数字作对照（`hw_cost.py`，写入各次实验目录的 `hw_cost.json`）。
所有数字都按"每生成一个 token、每一路对话"计。

**脉冲网络。** 每个 token 的计算分成两半：
- **前半，总线 → 神经元**：每层的 `W_in`、调节漏电的突触，以及最后的读出层。它们的输入是总线，是稠密的实数，
  所以每个权重每一步都要用一次（"稠密乘加"）。每个 token 模拟 T 步时，`W_in` 和调节漏电的突触要用 T 次。
- **后半，脉冲 → 总线**：每层的 `W_out`。只有发放了的神经元，它发出的那一行权重才参与，而且只做加法、不做乘法（"可跳过零的加法"）。

**每个 token 要从片外显存读多少字节**（权重放不进片上存储时，比如 FPGA 板上的 HBM）：
- 前半的权重全部读一遍；
- 后半只读这个 token 里发放过的神经元的那一行。每个 token 模拟 T 步时，第 l 层的 T 步只依赖它前面的层，
  所以可以一层一层地把 T 步算完，每个权重仍然只读一次。
- 16 路同时生成时，前半的权重 16 路共用，只读一次；后半读"任何一路发放过的神经元"的那些行，再除以 16。

发放情况在验证集上实测：64 个 256 token 的片段，每段从静息状态开始读，每 16 段当作同时生成的 16 路。
**状态**是全部膜电位，按每个 24 位计，放在片上。权重分别按 8 位和 4 位计。

**Transformer。**
- 计算量 = 权重的乘加 + 对前面 c 个 token 的注意力。
- 每个 token 要读的字节 = 权重（多路共用）+ 这一路前面 c 个 token 的 key 和 value（按 8 位计）。
- 状态就是这些 key 和 value。
- c 取 256、2048、8192。

**低精度模拟**（`quant_sim.py`，写入 `quant.json`）：不重新训练，把训练好的权重取整，再一步一步地运行网络，
每个量都按硬件的方式取整，看验证 loss 变化多少。所有设置用同一批验证片段，差值是成对比较的。
- 权重：8 位或 4 位整数。每行一个缩放系数，或者每 128 个输入一组一个系数。
- 总线：8 位，每个通道一个缩放系数（这个系数可以并进下一层的权重，在硬件上不额外花代价）；
  调节漏电的突触中间那一层也按 8 位处理。
- 膜电位：先除以各自的阈值（阈值可以并进 `W_in` 和偏置，这样神经元在 1 处发放），再用 16 位或 24 位定点数表示；
  整数部分的位数由校准时的最大值决定，其余是小数位。
- 漏电系数 β（每步经过 sigmoid 之后的值，硬件上用查表）和复位系数 γ：保留 12 位或 16 位小数。

**第一次计算的结果**（`slurm/hw.sbatch`，用了滑动平均的网络都用平均后的权重）。

每生成一个 token 要从显存读多少（权重按 8 位，Transformer 保存的历史也按 8 位）：

| 模型 | 验证 loss | 8 位权重 | 每路状态 | 单路，文本长 256 / 2048 / 8192 | 16 路同时，256 / 2048 / 8192 |
|---|---|---|---|---|---|
| 脉冲 117M + 三种方法 | 1.278 | 117 MB | 148 KB | 64.5 MB（与长度无关） | 5.3 MB |
| 脉冲 257M + 三种方法 | 1.242 | 257 MB | 221 KB | 140.7 MB | 11.0 MB |
| 脉冲 257M，更好的老师 | 1.229 | 257 MB | 221 KB | 140.6 MB | 11.0 MB |
| 脉冲 257M，读两遍 | 1.199 | 257 MB | 221 KB | 141.0 MB | 11.2 MB |
| Transformer 12.4M | 1.357 | 12 MB | 1.0 / 7.9 / 31.5 MB | 11.4 / 18.3 / 41.9 MB | 1.6 / 8.5 / 32.1 MB |
| Transformer 29.9M | 1.245 | 30 MB | 2.1 / 16.8 / 67.1 MB | 29.4 / 44.0 / 94.4 MB | 3.8 / 18.5 / 68.8 MB |
| Transformer 55.1M | 1.190 | 55 MB | 3.3 / 26.2 / 104.9 MB | 55.1 / 78.0 / 156.6 MB | 6.5 / 29.5 / 108.1 MB |
| Transformer 104.6M | 1.139 | 105 MB | 4.6 / 36.7 / 146.8 MB | 104.6 / 136.7 / 246.8 MB | 10.8 / 43.0 / 153.1 MB |

1. **发放情况和此前的估算一致。** 每层每步有 2%–6% 的神经元发放（257M 平均约 3%），所以单路生成时每个 token 只需读全部权重的约 55%。
   16 路同时生成时，"任何一路发放过"的神经元占 34%–44%，比按各路互相独立推算的约 40% 略少。
2. **单路生成时，脉冲网络读得更多。** 读两遍的 257M（1.199）和质量相近的 55.1M Transformer（1.190）相比，
   文本长 256 时脉冲网络读的是它的 2.6 倍；到 8192 个 token 时是 141 对 157 MB，才大致持平。
3. **16 路同时生成、文本较长时，脉冲网络读得更少。** 同样这两个模型，脉冲网络每个 token 读 11.2 MB，不随长度变化；
   Transformer 在 256 / 2048 / 8192 个 token 时是 6.5 / 29.5 / 108 MB。文本长 2048 时脉冲网络读的只有它的 38%，8192 时只有 10%。
   这就是第 0 节说的"近期可以主张的"场景。但前提是脉冲网络在这么长的文本上质量不掉，而它只用 256 个 token 训练过，这一点还没有验证。
4. **状态**：脉冲网络每路 148–221 KB，固定不变；Transformer 在 2048 个 token 时就要 8–37 MB。

低精度模拟（验证 loss 相对不取整时的变化；256 个 256 token 的验证片段，约 6.5 万个 token）：

| 权重 4 位，每行一个系数 | +0.051 | +0.050 | +0.061 | +0.041 |

| 膜电位 24 位 | −0.000 | −0.000 | −0.000 | +0.001 |

   也就是说，这些网络不需要重新训练，就能按 FPGA 和数据流加速器常用的整数精度运行。
2. **4 位权重会损失 0.016–0.023**（每 128 个一组缩放；每行一个系数时损失 0.04–0.06），大约是 117M → 257M 收益的一半。
   117M 用 4 位约 59 MB，可以整个放进 AMD V80 的片上存储；要用 4 位，需要在训练时就按 4 位训练来弥补这部分损失，留到以后。
3. **16 位膜电位不行，原因是少数神经元的膜电位偏得极远。** 校准时，有的层膜电位的绝对值最大达到阈值的约 5 万倍
   （读两遍的 257M 有一层达到约 42 万倍）。按最大值确定范围以后，16 位里几乎没有留给小数的位，舍入误差太大。
   改成按 99.99% 分位数确定范围、超出的部分截断（`V16p`），可能就能用 16 位，下次一起测。24 位已经没有损失，所以这一点不影响上面的结论。

### 5.21 第九批：每个 token 模拟多步、250M Transformer、更好的老师读两遍

**问题。** 5.19 节留下两种可能来解释"117M → 257M 收益变小"：一是每个 token 只模拟一步，每个神经元对一个 token 最多发一个脉冲，
能传递的信息有限；二是数据集本身，模型越接近 TinyStories 的极限，每翻一倍的收益本来就会变小。

**做法**（`gpu9.sh`）：
- **每个 token 模拟多个时间步**（新选项 `--steps_per_token T`，见 `model.py` 开头的说明）：
  - 每个 token 在网络里停留 T 步，它的输入神经元在这 T 步里每步发放一次，所以每个神经元对一个 token 最多能发 T 个脉冲；
  - 读出神经元在这 T 步里累加、不漏电，读完清零，相当于对 T 步的总线取平均；
  - 时间常数按 token 计的初始值不变；不增加参数，每个 token 的神经元计算量变成 T 倍；T=1 时和原来的代码逐位相同。

  在 117M + 三种方法上试 T=2 和 T=3。
- **250M 的 Transformer 过两遍**（总线 1280，12 层，247.8M），和过两遍的 105M Transformer 比较。
- **目前最好的配置过两遍**：257M、过两遍的老师、学习率 5e-4。

表中的脉冲网络都用平均后的权重；k=0 / k=128 是测量 A 中上文为 0 和 128 个 token 时的 loss；"净回看"见 5.1 节；
长故事上的数字是测到 512 个 token 的那组（5.18 节）。

| 模型 | 验证 loss | k=0 / k=128 | 上文收益（A） | 净回看 65–128 / 129–256 | 长故事上净回看 129–256 / 257–512 | 训练速度（token/秒） |
|---|---|---|---|---|---|---|
| 117M，每个 token 1 步（第四批） | 1.278 | 1.798 / 1.319 | 0.297 | 1.47 / 1.10 | 0.69 / 0.33 | 21.6 万（H100） |

| 117M，3 步 | 1.276 | 1.799 / 1.311 | 0.303 | 1.46 / 1.04 | 0.64 / 0.25 | 5.8 万（H100 NVL） |

1. **每个 token 2 步有一点帮助，3 步没有。** 2 步使验证 loss 改善 0.013，短上文（k=0）和长上文（k=128）都改善了 0.013–0.019，
   上文收益也略有提高（0.297 → 0.303）；但远距离的净回看没有变好，长故事上 256 以外还略差。3 步反而几乎退回到 1 步的水平。
   所以"每个 token 只能发一个脉冲"确实限制了一点，但不是主要瓶颈。代价是 GPU 上训练慢了约 2.5 倍；
   在 FPGA 上，权重仍然每个 token 只读一次（5.20 节），主要多出来的是前半的稠密计算，第十批会用 `hw_cost.py` 算清楚。
2. **Transformer 在 100M 以上也一样变慢了。** 过两遍时，105M → 250M（参数 2.37 倍）改善 0.042，每翻一倍约 0.034；
   脉冲网络 117M → 257M（2.2 倍）改善 0.039，每翻一倍也约 0.034。两者完全一样。所以 5.15 节第 4 条的"参数加倍收益变小"不是脉冲网络特有的，
   而是这个数据集在这个规模上的共同现象（早先"每翻一倍改善约 0.065"是在 27M–117M 的较小规模上测的）。
   这也意味着：两种网络沿着两条平行的线变好，**单靠扩大规模，"同样质量需要多少倍参数"这个差距不会缩小**，要缩小它只能靠提高每个参数的效率。
3. **更好的老师再次有效。** 257M 读两遍，老师从过一遍换成过两遍（1.139 → 1.091），学生从 1.199 改善到 **1.184**，是目前最好的脉冲网络。
   老师的进步传给学生约三分之一（第八批读一遍时约四分之一）。
4. **和 Transformer 的差距。** 都读两遍时，257M 脉冲网络（1.184）和 105M Transformer（1.091）的差距是 0.093，
   短上文（k=0）差 0.078，上文 128 时差 0.143，比读一遍时（0.089 / 0.163）略小。按读一遍时各个 Transformer 读两遍大约改善 0.045 推算，
   29.9M 和 55.1M 的 Transformer 读两遍约为 1.20 和 1.145，所以这个脉冲网络大约相当于 35M 的 Transformer，参数量是它的 7 倍多。
5. 一个值得注意的现象：读两遍的 257M 在 256 个 token 以外的回看（0.27）比只读一遍的（0.37，5.18 节）差。
   多读一遍 256 个 token 的片段，可能让网络更"习惯"在 256 处结束。如果以后要做长文本，需要用长片段训练（见 5.22 节）。

### 5.22 进行中

- **第十批**（`gpu10.sh`）：
  - **脉冲化总线**（`--spike_bus`，见第 6 节的网络选项）。目的：现在每层输入的那一半计算是稠密的（总线是实数），
    在所有候选硬件上都省不下来（5.20 节）；改成中继神经元的脉冲后，`W_in` 和调节漏电的突触也只有发放了的通道才需要计算和读取。
    代价是每个通道每步只能传 −1、0、1，信息变少，质量可能下降；中继神经元用减法复位，没发出去的部分留在膜电位里，下一步继续累积。
    关闭时和原来的代码逐位相同（CPU 上检查过初始权重和输出）。在 117M + 三种方法上，分别用每个 token 1 步和 2 步，
    和第四批的 117M（1.278）、第九批的 117M 2 步（1.265）比较，同时比较硬件代价。
  - **257M，每个 token 2 步**（老师过两遍，读一遍）：看第九批 2 步的改善在大网络上是否还在，和第八批的 1.229 比较。
  - **257M，用 250M Transformer（1.049）当老师**（读一遍）：老师又好了 0.042，看学生能跟上多少，也和 1.229 比较。
  - 四组跑完后算硬件代价（`slurm/hw.sbatch`）。第九批的几组也补算，同时用 `V16p` 重测 16 位膜电位（5.20 节）。
- **长文本实验线（决定开始准备）。** 理由有两条：一是上面第 2 条，两种网络在 TinyStories 上都进入了收益变小的区间，
  更难的数据更能拉开不同结构的差距；二是第 0 节"近期可以主张的"场景（多路并发、长文本）需要证明长文本上的质量，
  而 TinyStories 的故事平均只有约 200 个 token，做不到。和 TinyStories 主线并行，分步进行：
  - 数据用 **PG-19**：Project Gutenberg 上 1919 年以前出版的书，训练集 28,602 本，每本平均约 40 万字符，
    原论文的分词下约 20 亿 token。它是长距离语言模型的常用测试集，结果可以和文献对照。
  - 第一步：下载、为它训练新的分词器、转换成 token（CPU 作业），保留每本书的边界
    （`slurm/pg19_download.sh`、`prepare_pg19.py`；8192 个词的字节级 BPE，在验证集上平均每个 token 3.8 个字符，每本书约 9 万个 token）。
  - 第二步的工具已备好，都在 CPU 上测试过：
    - `train.py --data data/pg19 --tokenizer tok8192.json --vocab 8192` 读 PG-19；
    - Transformer 对照组可以用旋转位置编码（`--rope`），不再受学到的位置向量长度的限制；
    - `eval_long.py` 从每本书的开头读到 8192 个 token，按位置区间（0–64、64–128、……、4096–8192）报告平均 loss。
      脉冲网络分段读、膜电位接着往下传（和一次读完逐位相同）；Transformer 可以用全部上文，或只用最近 W 个 token（滑动窗口）。
      如果 loss 在后面的位置继续下降，说明模型用上了更长的上文。
  - 第二步的计划：在 117M 量级上，脉冲网络和 Transformer 各训练一组，看 loss 随位置的变化，以及硬件代价。
    脉冲网络用 `--carry_state` 沿着书连续往下读（每段几百个 token，膜电位传给下一段）；Transformer 用 2048 或更长的片段。
  - 第十一批（`gpu11.sh`，数据准备好后提交）就是第二步：脉冲网络 125M（117M 的结构，词表变大）两组，一组用 `--carry_state`
    沿书连续读 512 个 token 的片段、膜电位往下传，一组每段从静息开始；Transformer 98M 和 34M 各一组，旋转位置编码、2048 个 token 的片段。
    都读约 10 亿 token，暂不用老师。之后用 `eval_long.py` 在测试集的书上读到 8192 个 token，并算硬件代价。

## 6. 在 GPU 上运行

CPU 上用 C++/OpenMP 内核（`lif_kernel.cpp`），NVIDIA GPU 上用 Triton 内核（`lif_triton.py`），按张量所在设备自动选择，
方程和梯度完全相同。Triton 内核已在 CPU 上通过 Triton 的解释模式验证：24 种设置下脉冲完全一致，梯度和参考实现的最大相对误差 2.8e-6；
整个模型在两种内核下 float32 梯度相差 1e-6 量级。在 GPU 上内核也已通过同样的测试；一张 H100 上，25M + 漏电突触约 34–66 万 token/s，117M 约 29–31 万 token/s（CPU 上约 1 万），详见 `runs/gpu_setup_report.md`。同层连接（`--rec_rank`）暂时没有 GPU 内核，会退回到很慢的参考实现。

需要：支持 bf16 的 NVIDIA 显卡（Ampere 及以后，24GB 显存可训练到约 2 亿参数），Linux，带 CUDA 的 PyTorch 2.x（自带 Triton）。

```bash
bash gpu_setup.sh        # 检查显卡 → 安装依赖 → 下载并处理数据（校验与已有结果用的数据逐字节相同）→ 内核正确性测试 → 各规模的训练速度
python3 train.py --device cuda --out runs/xxx ...   # 其余参数和 CPU 上相同
python3 evaluate.py --device cuda --ckpt runs/xxx/ckpt.pt --out runs/xxx/final_eval.json
```

**训练方法选项**（不改变网络结构，默认都关闭）：
- `--teacher 路径 --distill_weight a --distill_temp T`：知识蒸馏。损失 = (1−a)·交叉熵 + a·T²·KL(老师 ‖ 学生)，老师是已训练好的模型
  （例如 `runs/tf_full` 的 Transformer）在同一个 batch 上的输出。验证 loss 仍只算交叉熵。
- `--ema d`：同时保存权重的滑动平均（例如 0.999），评估时两种权重都报告；`evaluate.py --ema`、`sample.py --ema` 使用平均后的权重。
- `--carry_state`：每个 batch 的每一行沿着训练文本连续往下读，上一段结束时的膜电位作为下一段的起点（梯度在段与段之间截断）。
  不加时每段都从静息状态开始。
- 已有的：`--lr`、`--alpha`（代理梯度宽度）、`--neuron_lr_mult`（神经元自身参数的学习率倍数）、`--tau_min/--tau_max`（时间常数初始范围）等。

**网络选项**（默认都关闭，见 `model.py` 开头的说明）：
- `--steps_per_token T`：每个 token 模拟 T 个时间步（默认 1，见 5.21 节）。
- `--spike_bus true`：脉冲化总线。每个神经元群之前，总线先经过一组中继 LIF 神经元（每个通道一对：一个由 +总线驱动，
  一个由 −总线驱动，减法复位），神经元群读的是它们的脉冲（每个通道 −1、0 或 1），而不是实数总线。
  `--bus_tau_min/--bus_tau_max`、`--bus_theta` 是中继神经元时间常数和阈值的初始值。

**数据选项**：`--data 目录 --tokenizer 文件`（默认 `data` 和 `tok4096.json`，即 TinyStories；PG-19 是 `data/pg19` 和 `tok8192.json`，
另加 `--vocab 8192`）。Transformer 另有 `--rope`（旋转位置编码），最长长度取 1024 和 `--seq` 中较大的一个。
