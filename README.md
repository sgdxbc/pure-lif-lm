# LIF 脉冲语言模型

一个用 LIF（漏积分发放）神经元搭成的语言模型：神经元之间只传 0/1 脉冲，网络里没有注意力，每生成一个 token 只需带着各神经元的膜电位往下算，
状态大小固定，不随文本变长。项目从 TinyStories 上的一个 1260 万参数、在 CPU 上训练的小模型开始，现在在 GPU 集群上训练上亿参数的网络，
在通用文本（FineWeb-Edu）上和同样数据训练的 Transformer、以及 GPT-2、Pythia 这类经典小模型比较，同时估算它在 FPGA 上的推理代价。

## 0. 项目目标与原则

**愿景**（2026-11-19，项目负责人的说明，整理如下）：
- **要证明什么**：在某些场景下，用 FPGA 或数据流硬件部署模型的方案，即使不能胜过 GPU 方案，也是它的有力竞争者：
  没有让人无法接受的短板，并且有鲜明的亮点。也就是说，一个需要从零开始部署这类方案的人，不会不假思索地选 GPU，
  至少会认真考虑 FPGA 或数据流硬件是不是更好，在 GPU 紧缺时尤其如此。
- **为什么选语言模型**：这个课题影响力大。在这里取得进展，其他课题的研究者会自然地想到自己的课题能不能也这样做；反过来就没有这种示范作用。
- **为什么用脉冲网络**：主流网络大概率还是在 GPU 上部署更有优势，拿它们来论证新硬件更好，会在领域内遇到更大的阻力。
  脉冲网络提供的超轻量的 recurrent + 非线性有希望在新硬件上取得奇效：LIF 神经元的记忆只是它自己的膜电位
  （每步乘一个衰减系数、加上输入，没有循环矩阵），非线性只是和阈值比一下、输出 0/1（读它们的突触只需做加法）。
- **改变对脉冲网络的印象**：常见的看法是脉冲网络规模小、极度稀疏，这是类脑芯片塑造出来的印象。这个项目要给脉冲网络定义它自己的
  scaling law（质量随参数、数据、算力怎样变化），并把更强大的硬件（大容量 FPGA、数据流加速器）作为脉冲网络的主场。
- **为什么强调趋势**：算力有限，所以重点是把趋势做清楚，给资源更充足的研究者指路。

由此的衡量方式：每个候选结构同时报告质量和在目标硬件上的代价（每个 token 的稠密乘加、只需加法的稀疏运算、读取的字节、片上存储），
对照的是"同等质量的 Transformer 在它最好的硬件上"；趋势曲线的横轴除了参数和训练 token 数，也用目标硬件上的代价。
稀疏是结果而不是目标：要的是每一步运算便宜，而不是为了稀疏而牺牲质量。

**阶段性目标**（2026-11-15 重新确定）：
1. **质量**：在通用文本上达到经典小模型的水平（GPT-2 124M–355M、Pythia 160M–410M 这一级），在一些任务上基本可用。
2. **随算力提升的趋势**：展示投入的训练算力越多、质量越好，而且这个趋势能持续（loss 随训练算力变化的曲线，
   和同样数据上训练的 Transformer 并排比较）。真正的大规模训练留给以后。
3. **硬件**：在目标硬件（FPGA、数据流加速器）上展现出某种实在的优势，最好不局限于很窄的场景；在没有优势的场景也不明显落后。
   **比较口径**：Transformer 一方用它表现最好的硬件上的对应指标，可以是 GPU，用成熟的推理软件实测；
   不把不适合在非 GPU 硬件上跑的 Transformer 硬搬到 FPGA 或数据流加速器上来比。
4. **结构**：纯 LIF 不再是硬性要求，硬性要求是能在目标硬件上跑起来。但尽量保留（或接近保留）LIF 神经元，结构保持单纯，
   给以后的扩展和更多的部署方式留余地。

考虑过但暂时放下的目标：追平当前前沿的 7–9B 模型（如 Qwen3.5-9B）。从零训练到这个水平远超现有算力；
以后如果要做，路线是从开源模型改造并蒸馏（SpikingBrain、RADLADS 等已有先例）。

**长期方向**（原目标，保留）：用任何方式尽可能提升模型性能，最终让**推理性能**匹配 Transformer。

**原则**：
- "脉冲神经网络规模小"是一种刻板印象，不是这个项目的约束。扩大规模，极端情况下扩大到比 Transformer 还大，是合理的选择，
  甚至可能是必须的。
- "追平 Transformer"是一个大致的目标：最终成果只要能在某种合理的意义上解释为达到了 Transformer 的水平即可，
  不预先限定是哪一个 Transformer、哪一项指标。
- 衡量标准是训练好的脉冲网络在推理时的表现（验证集 loss、回看能力、生成质量），和 Transformer 的推理表现比。
  **怎么训练出来的不重要**：训练数据用多少、训练多久、是否用 Transformer 等模型当老师做蒸馏，都不受限制，照常记录即可。
- 参数量、训练和生成速度、状态大小也照常记录，它们是实际算力预算要考虑的因素，但不作为否定一个改进方向的理由。
- "纯粹由脉冲神经元构成"按目前的约定是指：所有状态和非线性都在 LIF 神经元里，神经元之间只通过脉冲经突触传递
  （突触可以是普通突触、低秩分解的突触、带延迟的突触、调节漏电的突触）；不使用注意力、归一化层或非脉冲的非线性单元。
  双室神经元暂不采用。这仍是默认做法；从 2026-11-15 起，为了上面的目标可以有所放宽，但每一处都要记录理由，
  并优先选择保留硬件优势的做法（神经元之间传脉冲或小整数、状态大小固定）。

**硬件目标**：
- 当前的硬件实现候选是 **FPGA** 和**数据流加速器**（权重常驻片上、按数据流动计算的芯片，如 Groq、Tenstorrent、SambaNova、
  Cerebras、IBM NorthPole）。
- **类脑芯片**（Loihi 2、SpiNNaker2、达尔文 3 等）暂不作为目标，原因有两条：现在的网络层与层之间传的是实数总线；
  每个神经元的连接数远多于这类芯片的设计（我们的网络每个神经元约对应 2,400–3,500 个参数，Hala Point 平均每个神经元约 110 个突触）。
  移植上去，要么突触数增加几十倍，要么总线变成普通的矩阵乘法。
- "追平 Transformer"分两层来说：
  - **长期目标：同参数量打平。** 脉冲网络和参数量相同的 Transformer 推理质量相当。在 FPGA 上，这意味着各种场景下都更省
    （每个 token 只需读约一半的权重，也不用保存随文本变长的历史）；在数据流加速器上，短文本大致持平，长文本更省。
  - **近期可以主张的：多路并发、长文本时每个 token 的成本。** 按现在"257M 脉冲网络约等于 30M Transformer"的水平，
    只有在这个场景下脉冲网络读显存的量更少；前提是长文本上的质量得到验证。
- 每批实验除了验证 loss 和回看能力，同时报告硬件代价（`hw_cost.py`，口径见[实验记录](docs/experiments.md) 5.20 节），并和同样算法下的 Transformer 对照。
  这些"同样算法下"的数字只用来理解两种网络各自的代价从哪里来；**正式的硬件比较**按第 0 节第 3 条的口径：
  Transformer 在 GPU 上实测（`bench_gpu.py`：吞吐量、每个 token 的延迟、显卡功耗折算的每 token 能耗，按并发路数和文本长度分别测），
  脉冲网络在 FPGA 或数据流加速器上估算，以后用原型实测。

## 当前进展（2026-11-16，开头的摘要 2026-11-20 更新）

**摘要**（详见下面各小节和"正在做的"）：
- **质量**：最好的脉冲网络是 212M + 可塑突触 + 蒸馏，读 98 亿 token 3.428；同样数据的 Transformer 163M 3.162，GPT-2 124M 3.277。
  差距在 49、74、98 亿 token 上是 0.260、0.260、0.266，靠多训练追不上；而且这是第 12 万步换了更强的老师之后的数，
  同一个老师下差距随数据变大（12、25、49 亿 token：0.231、0.267、0.298），即按数据扩展时脉冲网络比 Transformer 涨得慢（5.37 节）。
  零样本：除 LAMBADA 外五项平均 43.1%，GPT-2 124M 42.4%；但六项平均 37.9% 对 40.8%，LAMBADA 11.8% 对 32.6%，
  五项里领先的主要是 ARC-e（FineWeb-Edu 的题材占便宜），同样数据的 Transformer 是 44.6%。
  更强的老师（GPT-2 Medium、XL）都没有帮上忙（5.42、5.45 节）。
- **差距来自哪里**：同样只有固定大小状态的线性注意力网络（不发放脉冲）比 Transformer 好 0.07–0.08，所以差距不在"状态大小固定"（5.47 节）。
  同样从 `g13_tf163` 蒸馏、同样读 25 亿 token，它最后比脉冲网络好 0.24（3.301 对 3.541；训练中途约 0.4，后来慢慢缩小）；
  不过蒸馏让它自己变差了约 0.09（不蒸馏是 3.211），因为老师（3.310）比它弱。脉冲网络的实数孪生网络反而差约 0.1，
  所以差距也不在"只传 0/1"本身（5.48 节）。同一个短配方下线性注意力网络领先约 0.47（3.396 对 3.863；它还多了 48M 参数、
  没有词的压缩编码），其中隐藏单元换成 0/1 占 0.068，再加膜电位和复位又差 0.010，大头不在隐藏单元（5.49、5.50 节）；
  给脉冲网络的总线加归一化，全精度时持平，按 4 位取整时少损失 0.055，以后的结构都带上它（5.49 节）。
  **记忆的形式占约 0.28**：神经元群不变，把可塑突触换成门控线性注意力，3.860 → 3.583（5.50 节；同时多了 50% 的状态和 16.7M 参数，
  状态大小的影响还在测）。逐项去掉（第四十二批，5.53 节，初步）：
  0/1 的键和查询代价 0.076（LAMBADA 掉得最多）、输出门 0.072、短卷积 0.048、随输入变化的衰减 0.018，状态小 25% 只差 0.011；
  四样一起去掉后反而比可塑突触还差 0.125，但它后半段不稳定（126 步被跳过），差距正是在那一段拉大的，
  所以"可塑突触自己也有长处"只是可能。把前三样加回可塑突触（一个词里最多 4 个脉冲的键和查询神经元、延迟 0–3 个词的突触，
  这两样是脉冲的形式；输出门是稠密的实数乘法，不是脉冲的形式），3.860 → 3.688，追回了 0.28 里的 0.17，其中门一样就占 0.10；
  LAMBADA 从 3.2% 到 8.9%（第四十四批，5.55 节，单种子、初步；以后的脉冲网络默认带上它们）。剩下约 0.19 在词的压缩编码、网络大小和训练设置里。先软后硬的训练没有帮助（5.48 节）。
- **硬件网络**（整个放进 FPGA 片上的版本，4 位权重）：3.753。整数版的定义（12 位激活、20 位可塑突触）没有损失，
  FPGA 内核在 C 模拟里和它逐位一致；下一步在 AMD HACC 的 U55C 上综合、上板卡实测（5.44 节）。
- **硬件比较**（都是估算，FPGA 还没有上板；能耗按整卡功率 × 时间算，所以同一种卡上能耗之比就是速度之比）：
  - **和 GPU 比**：单路、少数几路时 FPGA 快很多（硬件网络单路快 14–17 倍、省 5–8 倍，5.43 节），大量并发时 GPU 更好。
    这是"小网络整个放进 FPGA 片上"的好处，对任何小网络都成立，不是脉冲带来的。
  - **在同一块 FPGA 上、同样质量下比**（5.51、5.52、5.59、5.60 节；第 2、3 次自我审计更正过；估算从 5.60 节起按"放得下的留在片上、
    只从 HBM 读放不下的部分"算）：**现在的小 Transformer 比脉冲网络和它的各种变体都省。** 31M 的 Transformer（3.787）单路和 16 路都是 0.96 mJ；
    77M 的线性注意力网络加上压到 0.25 的中继、蒸馏（`g45_kd25`，3.811）1.45 mJ；接近 LIF 的三样一起的脉冲网络（3.688）约 3.0 mJ，
    而同配方、同老师的 50M Transformer（3.612）质量更好，只要 1.6–1.8 mJ。两边都换成两级读出时单路持平（0.47 对 0.46），16 路时脉冲那边省约 13%，
    但质量差 0.024、LAMBADA 8.1% 对 11.5%，而且这一点来自"状态大小固定"，不是脉冲本身。真的训一个两级读出，中继网络差了 0.043
    （5.58 节，超过事先定的 0.03），所以硬件比较以完整读出为准，两级读出的数只作参考。
  - **已经知道的**：MLP 换成 0/1 单元差 0.10（77M）；所有大矩阵前加中继、把脉冲压到一半，块里的乘法几乎都变成加法，质量差 0.11；
    三值权重差 0.13，和中继的代价可以相加，它在硬件上的用处主要是权重小一半（GPT-2 small 的形状因此一张 U55C 放得下）。
    单个神经元的膜电位在 MLP 里没有可测的好处（差在随机波动 0.012 之内），在中继里差 0.15
  （MLP 那一处神经元参数用基础学习率和 10 倍学习率都试过，结论一样，5.55 节）。三个随机种子量出的波动是 σ = 0.004（5.55 节）。
    并发 256 路时，线性注意力每一路的状态放不进片上，几个网络的代价都差不多。
  - **决定性的稠密对照**（第四十八批，5.60 节，初步）：50M 的稠密门控线性注意力（`g48_gla50`，3.659）和压在 0.25 的 77M 中继网络估算代价一样（1.45 mJ），
    质量好 0.15，LAMBADA 9.9% 对 7–8%；它也压倒了三样一起的脉冲网络（3.688，3.02 mJ）。所以在现在的估算下，77M 和 126M 的脉冲候选都没有带来好处。
    原因之一是完整读出时 5 万词的读出占了小网络代价的大头，中继省下的主体运算在总代价里很少。只有 GPT-2 small 形状、中继压在 0.5 的 `g43_q4t163`
    （3.545，3.38 mJ）还没被同样短配方训的稠密网络压倒；训了 3.75 倍数据的 77M Transformer（3.456）单路时已经比它好又省（5.60 节更正）。所有硬件数都是估算，"一次加法比一次乘加便宜多少"没有建模：估算按一样算，
    如果加法只算一半，两级读出时 `g45_kd25` 能追上稠密网络（转折点 0.69，用的是没训过的读出），但三值权重的稠密网络也一样受益。
  - **长文本**（5.60、5.62 节）：改进后的评测（"热启动"对照、换过的假答案、容易的阳性对照）显示，五个网络都没有用上 1–2k 以外的上文：
    状态固定的网络在 512 远处记得的远不如窗口里的 Transformer，到 2k 就基本没有了。所以在按 1,024 个词训练的条件下，长文本不能作为脉冲网络的优势；
    用更长的文本训练会不会不同，没有测过。
  - **读出层只在变化时发脉冲**（5.62 节，不训练的重放）：最后一层的输出每个词都在变，没有一个阈值能在质量几乎不变的同时省 25%，不往下做。
  - **支持和反对"脉冲本身带来好处"的证据**（第 3 次自我审计列出，第 4 次更新）：支持的——压到 0.25 时块里的矩阵只要约 490 万次加法，不是约 2,100 万次乘加
    （前提是加法比乘加便宜，这一点还没测）；蒸馏让中继网络好 0.085（但它对不带中继的网络是否同样有效还在测，所以不一定是在缩小脉冲的代价）。
    反对的——还没有一个候选在同样质量下比稠密网络省；接近 LIF 的三样一起的记忆虽然比原来好很多，但已被同样代价的稠密网络压倒，而且好处主要来自稠密的门；
    长文本（按 1,024 个词训练时）、读出层只在变化时发脉冲都没有带来好处；训练过的两级读出让中继网络差 0.043；
    测过的 LIF 特有的部分（MLP 的膜电位、LIF 中继）都没有帮助或更差；稀疏很贵（不蒸馏时压到 0.25 差 0.19），加宽补不回来；
    LAMBADA 都不如对应的 Transformer；77M 那条线的"脉冲"其实是没有膜电位的 9 级激活，普通的"跳过零"的 4 位设计也能用上同样的稀疏；
    同样估算代价下，稠密的 50M 线性注意力比 77M 中继网络好 0.15（第四十八批）。
  - **稀疏脉冲的训练方式**（第四十五批，5.56 节，单种子、初步）：从 `g13_tf163` 蒸馏比不蒸馏好 0.085，换种子也好 0.086，已定为默认（5.58 节）；
    在同样的加法下把 MLP 加宽 2 倍、4 倍没有好处；先训普通网络再接上中继、逐步收紧脉冲数都没有帮助。前者的起点很差，不训练的检查显示
    主要不是初始阈值的问题：阈值按数据定好、脉冲一样多时，刚接上中继仍多出约 1.9 的损失（5.62 节，初步）。

### 通用文本：FineWeb-Edu（目标 1、2 的主线）

每个网络读 25 亿 token，没有老师（[实验记录](docs/experiments.md) 5.28 节）。验证 loss 越低越好；零样本基准是 lm-evaluation-harness 的六项
（HellaSwag、LAMBADA、PIQA、ARC-Easy、ARC-Challenge、WinoGrande）的平均准确率，单位 %。参考模型用同一工具、同一台机器实测。

| 网络 | 参数 | 验证 loss | 六项平均 | 除 LAMBADA 外五项平均 | LAMBADA |
|---|---|---|---|---|---|
| **脉冲 212M + 可塑突触 + 蒸馏，按 (1 − λ) 缩放写入**（5.34 节） | 237.0M | **3.541** | 36.4 | 41.7 | 9.8 |
| 脉冲 212M + 可塑突触 + 蒸馏（新配方，5.33 节） | 237.0M | 3.600 | 35.9 | 41.2 | 9.6 |
| **脉冲 138M + 可塑突触 + 蒸馏**（新配方） | 157.4M | **3.621** | 35.8 | 41.1 | 9.1 |
| 脉冲 212M | 211.8M | 3.814 | 34.6 | 41.3 | 1.0 |
| 脉冲 138M | 138.5M | 3.906 | 34.4 | 41.0 | 1.3 |
| 我们的 Transformer 163M（GPT-2 small 的形状） | 163.0M | 3.310 | 39.3 | 43.2 | 19.7 |
| 我们的 Transformer 77M | 77.2M | 3.535 | 37.4 | 41.9 | 14.8 |
| *GPT-2 124M* | *124M* | *3.277* | *40.8* | *42.4* | *32.6* |
| *Pythia-160M* | *162M* | | *41.1* | *42.2* | *35.4* |
| *GPT-2 355M* | *355M* | *3.000* | *46.2* | *46.8* | *43.0* |

- 我们自己的 Transformer 和 GPT-2 124M 基本持平，说明数据和训练流程没有问题。脉冲网络的验证 loss 差 0.5，而且从 138M 到 212M 只改善了 0.09，
  比 Transformer 随规模的改善慢得多（`runs/scaling_fineweb.png`）。
- 除 LAMBADA 外，脉冲网络的零样本五项平均和 GPT-2 124M 只差一两个百分点，但六项平均差 4–5 个百分点，大头在 LAMBADA；
  五项里 ARC-e 一类题材 FineWeb-Edu 占便宜，所以更合适的比较是同样数据的 Transformer（五项平均 43.2%）。
- 诊断（5.30 节）：LAMBADA 的最后一个词多半在前文出现过。Transformer 读完整段能把这个词的 loss 降低 5–6 nat，脉冲网络只降低约 1.3 nat；
  在 FineWeb-Edu 的文档里，两者的差距也随位置变大（前 64 个 token 差 0.35，512–1024 差 0.56）。
  **主要的短板是不能把前文出现过的具体内容原样找回来**，膜电位只能记住"大致发生了什么"。
- 让 Transformer 163M 只看最近 W 个 token 做对照：脉冲 212M 的水平大约相当于只能看最近二三十个 token 的它。
  Transformer 从上文得到的好处，大部分来自最近几十到两百多个 token，所以要补的主要是这个范围里的准确回忆。
- **可塑突触和蒸馏都有效，而且能叠加**（5.32 节，138M，较短的训练：各读 6.55 亿 token）：

  | 做法 | 验证 loss | LAMBADA |
  |---|---|---|
  | 旧配方 | 4.195 | 0.2 |
  | 加可塑突触（一种联想记忆，见下文"网络结构"） | 4.029 | 3.7 |
  | 加蒸馏（老师是我们的 Transformer 163M） | 4.073 | 0.5 |
  | 两者都加 | **3.892** | 4.5 |
  | Transformer 163M，同样的训练量 | 3.446 | 15.7 |

  两者都加，和 Transformer 的差距从 0.75 缩小到 0.45，而且只读 6.55 亿 token 就好过旧配方读 25 亿 token 的结果（3.906）。
  代价：参数 +14%，每个 token 的乘加 +27%，状态从 0.11 MB 增加到 1.3 MB（仍是固定大小），训练慢将近一半。
- **新配方训满 25 亿 token**：212M 3.600，138M 3.621，比旧配方好 0.21 和 0.29，LAMBADA 从 1% 升到 9% 多。
  但 212M 只比 138M 好 0.02（旧配方是 0.09）：它的训练里有严重的梯度尖峰（只在加了可塑突触的网络里出现，5.34 节），
  原因是时间常数长的那几组可塑突触里的数会累加到几万。
- **修正：写入时按 (1 − λ) 缩放**（训练完可以并进权重，网络和硬件不变）。212M 重训一遍（同样的数据顺序）：**3.600 → 3.541**，
  是目前最好的脉冲网络，和 Transformer 77M（3.535）只差 0.006；LAMBADA 9.8%，尖峰从 88–117 降到最大 6.3。
  但它只在训练不稳的设置里有用：每组 256 个键时（本来就稳），138M、212M 上都没有好处，LAMBADA 还略差（5.34 节）。
- **记忆的容量**（5.35 节，138M 短训练）：每组 256 个键神经元（原来 64）好 0.08，和蒸馏能叠加（"蒸馏 + 256 个键" 3.795，
  "蒸馏 + 64 个键" 3.892）；键神经元总数相同时分几组无所谓；每组 512 个和 256 个一样，不再变好；
  每组 256 个时每层都加最好，每隔一层加差 0.017、状态省一半，只在四分之一的层加差 0.033、状态约四分之一；
  最短的时间常数从 1 个 token 起（原来 8）好 0.018，不花任何代价。同样读 6.55 亿 token，212M（256 个键）3.703，比 138M 好 0.09。
- **词表撑大网络的问题**（5.36 节）：词表的输入、读出两块占参数的 42–56%，读出还占每个词稠密乘加的 30–54%，而且这部分脉冲帮不上忙。
  换一种编码：读出分两级（先猜"哪一类词"，再在这一类里猜），输入让每个词由两个输入神经元的组合表示。按训练好的网络给词聚类时，
  CPU 小网络上各只差约 0.03；在 5 万词表上，两级读出能让每个词的稠密乘加约少四成，组合输入省下约 3,860 万个权重的存储。GPU 上正在核对。

### TinyStories（早期的主线，现在用来快速试验）

读一遍训练集（5.49 亿 token），脉冲网络加"三种方法"（蒸馏、权重滑动平均、神经元参数 10 倍学习率；5.12–5.19、5.23、5.27 节）：

| 网络 | 验证 loss |
|---|---|
| 脉冲 117M | 1.278 |
| 脉冲 257M（老师读两遍训练集） | 1.229 |
| 脉冲 257M，每个 token 模拟 2 步 | 1.219 |
| Transformer 12.4M / 29.9M / 55.1M | 1.357 / 1.245 / 1.190 |
| Transformer 104.6M（AdamW / Muon） | 1.136 / 1.114 |

257M 的脉冲网络大约相当于 30M 的 Transformer。优化器 Muon 对 Transformer 有效，对脉冲网络无效（5.27、5.31 节），脉冲网络继续用 AdamW。差距约一半在短上文时就已存在，另一半随上文变长而拉开（5.19 节）。
长文本（PG-19，5.22 节）上也看不出脉冲网络用上了 2000 个 token 以前的内容，这条线暂停。

### 硬件（目标 3）

- **质量相当时的第一次完整比较**（5.43 节）：硬件网络 `g29_hw`（1.21 亿参数，4 位权重，3.753）和质量相当的 Transformer
  （3,100 万到 5,000 万参数之间：31M 的 `g33_tf31` 是 3.789）。GPU 一侧在 H100 上量了两种口径：成熟的服务软件 vLLM（正式口径），
  和只做生成本身的最简程序（GPU 本身能做到多少的界限）；FPGA 一侧是估算（两张 U55C，或一张 V80）。

  | 路数 | 两张 U55C（估算） | GPU，最简程序 | GPU，vLLM |
  |---|---|---|---|
  | 1 | 0.018 ms，5.5 mJ | 0.25–0.31 ms，26–43 mJ | 1.0 ms，96–106 mJ |
  | 16 | 每步 0.15 ms，2.76 mJ | 每步 0.31–0.37 ms，2.5–4.2 mJ | 每步 1.2 ms，7.5–9.3 mJ |
  | 4,096 | 每秒 10.9 万，2.76 mJ | 每秒 29–116 万，0.34–1.39 mJ | 每秒约 8 万，1.5–3.4 mJ |

  **站得住的优势只在少数几路**：单路时每个 token 快 14–17 倍、省 5–8 倍（和最简程序比）。大量并发时 GPU 明显更好，
  根本原因是硬件网络每个 token 的稠密乘加（5,860 万次）是质量相当的 Transformer 的 2–3 倍，脉冲的稀疏几乎没有用在大头上。
  （按 5.60 节的"部分放置"重算，`g29_hw` 用一张 U55C 单路和 16 路都约 2.76 mJ，质量相当、一张卡放得下的 31M Transformer 是 0.96 mJ。）
  要扩大优势，需要同样质量下更小的网络，或者让层间传递真正稀疏起来。
- **真实的 FPGA**：AMD HACC 计划在新加坡国立大学的机群有 6 张 Alveo U55C（没有 V80）。整数版的定义和 FPGA 内核已经写好，
  在 C 模拟里和整数参考实现逐位一致；下一步在 HACC 上综合、上板卡实测（5.44 节）。
- 8 位权重和 8 位激活几乎不损失质量（+0.006、+0.005）；硬件网络按 4 位权重训练，代价 0.019（5.39 节）。

## 网络结构

默认的网络只由 LIF 神经元组成（项目里说的"纯 LIF"）：

| 部件 | 在神经元层面是什么 | 代码 |
|---|---|---|
| 输入 | 每个词表项对应一个"输入神经元"。读到 token `x_t`，该神经元发放 1 个脉冲，经突触注入电流（数学上等于 embedding 查表） | `SpikingLM.embed` |
| 隐藏层 | L 个 LIF 神经元群，每群 H 个。通用文本上现在用 12 × 4096（212M）和 12 × 3072（138M） | `LIFPopulation` |
| LIF 动力学 | `V[t] = β·V[t-1] + I[t]`；`s[t] = [V[t] ≥ θ]`；发放后乘法复位 `V ← V·(1 − γ·s)`。β（漏电）、θ（阈值）、γ（复位程度）每个神经元各自可学习 | `lif.py`（内核：`lif_kernel.cpp`、`lif_triton.py`） |
| 调节漏电的突触 | 同一批脉冲除了注入电流，还经另一组低秩突触改变漏电快慢：`β[t] = sigmoid(β_logit + U·bus[t])`，网络可以按读到的内容决定一个神经元"保持"还是"清空"（相当于生物神经元里的电导型突触） | `--leak_rank` |
| 神经元之间的连接 | 只传 0/1 脉冲，突触是线性加权求和（外加偏置） | `w_in`、`w_out` |
| 跨层连接（总线） | `bus_l = embed[x_t] + Σ_{k<l} W_out_k·s_k`，`I_l = W_in_l·bus_l + b_l`。总线只是脉冲的加权和，没有状态，也没有非线性，作用相当于 Transformer 的残差流 | `SpikingLM.forward` |
| 输出 | 词表大小的一组读出神经元，只积分、不发放，膜电位 `W_head·bus_L` 就是 logits | `SpikingLM.head` |
| 记忆 | 只在膜电位里。生成时每一步只携带各神经元的膜电位（212M 网络每路约 150 KB），不保存、也不回看历史 token | `SpikingLM.generate` |

- **不包含**：注意力、归一化层（LayerNorm 等）、非脉冲的非线性单元。
- **时间步**：每个 token 对应一个模拟时间步，同一时间步内脉冲逐层向上传完。
- **可选扩展**（默认关闭，详见 [`docs/running.md`](docs/running.md#全部选项) 和 `model.py` 开头的说明）：
  - 每个 token 模拟多步（`--steps_per_token`）；
  - **可塑突触**（`--mem_heads`）：一个用脉冲读写的联想记忆。键神经元发放时，把当前的值写进它那一行突触；
    查询神经元发放时，读出它那一行；突触随时间衰减。第十七批里它带来的改善最大（5.32 节），现在是新配方的一部分。
  - **现在默认配方里偏离"纯 LIF"的地方**（第 3 次自我审计要求列全）：
    - 可塑突触本身（突触权重随活动快速变化）；写入按 (1 − λ) 缩放（`--mem_write_avg`）；读出按每组的均方根缩放（`mem_eps`）；
    - 总线归一化（`--bus_norm`，5.49 节）：每个读总线的地方先除以总线的均方根，像 Transformer 的 pre-norm；
    - 输出门（`--mem_gate channel`，5.55 节）：读出乘以 silu(W_g · 总线)，这是稠密的实数乘法和非脉冲的非线性；
    - 一个词里最多 4 个脉冲的键和查询神经元、延迟 0–3 个词的突触（5.55 节）：仍是脉冲和突触的形式；
    - 词的组合输入和两级读出（5.36 节）：只改输入、输出的编码方式。
    77M 那条线（`model_tf.py` 的门控线性注意力 + 0/1 单元 + 量化中继）离 LIF 更远：记忆不是脉冲网络，0/1 单元和中继都没有膜电位。
  - 试验和诊断用的选项（不在正式配方里）：把可塑突触换成线性注意力 `--mem_kind gla`（5.50 节，不是脉冲网络）、
    （第三十五、三十七批试过的 `--in_rank`、`--mem_src spikes`、`--spike_soft` 不采用，已删掉，代码在提交 5fcacfd。）
  - 试过但没有带来改善的结构选项（同层连接、带延迟的突触、脉冲化总线、输入电流缩放，可塑突触的纠错式写入、按位置写入、按次数归一化）已从代码里删掉，
    记录仍在实验记录里，代码在提交 490e9e6、c138343、c0868f9、bf7fed7 和 5fcacfd。
  - 按第 0 节第 4 条，偏离纯 LIF 时要记录理由，并保留硬件上的好处：神经元之间传脉冲，状态大小固定。

## 训练方法

- **代理梯度 + 沿时间反向传播**：前向用阶跃函数，反向用 fast-sigmoid 代理导数 `1/(1+α|z|)²`，其中 `z=(V−θ)/θ`，α=4。
  反向传播贯穿整个训练片段（通用文本上 1024 个 token）。
- **内核**：LIF 的时间循环有手写的前向和反向内核，CPU 上是 C++/OpenMP（`lif_kernel.cpp`），GPU 上是 Triton（`lif_triton.py`）。
  两者都和纯 PyTorch 的参考实现逐项核对过。矩阵乘法用 bf16，膜电位用 float32。
- **优化器**：AdamW，余弦学习率。
- **训练方法**：在 TinyStories 上有效的"三种方法"是：
  - 蒸馏：老师是同样数据上训练的 Transformer；
  - 权重的滑动平均；
  - 神经元自身参数的学习率乘 10。
  通用文本上蒸馏同样有效，和可塑突触能叠加（5.32 节）。
- **对照组**：同样数据、同样训练流程的 Transformer（`model_tf.py`）。
