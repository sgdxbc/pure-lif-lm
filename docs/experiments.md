## 1. 最早的网络："纯 LIF"具体指什么（原 README 第 1 节，最早的 CPU 模型）

| 部件 | 在神经元层面是什么 | 代码 |
|---|---|---|
| 输入编码 | 每个词表项对应一个"输入神经元"。读到 token `x_t`，该神经元在第 t 步发放 1 个脉冲，经突触注入电流（数学上等于 embedding 查表） | `SpikingLM.embed` |
| 隐藏层 | 8 个 LIF 神经元群，每群 1536 个，共 12,288 个 LIF 神经元 | `LIFPopulation` |
| LIF 动力学 | `V[t] = β·V[t-1] + I[t]`；`s[t] = [V[t] ≥ θ]`；硬复位 `V ← V·(1-s)`。β（泄漏）和 θ（阈值）每个神经元各自可学习。后续实验里也用部分复位 `V ← V·(1-γ·s)`，γ 每个神经元各自可学习（第 5 节） | `lif_kernel.cpp` |
| 神经元之间的连接 | 只传 0/1 脉冲，突触是线性加权求和（外加一个常数背景电流，即偏置） | `w_in`, `w_out` |
| 跨层连接 | 第 l 群从输入神经元以及之前所有群接收脉冲。这些跳跃突触经过一条 384 维的"电流总线"做了低秩分解：`bus_l = embed[x_t] + Σ_{k<l} W_out_k·s_k`，`I_l = W_in_l·bus_l + b_l`。总线只是脉冲的线性加权和，**没有状态，也没有非线性**；它起的作用相当于 Transformer 的残差流 | `SpikingLM.forward` |
| 输出解码 | 词表大小的一组"读出神经元"，只积分、不发放（β=0），膜电位 = `W_head·bus_L` 就是 logits，经 softmax 后采样出下一个 token | `SpikingLM.head` |
| 记忆 | **只存在于膜电位里**。生成时每一步只携带 12,288 个膜电位，不保存、也不回看历史 token | `SpikingLM.generate` |

**不包含**：注意力、LayerNorm/RMSNorm/BatchNorm、门控或任何乘法交互、层内循环矩阵。
（第 5 节的实验里试过两种可选扩展：低秩的同层连接，以及"调节漏电的突触"。它们默认关闭，正式模型里都没有。）

时间步约定：每个 token 对应一个模拟时间步；在同一时间步内，脉冲逐层向上传播完毕（这是深度 SNN 训练中常用的离散时间约定）。
第九批起可以让每个 token 模拟多个时间步（`--steps_per_token`，5.21 节）。

## 2. 最早的训练方法（原 README 第 2 节）

- 代理梯度 + 沿时间反向传播（BPTT）：前向用阶跃函数，反向用 fast-sigmoid 代理导数 `1/(1+α|z|)²`，其中 `z=(V-θ)/θ`，α=4。
- LIF 的时间循环写成了 C++/OpenMP 内核（`lif_kernel.cpp`），前向和反向都是手写的，并与纯 PyTorch 参考实现逐项核对过（`test_lif.py`：独立神经元、同层连接、可变漏电三种内核各 12 种配置，相对误差都在 1e-5 以内）。
- 矩阵乘法用 bf16（这颗 CPU 带 AMX，能跑到约 3 TFLOPS），膜电位用 fp32 计算和保存。
- 分词：在 TinyStories 上训练的 4096 词表字节级 BPE（平均约 3.95 字符/token）。

## 3. 最早的消融实验（CPU，12.6M 规模，每组 400 步 × 8192 token ≈ 330 万 token，验证 loss）

| 配置 | 验证 loss | 现象 |
|---|---|---|
| 软复位、sigmoid 代理梯度、截断复位梯度、lr 2e-3（base） | 3.141 | 梯度范数常冲到 100 以上；前 4 层几乎不发放（<1%） |
| base + 改用"缩小权重"做初始化 | 3.198 | 梯度范数冲到 800 |
| base + fast-sigmoid | 2.969 | 各层发放率恢复到 2%–16% |
| **base + 硬复位** | **2.819** | 梯度稳定，所有层都在工作 |
| 硬复位 + fast-sigmoid | 2.779 | |
| 硬复位 + 复位梯度不截断 | 2.736 | |
| 硬复位 + lr 4e-3 | 2.703 | |
| 硬复位 + fast-sigmoid + 不截断 + lr 4e-3 | 2.721 | 梯度最稳（0.38），各层发放率约 3% |
| *参照：同规模 Transformer（12.4M，5 层，lr 2e-3）* | *2.707* | |

几点解读：
1. **硬复位是最关键的一项**。发放即清零，等于让神经元"由输入决定何时遗忘"（类似 Mamba 这类模型的选择性），同时把反向传播在发放时刻截断，梯度不会沿长时间链条累积。
2. **阈值法初始化**：慢神经元（β→1）会累积很大的膜电位。与其缩小它们的输入权重，不如把阈值 θ 调高到 `1/sqrt(1-β²)`。两种做法的前向计算完全等价，但后一种让 Adam 对所有权重的相对更新幅度一致，训练初期更平稳。
3. 同样 330 万 token 时，纯 LIF 网络和同规模的 Transformer 基本持平。这只是训练早期的单次对比，Transformer 的超参数也没有专门调。

## 4. 第一个正式训练的模型（12.6M，CPU，TinyStories）

配置：8 层 × 1536 LIF（共 12,288 个神经元，12.62M 参数），硬复位 + fast-sigmoid 代理梯度 + 复位梯度不截断，
batch 32 × 256，14,000 步 = 1.15 亿 token（约占训练集的 1/5，每条数据最多见一次），学习率峰值 3e-3、余弦衰减，
4 核 CPU 训练 2 小时 45 分钟（约 11,500 token/s）。

| 指标（完整验证集，557 万 token） | 数值 |
|---|---|
| 验证 loss | **1.912 nats/token**（困惑度 6.76） |
| 每字符比特数 | **0.696 bits/char**（与分词方式无关，可横向比较） |
| 平均发放率 | 训练末期约 4%（每个 token 约 500 个神经元发放，共 12,288 个） |
| 流式生成速度 | 约 610 token/s（batch 1，单 CPU；每步只携带膜电位，代价不随上下文变长而增加） |

验证 loss 随训练的变化（每 1000 步）：2.71 → 2.55 → 2.46 → 2.39 → 2.31 → 2.27 → 2.20 → 2.15 → 2.09 → 2.04 → 1.99 → 1.95 → 1.93 → 1.91。
训练结束时曲线还在下降，没有饱和，继续训练应该还能变好。

**样例**（温度 0.8，top-k 50；前缀部分为人工给定）：

> **Once upon a time**, there was a little girl named Mia. She had a pet dog named Max. ... One sunny day, Mia and Max went to the park. ...
> In the end, they were not grumpy anymore. They both had a great time and were very happy.

> **Lily wanted to go to the park, but** she did not know how. "Look, Ben, I found a big box!" Ben said. Lily opened the box and found many colorful balls. ...
> "Help, help, dog!" Lily shouted. "We can't get out!" They pulled and pulled, but the dog did not come.

> **One day, a little bird could not fly. It** was so very high. The bird was sad. ... A girl named Lily wanted to help the bird. She had an idea. ...
> The bird and Lily became good friends. They sang together every day.

完整样例见 `runs/main/final_eval.json`。

**观察到的现象**
1. **时间常数的分布主要来自初始化，不是训练学出来的**（`figs/time_constants.png`）：时间常数初始化为 0.5–200 token 之间对数均匀分布。
   重建初始权重后逐个神经元对比，训练前后的相关系数是 0.976，整体只略向慢的方向移动（中位数约从 10 token 变为 12 token）；
   阈值 θ 的变化大一些（相关系数 0.758）。早先版本的 README 把图中的形状解读为"快慢神经元自发分化"，这是误读，特此更正。
2. **稀疏发放**（`figs/raster.png`）：各层发放率约 4%–6%。故事开头（"Once upon"）会出现一次大范围的同步发放，之后转为稀疏活动。
3. **主要弱点：精确复述上文中的罕见词**。人名前后不一致（"Tom and Tom"、he/she 混用），给一个罕见名字（如 "Bolt"）它很快就记丢了。Transformer 能用注意力直接回看原文，这个网络却必须把身份信息压进膜电位再还原出来，对 1 比特/步的 LIF 群体来说很难。偶尔还会陷入重复（"You are mean. You are rude..."）。

**和 Transformer 对照组的比较**：330 万 token 时两者都约 2.70；1230 万 token 时 Transformer 已明显领先（2.046 对 2.31–2.37）。
相同 1.15 亿 token 预算的对照见 5.7 节。

## 5. 后续实验：复位方式、同层连接、扩大规模、神经元参数的学习率

正式训练之后，模型最明显的弱点是"记不住上文里的具体内容"（人名前后不一致等）。
这一节的实验都围绕一个问题：**这个网络能在多大程度上借助膜电位回看上文，怎样能让它回看得更好。**

除特别说明外，短实验都是 1500 步 × 8192 token = 1230 万 token、12.6M 参数（8 层 × 1536），
"验证 loss"是固定的 40 个验证 batch（约 33 万 token）上的平均值。
同一设置换随机种子重跑（第四阶段测了两组）：验证 loss 相差 0.001–0.004；测量 B 的回看收益相差 0.03–0.10，
测量 A 的上文收益相差约 0.003。所以短实验之间验证 loss 0.01 以上的差别是可信的，回看收益要差 0.1 左右才算明显。

### 5.1 两种测量"回看能力"的方法

**测量 A：截断上文**（`probe_memory.py`）。取验证集里足够长的故事，只看第 128–191 个 token 上的 loss；
让模型从第 128 个 token 之前 k 个 token 处开始读（脉冲网络从静息状态开始）。k 从 8 增加到 128 时 loss 降了多少，
就是 8 个 token 以外的上文对它的帮助（表中记作"上文收益"）。

**测量 B：重复出现的词**（`probe_recall.py`）。找出故事中重复出现的内容词（排除最常见的 150 个词，
剩下的主要是人名、物品名），比如第 30 个 token 是 "Lily"，第 110 个 token 又要预测 "Lily"，两次相距 80。
对这个词比较两种条件下的 loss：读了整篇故事 / 只读最近 16 个 token（早先那次出现被截掉）。
两者之差就是"早先的内容对预测这个词的帮助"，按距离分组。差值 1 表示正确词的概率平均提高到约 e ≈ 2.7 倍。
对照组是故事里第一次出现的内容词：它们不可能靠"回忆同一个词"受益，上文只能通过故事大意帮忙，约 0.2。

**净回看收益（第七批之后补充）。** 测量 B 的差值有一个弱点：如果一个模型在"只读最近 16 个 token"时变差了
（比如它不太会从故事中间冷启动），差值也会变大，看起来像是回看能力变强了，实际上记忆并没有变好。
对照组（第一次出现的词）同样受冷启动的影响，所以用"重复词的收益 − 第一次出现的词的收益"可以扣掉这部分，
剩下的才是"回忆同一个词"本身带来的帮助，记作净回看收益。5.18 节起两种数字都列出，比较时以净回看收益为准；
`slurm/recall_gains.py` 也同时打印两者。

### 5.2 第一阶段：复位方式和同层连接（各 1230 万 token）

| 配置 | 验证 loss | 训练速度（token/s） | 上文收益（测量 A） |
|---|---|---|---|
| 基线：硬复位（γ = 1） | 2.366 | 14,100 | 0.066 |
| 部分复位，γ 可学习，初值 0.9 | 2.350 | 13,500 | 0.072 |
| 同层连接（低秩，秩 128） | 2.350 | 8,400 | 0.072 |
| 部分复位 + 同层连接 | 2.333 | 8,500 | 0.075 |
| **部分复位，γ 初值在 0.05–1 之间均匀铺开** | **2.313** | 13,800 | **0.086** |
| *参照：Transformer（12.4M，5 层）* | *2.046* | *10,800* | *0.178* |

- 让一部分神经元"发放后只清掉一小部分膜电位"（γ 小）是最划算的改动：不增加计算量，loss 和回看都有改善。
- 同层连接有一点帮助，但让训练慢了约 40%，按相同时间算并不划算，后面没有再用。按README 第 0 节的原则（以相同训练数据下的效果为准），它值得在更大规模上重新评估。
- 和 Transformer 的差距，大约 70% 出在 8 个 token 以内的局部预测上（k = 8 时差 0.29，k = 128 时差 0.41）。

### 5.3 第二阶段：扩大规模（1.15 亿 token）

配置：10 层 × 2048 个 LIF 神经元（共 20,480 个），总线 512 维，25.25M 参数；γ 初值铺开；峰值学习率 2.5e-3（正式模型是 3e-3）；
其余和正式训练相同。4 核 CPU 约 5 小时 20 分钟（中途容器重启一次，从第 6000 步的存档接着训练）。

| 指标（完整验证集） | 正式模型（12.6M） | 大模型（25.25M） |
|---|---|---|
| 验证 loss | 1.912 | **1.793** |
| 每字符比特数 | 0.696 | **0.653** |
| 上文收益（测量 A） | 0.148 | 0.169 |
| 流式生成速度（batch 1） | 610 token/s | 326 token/s |

同一步数下大模型的验证 loss 始终低约 0.09–0.13；第 10,000 步时已和正式模型训练完的结果持平。

> Mia's mom saw her crying and asked her what was wrong. Mia told her mom that she lost her toy. Her mom hugged her and said, "Don't worry, Mia. We will find your toy car."

局部更通顺了，但角色身份混淆仍然常见（同一段里 "wise old man" 和 "wise owl" 来回切换，"Sam and Sam went back to their homes"）。

### 5.4 第三阶段：神经元参数的学习率

前面发现，β、θ、γ 这些每个神经元自己的参数在 1500 步里几乎不动（训练前后相关系数 ≥ 0.98）。
这里把它们的学习率单独放大 10 倍或 30 倍（其余参数不变）：

| 配置 | 验证 loss | τ 前后相关 | θ 前后相关 | γ 前后相关 | 上文收益（测量 A） |
|---|---|---|---|---|---|
| γ 铺开，×1 | 2.313 | 0.999 | 0.987 | 0.998 | 0.086 |
| γ 铺开，×10 | **2.295** | 0.959 | 0.693 | 0.898 | 0.087 |
| γ 铺开，×30 | 2.303 | 0.866 | 0.529 | 0.687 | 0.091 |
| γ 统一 0.9，×1 | 2.350 | 0.999 | 0.979 | — | 0.072 |
| γ 统一 0.9，×30 | 2.341 | 0.863 | 0.561 | — | 0.082 |

学习率放大后这些参数确实动起来了，而且学到的变化有规律。以"γ 统一从 0.9 出发、×30"为例：

| 初始时间常数 τ | γ 平均值（训练前 → 后） | γ < 0.5 的比例（训练后） |
|---|---|---|
| < 2 token | 0.90 → 0.78 | 17% |
| 2–10 | 0.90 → 0.65 | 29% |
| 10–50 | 0.90 → 0.66 | 31% |
| > 50 | 0.90 → 0.62 | 38% |

也就是**时间常数越长的神经元，学到的复位越轻**（发放时保留更多膜电位），越靠前的层降得越多。
这说明 γ 的梯度虽然每一步都很嘈杂（Adam 的 |m|/√v 中位数约 0.15，和纯噪声差不多），但里面有一个微弱、稳定的方向；
学习率为 ×1 时步子太小，1500 步里积累不出来。不过即使学动了，它也没追上"一开始就把 γ 铺开"的效果（2.341 对 2.313）。

### 5.5 回看能力随距离的变化（测量 B）

表中数字是"读整篇 / 只读最近 16 个 token"的 loss 差。

| 早先出现的距离 | γ=1，1230 万 | γ 铺开，1230 万 | γ 铺开 ×30，1230 万 | 正式模型 12.6M，1.15 亿 | 大模型 25.25M，1.15 亿 | Transformer，1230 万 |
|---|---|---|---|---|---|---|
| 17–32 | 0.52 | 0.69 | 0.79 | 1.80 | 2.17 | 2.09 |
| 33–64 | 0.39 | 0.48 | 0.56 | 1.33 | 1.59 | 1.66 |
| 65–128 | 0.29 | 0.35 | 0.39 | 0.87 | 0.97 | 1.14 |
| 129–256 | 0.24 | 0.31 | 0.32 | 0.52 | 0.68 | 0.77 |
| 对照：首次出现 | 0.16 | 0.16 | 0.17 | 0.21 | 0.25 | 0.20 |

1. **能回看，但距离越远越弱。** 正式模型对 17–32 个 token 前出现过的词，把正确词的概率平均提高到约 6 倍；129–256 个 token 时只有约 1.7 倍。
2. **训练量影响最大。** 同样结构，训练量增加 10 倍，各距离上的回看收益都翻了一倍以上。训练量少时，连 1–4 个 token 前刚出现过的词也抄得很差（loss 3.48，首次出现的词是 4.10；训练充分后是 2.09 对 3.39）。
3. **规模有帮助，远距离也在涨**（大模型对正式模型：129–256 从 0.52 到 0.68），但比较慢。
4. **放大神经元参数的学习率只改善了近距离**（17–64），最远的一档基本没变。
5. 即使是只训练了 1/10 数据量的 Transformer，在 65 个 token 以外仍然领先，而且距离越远，脉冲网络的相对差距越大。

### 5.6 为什么越远越弱：结构上的原因

- **漏电速度固定，和内容无关。** 膜电位每一步乘以固定的 β，重要和不重要的信息按同样速度消失。
- **读出会擦除。** 神经元把信息传出去的唯一方式是发放，而发放会复位。γ 铺开之所以有效，和"让一部分神经元发放时不清空"是一致的。
- **信息叠加在固定数量的膜电位里**，不同 token 的信息混在一起；Transformer 则每个 token 单独存放。

前两条由方程本身决定，靠训练改变不了。为此加入了可选的**调节漏电的突触**（`--leak_rank`）：
除了注入电流的普通突触，再加一组来自同样突触前脉冲的低秩突触，它们不注入电流，而是改变神经元当前这一步的漏电速度：
`β[t] = sigmoid(β_logit + U·bus[t])`。这样网络可以在读到重要内容时让某些神经元几乎不漏电，在话题切换时让它们快速清空。
U 初始为零，所以训练开始时和原网络完全相同。这和神经科学里的电导型突触思路一致；
不过这里的调节是双向的（既能减慢也能加快漏电），而生物上的电导型突触通常只能加快漏电。

### 5.7 公平对照：同样 1.15 亿 token 的 Transformer

Transformer 对照组：5 层，d_model 384，6 个注意力头，12.39M 参数（和正式模型的 12.62M 基本相同），
数据、batch、步数、学习率调度都和正式模型一样（`runs/tf_full`）。

| 指标 | 脉冲网络 12.6M | 脉冲网络 25.25M | Transformer 12.4M |
|---|---|---|---|
| 验证 loss（完整验证集） | 1.912 | 1.793 | **1.480** |
| 每字符比特数 | 0.696 | 0.653 | **0.539** |
| 测量 A：上文从 8 加到 128 个 token 的收益 | 0.148 | 0.169 | **0.300** |
| 测量 A：完全没有上文时（k=0） | 2.402 | 2.286 | **2.024** |

测量 B（"读整篇 / 只读最近 16 个 token"的 loss 差）：

| 早先出现的距离 | 脉冲网络 12.6M | 脉冲网络 25.25M | Transformer，1230 万 token | Transformer，1.15 亿 token |
|---|---|---|---|---|
| 17–32 | 1.80 | 2.17 | 2.09 | **3.05** |
| 33–64 | 1.33 | 1.59 | 1.66 | **2.63** |
| 65–128 | 0.87 | 0.97 | 1.14 | **1.90** |
| 129–256 | 0.52 | 0.68 | 0.77 | **1.39** |
| 对照：首次出现 | 0.21 | 0.25 | 0.20 | 0.34 |

1. **差距很明显。** 同样的参数量和训练量，Transformer 的验证 loss 低 0.43；脉冲网络参数翻倍只追回了其中 0.12。
2. **差距不只在远距离。** 完全没有上文时（测量 A 的 k=0），Transformer 也领先约 0.38；读整篇时，对 1–4 个 token 前刚出现过的词，
   Transformer 的 loss 是 1.04，脉冲网络是 2.09。也就是说，脉冲网络在"处理眼前几个词"上就已经落后，不能全部归因于记忆距离。
3. **远距离的相对差距更大。** 129–256 个 token 之外的回看收益，Transformer 是脉冲网络（12.6M）的约 2.7 倍；17–32 时约 1.7 倍。
   而且 Transformer 的回看收益随训练量增长得也很快（从 1230 万到 1.15 亿 token，129–256 一档从 0.77 涨到 1.39），差距并没有随训练缩小。
4. **脉冲网络的长处在状态大小。** 生成时它只需要保存 12,288 个膜电位，和上文多长无关；Transformer 要保存每个已读 token 的键和值，
   读到第 256 个 token 时是 5 层 × 2 × 384 × 256 ≈ 98 万个数，并随上文线性增长。
   （`final_eval.json` 里 Transformer 的生成速度约 61 token/s，脉冲网络约 610 token/s，但这里的 Transformer 生成没有做键值缓存，
   每一步都把整段上文重算一遍，所以这个速度比较对 Transformer 不公平，不能作为结论。）

### 5.8 第四阶段：调节漏电的突触

配置和 5.2 节最好的一组相同（γ 初值铺开，1230 万 token），只是加上调节漏电的突触（5.6 节），并换随机种子重跑。

| 配置 | 参数量 | 验证 loss（种子 0 / 种子 1） | 上文收益（测量 A） | 训练速度（token/s） |
|---|---|---|---|---|
| 无（γ 铺开） | 12.63M | 2.313 / 2.312 | 0.086 / 0.083 | 约 12,200 |
| **调节漏电的突触，秩 64** | 13.62M | **2.234 / 2.230** | **0.102 / 0.102** | 约 6,500 |
| 调节漏电的突触，秩 256 | 16.56M | 2.233 | 0.098 | 约 5,800 |

测量 B（"读整篇 / 只读最近 16 个 token"的 loss 差）：

| 早先出现的距离 | 无，种子 0 | 无，种子 1 | 秩 64，种子 0 | 秩 64，种子 1 | 秩 256 |
|---|---|---|---|---|---|
| 17–32 | 0.69 | 0.73 | 0.76 | 0.84 | 0.76 |
| 33–64 | 0.48 | 0.52 | 0.59 | 0.66 | 0.56 |
| 65–128 | 0.35 | 0.38 | 0.46 | 0.52 | 0.48 |
| 129–256 | 0.31 | 0.34 | 0.37 | 0.47 | 0.43 |
| 对照：首次出现 | 0.16 | 0.18 | 0.17 | 0.20 | 0.19 |

1. **验证 loss 降低约 0.08，远大于换种子的差别（0.001–0.004）。** 作为比较，γ 铺开相对 γ = 1 的改善是 0.05。
2. **远距离回看也变好了。** 65–256 个 token 这两档平均提高约 0.1（约 30%），大于换种子的差别，但幅度不算大；
   这是第一个在远距离上明显起作用的改动（5.4 节放大学习率时，最远一档基本没变）。
3. **秩 256 并不比秩 64 好**，虽然它对漏电的调节幅度大得多（见下）。
4. **代价是训练变慢。** 每一步都要为每个神经元算一次新的漏电系数，第四阶段时整体训练速度约为原来的一半（约 6,500 对 12,300 token/s）。
   早先估计"只慢 10% 左右"是测量时 CPU 被其他任务占用导致的误判，特此更正。
   之后把这部分计算合并进了 C++ 内核（结果逐位相同）：单层单独计时是普通层的 1.86 倍（之前 2.16 倍），
   整个模型训练时约 9,900 对 11,500 token/s（第六阶段实测），只慢约 15%。

**网络学到了怎样调节漏电**（`leak_stats.py`，64 个验证故事；"慢神经元"指静息时间常数超过 20 个 token 的神经元）：

- **调节用得很多。** 秩 64 时，同一个神经元的时间常数随 token 变化，标准差相当于 4–16 倍（以 10 为底的对数 0.6–1.2）。
  平均而言时间常数变长了（多数层约 2–7 倍）：50%–65% 的时刻比静息值长 2 倍以上，20%–35% 的时刻短 2 倍以上。
- **越深的层越常"清空"。** 慢神经元的时间常数瞬间降到 2 个 token 以下的比例，从第 0 层的约 1% 增加到第 7 层的约 17%。
- **第 0 层只看当前这个 token，可以直接看出它对哪些词怎么反应。** 读到逗号、句号、the、to、and 这类虚词时，
  慢神经元的时间常数拉得最长（约 13–25 倍）；1500 步时，人名（Mom、Ben、Tom、Anna）和物品（boat、slide、door）拉长得最少，
  甚至略微缩短。**但这一点随训练变了**：训练到 5000 步时（5.10 节），Lily、Tim 等人名已经排在拉长最多的词里，
  只有 slide、paper、boat 等少数物品词仍让记忆变短。所以稳定的规律只是"虚词和标点让慢神经元保持记忆"，
  "内容词让记忆更新"是训练早期的现象，不能当作结论（早先的汇报里我把它当成了结论，特此更正）。
  近年的选择性状态空间模型（如 Mamba）也是让"保留多少旧状态"随输入变化，思路相近。
- **神经元本身的静息漏电几乎没变**（训练前后相关系数 0.999），调整都由漏电突触完成。

**变化本身是否重要**（`leak_ablate.py`，64 个验证窗口）：把每个神经元逐步变化的漏电换成它自己的平均值，
loss 从 2.17 变为 3.30；全部换回静息漏电是 2.84，都比没有漏电突触、正常训练出来的网络在同样窗口上的 2.25 差得多。
这说明训练好的网络确实在大量依赖"漏电随内容变化"，而不只是把时间常数整体调长了。
（这个检查是在训练好之后才把变化拿掉，网络来不及适应，所以只能说明它"用了"这种变化；
要回答"静态漏电如果初始化得更长，能否达到同样效果"，还需要单独训练对照。）

### 5.9 第五阶段：参数量对照和突触延迟

**参数量对照。** 调节漏电的突触（秩 64）多了约 100 万个参数。为了排除"只是参数多了"，
把每层神经元从 1536 个加到 1696 个，使总参数量同样是 13.62M，其余不变：验证 loss 2.306，只比 2.313 好 0.007，
远小于漏电突触带来的 0.08。各距离的回看收益也和不加宽时基本一样（129–256 一档 0.26）。所以改善来自"漏电可以随内容变化"，不是参数量。

**突触延迟（方向 C）。** 加上延迟 1 和 2 个 token 的低秩突触（秩 64，13.81M 参数，见 `model.py` 开头的说明），
让神经元能直接对"现在这个词和前一两个词"的组合作出反应：

| 配置 | 验证 loss（种子 0 / 种子 1） | 上文收益（测量 A） | 回看收益 65–128 / 129–256 | 训练速度（token/s） |
|---|---|---|---|---|
| 无（γ 铺开） | 2.313 / 2.312 | 0.086 / 0.083 | 0.35–0.38 / 0.31–0.34 | 约 12,200 |
| 加宽到 1696 | 2.306 | 0.086 | 0.37 / 0.26 | 约 11,500 |
| 突触延迟 1–2 步 | 2.310 / 2.306 | 0.082 / 0.082 | 0.35–0.36 / 0.30–0.35 | 约 10,500 |
| *参照：调节漏电的突触，秩 64* | *2.234 / 2.230* | *0.102 / 0.102* | *0.46–0.52 / 0.37–0.47* | *约 6,500* |

突触延迟几乎没有带来改善。但网络确实用上了它们：训练好以后把延迟突触去掉，loss 从 2.245 升到 2.76。
也就是说，网络把一部分"前一两个词是什么"的信息改走延迟突触，而不是额外多学到了什么；
原来靠膜电位也能拿到这些信息。由此看，**脉冲网络和 Transformer 在近距离上的差距，瓶颈不在"拿不到前一两个词"。**

### 5.10 第六阶段：训练量增加到 4100 万 token

同样两种配置（γ 铺开，有 / 无调节漏电的突触，秩 64），各训练 5000 步（4100 万 token，学习率按 5000 步的余弦衰减）：

|---|---|---|---|
| 验证 loss（第 1000 / 2000 / 3000 / 4000 / 5000 步） | 2.633 / 2.413 / 2.244 / 2.108 / **2.040** | 2.563 / 2.342 / 2.158 / 2.018 / **1.952** | −0.07 / −0.07 / −0.09 / −0.09 / **−0.088** |
| 上文收益（测量 A） | 0.123 | 0.140 | +0.017 |
| 回看收益 17–32 / 33–64 | 1.40 / 0.98 | 1.55 / 1.19 | +0.15 / +0.21 |
| 回看收益 65–128 / 129–256 | 0.61 / 0.44 | **0.83 / 0.63** | **+0.22 / +0.19** |
| 训练速度（token/s） | 约 11,500 | 约 9,900 | |

1. **改善随训练量保持住了**（1230 万 token 时 −0.08，4100 万 token 时 −0.088），没有被更多训练抵消。
2. **远距离回看的改善变得更明显**：65–256 个 token 两档提高约 40%（1230 万 token 时约 30%）。

3. 漏电调节的幅度随训练继续变大（深层时间常数随 token 变化的标准差约 1.5–1.9，以 10 为底的对数），
   慢神经元瞬间"清空"的比例在最深一层达到 24%。

从这一阶段起，实验改在学校的 SLURM GPU 集群上跑。作业脚本在 `slurm/`，集群情况和测速见 `runs/gpu_setup_report.md`。

差别都在 0.002 以内，和换随机种子带来的波动相当。所以 CPU 上的第七阶段在第 9100 步停掉了，结果用 GPU 上的那份。

### 5.12 第八阶段：训练方法（GPU 上训练满 1.15 亿 token）

网络固定为 12.6M 脉冲网络（γ 铺开 + 调节漏电的突触，秩 64），学习率 3e-3，每种方法都训练 14000 步（1.15 亿 token），
只改训练方法（`gpu1.sh` 的 (c) 组）。对照组 `g1_s_base` 的验证 loss 是 1.752
（不加漏电突触、不铺开 γ 的正式模型是 1.912）。

| 训练方法 | 验证 loss | 相对对照组 |
|---|---|---|
| 蒸馏：老师是 12.4M Transformer（`g1_tf_full`），老师占比 0.9 | **1.672** | **−0.080** |
| 蒸馏，老师占比 0.5 | 1.684 | −0.069 |
| 权重滑动平均（0.998），用平均后的权重评估 | 1.720 | −0.033 |
| 神经元自身参数（漏电、阈值、复位）的学习率 ×10 | 1.725 | −0.028 |
| 学习率 2e-3 / 4.5e-3 | 1.756 / 1.770 | +0.004 / +0.017 |
| 代理梯度更宽（α=2）/ 更窄（α=8） | 1.792 / 1.818 | +0.039 / +0.066 |
| 跨片段保留膜电位（`--carry_state`） | 1.868 | +0.116 |

1. **蒸馏的效果最大**：老师占比 0.9 比 0.5 更好，说明 Transformer 给出的整个概率分布比单个正确答案包含更多可学的信息。
2. **权重滑动平均**和**神经元参数用更大的学习率**各带来约 0.03 的改善，几乎不增加计算量。
3. 原来的学习率（3e-3）和代理梯度宽度（α=4）已经是这几个选项里最好的。
4. 跨片段保留膜电位明显变差。可能的原因是评测时每段都从静息状态开始，和训练时的情况不一致。

### 5.13 第二批：在整个训练集上扩大规模

脉冲网络（γ 铺开 + 调节漏电的突触）和 Transformer 各取几种规模，都在整个训练集上训练 67000 步
（5.49 亿 token，大约把训练集过一遍；以前的实验都只用了 1.15 亿 token）。批大小、序列长度、预热和学习率衰减方式都和以前相同（`gpu2.sh`）。

| 模型 | 参数 | 学习率 | 验证 loss | 上文收益（测量 A） | 回看收益 65–128 / 129–256 |
|---|---|---|---|---|---|
| 脉冲 | 26.9M | 2.5e-3 | 1.529 | 0.247 | 1.62 / 1.17 |
| 脉冲 | 48.4M | 1.8e-3 | 1.468 | 0.262 | 1.69 / 1.23 |
| 脉冲 | 117.1M | 1.2e-3 | 1.411 | 0.266 | 1.68 / 1.21 |
| 脉冲 | 117.1M | 8e-4 | **1.391** | 0.270 | 1.73 / 1.29 |
| Transformer | 12.4M | 2e-3 | 1.357 | 0.332 | 2.03 / 1.56 |
| Transformer | 29.9M | 1.5e-3 | 1.245 | 0.355 | 2.08 / 1.62 |
| Transformer | 55.1M | 1.2e-3 | 1.190 | 0.364 | 2.10 / 1.71 |
| Transformer | 104.6M | 1e-3 | 1.156 | 0.365 | 2.12 / 1.70 |
| Transformer | 104.6M | 6e-4 | **1.139** | 0.372 | 2.12 / 1.71 |

1. **两种网络都随规模稳定变好。** 脉冲网络参数每翻一倍，验证 loss 大约下降 0.065；Transformer 在小规模时下降得差不多快，
   到 55M 以上开始变慢。
2. **差距用参数量来衡量，目前大约是十倍。** 117M 的脉冲网络（1.391）比 12.4M 的 Transformer（1.357）还差 0.034。
   按上面的斜率推算，脉冲网络大约要 170M 才能追平 12.4M 的 Transformer。
3. **记忆能力的差距在缩小。** 129–256 个 token 的回看收益，12.6M 脉冲网络训练 1.15 亿 token 时只有 0.52，
   而同等训练量的 Transformer 是 1.38；现在 117M 脉冲网络达到 1.29，12.4M Transformer 是 1.56。
4. **数据量本身很重要。** 同样是 12.4M 的 Transformer，训练 5.49 亿 token（1.357）比训练 1.15 亿 token（1.480）好 0.12；
   26.9M 的脉冲网络从 1.709 降到 1.529，好了 0.18。
5. 两个最大的模型都是较低的学习率更好，说明大模型的学习率还可以再往下调。

### 5.14 第三批：三种训练方法能否叠加

网络、数据量和对照组都和第八阶段相同（12.6M 脉冲网络，1.15 亿 token，对照组 1.752；`gpu3.sh`）。
蒸馏的老师仍是 12.4M Transformer（`g1_tf_full`，1.480），老师占比 0.9、温度 1；用了权重滑动平均的，都用平均后的权重评估。
回看收益是 129–256 个 token 一档（测量 B，用的是未平均的权重；事后用平均后的权重补测过，
三个用了滑动平均的组合变化都在 0.03 以内：三者一起 0.95，蒸馏 + 滑动平均 0.98，滑动平均 + 神经元学习率 0.90）。

### 5.16 第五批：神经元个数（状态大小）是不是远距离回看的瓶颈

**问题。** 脉冲网络对过去的全部记忆都存在膜电位里，所以它能记住多少，取决于神经元的个数（每层神经元数 × 层数），
而不直接取决于参数量。第二批扩大规模时，层间总线（d_model）和每层神经元是一起加宽的，参数涨得比神经元快
（27M → 117M：参数 4.4 倍，神经元只有 2.4 倍），129–256 一档的回看收益也只从 1.17 提高到 1.29。
所以要单独检验：参数量不变、只增加神经元，远距离回看会不会变好？

**做法。** 以第二批的 117M 网络为基准（总线宽 1024，每层 4096 个神经元，12 层，共 49,152 个神经元），
把总线变窄、每层神经元加多，让参数量基本不变：神经元翻倍（总线 512，每层 8192 个），和神经元变成三倍（总线 384，每层 12288 个；
这一组参数多了 17%）。都不用三种训练方法，数据、步数、学习率调度和第二批完全相同（5.49 亿 token，`gpu5.sh`）。

| 网络 | 总线宽 | 每层神经元 | 神经元总数 | 参数 | 学习率 | 验证 loss | 上文收益（测量 A） | 回看收益 17–32 / 33–64 / 65–128 / 129–256 |
|---|---|---|---|---|---|---|---|---|
| 基准 | 1024 | 4096 | 49,152 | 117.1M | 8e-4 | **1.391** | 0.270 | 2.65 / 2.28 / 1.73 / 1.29 |
| 基准 | 1024 | 4096 | 49,152 | 117.1M | 1.2e-3 | 1.411 | 0.266 | 2.64 / 2.29 / 1.68 / 1.21 |
| 神经元 ×2 | 512 | 8192 | 98,304 | 118.6M | 8e-4 | 1.416 | 0.261 | 2.55 / 2.17 / 1.61 / 1.08 |
| 神经元 ×2 | 512 | 8192 | 98,304 | 118.6M | 1.2e-3 | 1.426 | 0.257 | 2.56 / 2.22 / 1.64 / 1.25 |
| 神经元 ×3 | 384 | 12288 | 147,456 | 136.4M | 8e-4 | 1.432 | 0.249 | 2.56 / 2.12 / 1.49 / 1.05 |

1. **神经元多了，验证 loss 没有变好，反而略差。** 在相同学习率下比较：8e-4 时，神经元翻倍差 0.025，变成三倍差 0.041
   （尽管参数还多了 17%）；1.2e-3 时，神经元翻倍差 0.015。整个训练过程中，验证 loss 曲线都比基准略高一点，并没有后来居上的迹象。
2. **远距离回看也没有变好。** 129–256 一档：8e-4 时从 1.29 降到 1.08（×2）和 1.05（×3）；1.2e-3 时从 1.21 变成 1.25，
   基本持平。这一档的数字本身有一定波动（同一个 ×2 网络，两种学习率之间差了 0.17），但方向很一致：没有一组明显变好。
   近距离（17–32）各组都比基准低 0.09 左右；上文收益（测量 A）也随神经元增多从 0.27 降到 0.25。
3. **多出来的神经元确实在工作。** 训练结束时三种网络的平均发放率差不多（2.7%、2.7%、2.4%），
   所以每层每个 token 发出的脉冲数从 111 个增加到 223 个和 298 个。不是"多出来的神经元一直沉默"造成的。
4. **需要注意的一点：** 这个实验在加神经元的同时把总线变窄了（参数量要保持不变，只能这样换）。
   总线是层与层之间传递信息的通道，它变窄可能抵消了状态变大的好处。所以严格地说，这一批证明的是
   "在参数量固定时，用总线宽度去换神经元个数没有好处"，而不是"神经元再多也没用"。
   不过第四批从 117M 到 257M 时，总线和神经元都变大了（神经元 49,152 → 73,728），129–256 一档同样没有提高
   （普通训练 1.29 → 1.29，加三种方法 1.51 → 1.49）。两个方向的证据合在一起，说明在 256 个 token 的范围内，
   单纯把网络做大或者把状态做大，都不能直接提高远距离回看。
5. **速度：** 神经元越多，每个 token 的计算越慢，神经元 ×2 的网络在 A100 上每秒约 6.5 万 token，训练用了 2.3 小时。

**结论：远距离回看主要卡在"学不学得会"，而不是"装不装得下"。** 要记住远处的词，网络至少需要三样东西：
有地方存（神经元个数）、有连接把信息存进去和取出来（参数）、以及训练过程能教会它在该存的时候存、该取的时候取。
目前看，前两样都不是瓶颈：状态翻倍、变三倍，参数翻倍，129–256 一档都不提高；而网络大小完全不变、只加上蒸馏，
117M 网络就从 1.29 提高到了 1.51（第四批；按 5.1 节后来补充的净回看收益是 0.93 → 1.10，结论不变）。
蒸馏改变的只是训练信号，所以瓶颈更可能在训练这一边。
这也回答了"参数量是不是应该匹配回看窗口"的问题：至少在 256 个 token 以内，现在的网络并不缺参数或状态，
缺的是让它学会长距离存取的训练信号。更长的窗口（比如上千个 token）是否会需要更大的状态，这一批还回答不了。

### 5.17 第六批：在训练集上多过几遍

**问题。** 第四批里，脉冲网络从 117M 加到 257M，验证 loss 只改善了 0.036，比第二批"参数每翻一倍改善约 0.065"小得多。
一个可能的原因是 257M 的网络数据不够：它只看了 5.49 亿 token，平均每个参数约 2 个 token。
如果是这样，多给数据时 257M 应该比 117M 受益更多。

**做法。** 把第四批两个加了三种方法的网络在训练集上过两遍（134000 步，11.0 亿 token），117M 再加一个过三遍的（16.5 亿 token）；
105M Transformer 也过两遍，作为对照。训练集只有 5.52 亿 token，所以多出来的训练量是把同一批故事再读一遍。
其余设置和第四批完全相同（`gpu6.sh`）。用了滑动平均的网络，表中所有数字都用平均后的权重。

| 模型 | 参数 | 训练量 | 验证 loss | 上文收益（测量 A） | 回看收益 65–128 / 129–256 |
|---|---|---|---|---|---|
| 脉冲 + 三种方法 | 117.1M | 1 遍（5.49 亿 token） | 1.278 | 0.297 | 1.88 / 1.51 |

| 脉冲 + 三种方法 | 117.1M | 3 遍（16.5 亿） | 1.226 | 0.315 | 1.92 / 1.54 |
| 脉冲 + 三种方法 | 257.1M | 1 遍 | 1.242 | 0.306 | 1.92 / 1.49 |

1. **多过一遍，三个模型都明显变好，而且好得差不多一样多。** 117M 改善 0.040，257M 改善 0.043，105M Transformer 改善 0.045。
   第三遍只再改善 0.012，重复使用同一批故事的收益在快速变小。
2. **"257M 特别缺数据"的猜测不成立。** 如果 257M 比 117M 更缺数据，第二遍对它的帮助应该明显更大，实际只多了 0.003。
   过两遍时，117M → 257M 的改善是 0.039，和过一遍时的 0.036 差不多。所以参数加倍收益变小，原因不在数据量。
   剩下的可能有两个：一是 257M 的学习率不合适（只试过 5e-4）；二是网络的形状——117M 到 257M 只是把每层加宽
   （总线 1024 → 1536，层数都是 12），而 27M 到 48M 时层数也从 10 层加到了 12 层。第八批检验这两点。
3. **同样多的数据下，和 Transformer 的差距没有缩小。** 105–117M 这个量级，过一遍时差 0.141，过两遍时差 0.147。

   117M 从 1.51 提高到 1.55，第三遍不再提高（1.54）。但按后来补充的净回看收益（5.1 节，扣掉对照组），

   也就是说，在训练量相同的公平比较下，257M 脉冲网络大约相当于 30M 的 Transformer，参数量相差 8 倍多，这个比例和第四批一样。

### 5.18 第七批：加长训练片段

**问题。** 5.16 节的结论是瓶颈在训练信号，而训练数据本身有一个特点：TinyStories 的故事很短
（平均 202 个 token，中位数 179，只有 13% 达到 256 个 token），训练时又是从整个文本里随机截取 256 个 token 的片段，
片段通常从某个故事的中间开始。在训练数据上统计：一个位置在片段内能看到本故事前文超过 128 个 token 的，只占 17.9%；
超过 192 个 token 的只占 3.6%。网络在训练中很少有机会练习"回看 129–256 个 token"，这会不会是远距离回看弱的原因？
片段加长到 512 个 token，这两个比例会提高到 27.1% 和 9.2%。

**做法。** 第二批的 117M 网络（学习率 8e-4，不用三种方法），训练片段从 256 加长到 512 和 1024 个 token，
批大小相应减到 16 和 8，每步的 token 数（8192）、总步数和学习率调度都不变（`gpu7.sh`）。验证 loss 仍然在 256 个 token 的片段上测。
另外在较长的故事上（至少 513 个 token，约占 2%）把回看测量延伸到 512 个 token（`probe_recall.py --length 512`），
新增 257–512 一档；用 256 个 token 训练的网络从没在第 256 个 token 以后运行过，这一档也顺带检验它们能不能接着往下读。
表中"净"是 5.1 节的净回看收益（扣掉第一次出现的词的收益）；"冷启动 loss"是测量 A 中 k=0（从故事中间、静息状态开始读）的 loss。

| 训练片段 | 验证 loss | 冷启动 loss | 上文收益（测量 A） | 129–256 回看收益 / 净 | 长故事上的净回看 129–256 / 257–512 | 长故事 257–512 处重复词的 loss |
|---|---|---|---|---|---|---|
| 256（第二批） | **1.391** | **1.914** | 0.270 | 1.29 / **0.93** | 0.61 / 0.20 | 2.74 |
| 512 | 1.408 | 1.955 | 0.295 | 1.28 / 0.86 | 0.63 / 0.27 | 2.65 |
| 1024 | 1.425 | 1.995 | 0.310 | 1.33 / 0.86 | 0.65 / 0.30 | 2.65 |
| （对照）256，117M + 三种方法 | 1.278 | 1.798 | 0.297 | 1.51 / 1.10 | 0.69 / 0.33 | 2.39 |
| （对照）256，257M + 三种方法 | 1.242 | 1.761 | 0.306 | 1.49 / 1.06 | 0.71 / 0.37 | 2.27 |

1. **验证 loss 变差了。** 片段 512 差 0.018，1024 差 0.034。冷启动明显变差（1.914 → 1.955 → 1.995）：
   256 个 token 的片段，每个片段都要从静息状态开始读一次；片段越长，这样的练习越少，而验证正是在 256 个 token 的片段上、从静息状态开始测的。
   上文足够长时（k=128）也差了 0.014 和 0.031，可能还因为每步只有 16 或 8 段不同的文字，每步的样本不如原来多样。
2. **256 个 token 以内，远距离回看并没有变好。** 未扣对照组的回看收益看起来持平或略升（1.29 → 1.28 → 1.33），上文收益也升了
   （0.270 → 0.310），但这主要是因为"只读最近 16 个 token"那一边变差了（冷启动变差）。扣掉对照组以后，净回看收益从 0.93 降到 0.86；
   读了整篇时，重复词本身的 loss 也从 2.06 升到 2.18 和 2.21。所以"长距离例子太少"不是远距离回看弱的主要原因：
   超过 192 个 token 的例子增加到约三倍，129–256 一档却没有提高。
3. **256 个 token 以外，加长片段有帮助。** 长故事上 257–512 一档的净回看从 0.20 提高到 0.27 和 0.30，重复词的 loss 从 2.74 降到 2.65。
   这主要是"在更长的时间里保持正常工作"的能力：用 256 个 token 训练的网络从没在第 256 个 token 以后运行过。
   不过，加了三种方法、只用 256 个 token 训练的网络在这一档做得更好（117M 0.33，257M 0.37），
   说明训练得好的网络本身就能接着往下读到 512 个 token，并不需要专门用长片段训练。
4. **小结。** 到目前为止，增加神经元（第五批）、增加参数（第四批）、多读几遍（第六批）、多给长距离例子（这一批），
   对 129–256 一档的净回看收益都只有很小的帮助，甚至略有损害；唯一明显有效的是蒸馏（117M：0.93 → 1.10）。
   老师给的概率分布是目前最有效的"长距离记忆"训练信号，下一步值得在这个方向上多想办法。

### 5.19 第八批：网络形状、学习率和老师

**问题。** 第六批排除了"数据不够"，剩下两个可能的原因：257M 的学习率不合适，或者网络形状不对
（117M → 257M 只加宽、没加深）。另外顺带问：老师变好，学生能不能跟着变好？

### 5.20 硬件代价和低精度模拟：怎么算

目前考虑的硬件实现是 FPGA 和数据流加速器（权重常驻片上、按数据流动计算的芯片）。从这一节起，除了验证 loss 和回看能力，
也报告网络在这类硬件上的代价，并用同样的算法给出 Transformer 的数字作对照（`hw_cost.py`，写入各次实验目录的 `hw_cost.json`）。
所有数字都按"每生成一个 token、每一路对话"计。

**脉冲网络。** 每个 token 的计算分成两半：
- **前半，总线 → 神经元**：每层的 `W_in`、调节漏电的突触，以及最后的读出层。它们的输入是总线，是稠密的实数，
  所以每个权重每一步都要用一次（"稠密乘加"）。每个 token 模拟 T 步时，`W_in` 和调节漏电的突触要用 T 次。
- **后半，脉冲 → 总线**：每层的 `W_out`。只有发放了的神经元，它发出的那一行权重才参与，而且只做加法、不做乘法（"可跳过零的加法"）。

**每个 token 要从片外显存读多少字节**（权重放不进片上存储时，比如 FPGA 板上的 HBM）：
- 前半的权重全部读一遍；
- 后半只读这个 token 里发放过的神经元的那一行。每个 token 模拟 T 步时，第 l 层的 T 步只依赖它前面的层，
  所以可以一层一层地把 T 步算完，每个权重仍然只读一次。
- 16 路同时生成时，前半的权重 16 路共用，只读一次；后半读"任何一路发放过的神经元"的那些行，再除以 16。

发放情况在验证集上实测：64 个 256 token 的片段，每段从静息状态开始读，每 16 段当作同时生成的 16 路。
**状态**是全部膜电位，按每个 24 位计，放在片上。权重分别按 8 位和 4 位计。

**Transformer。**
- 计算量 = 权重的乘加 + 对前面 c 个 token 的注意力。
- 每个 token 要读的字节 = 权重（多路共用）+ 这一路前面 c 个 token 的 key 和 value（按 8 位计）。
- 状态就是这些 key 和 value。
- c 取 256、2048、8192。

**低精度模拟**（`quant_sim.py`，写入 `quant.json`）：不重新训练，把训练好的权重取整，再一步一步地运行网络，
每个量都按硬件的方式取整，看验证 loss 变化多少。所有设置用同一批验证片段，差值是成对比较的。
- 权重：8 位或 4 位整数。每行一个缩放系数，或者每 128 个输入一组一个系数。
- 总线：8 位，每个通道一个缩放系数（这个系数可以并进下一层的权重，在硬件上不额外花代价）；
  调节漏电的突触中间那一层也按 8 位处理。
- 膜电位：先除以各自的阈值（阈值可以并进 `W_in` 和偏置，这样神经元在 1 处发放），再用 16 位或 24 位定点数表示；
  整数部分的位数由校准时的最大值决定，其余是小数位。
- 漏电系数 β（每步经过 sigmoid 之后的值，硬件上用查表）和复位系数 γ：保留 12 位或 16 位小数。

**第一次计算的结果**（`slurm/hw.sbatch`，用了滑动平均的网络都用平均后的权重）。

每生成一个 token 要从显存读多少（权重按 8 位，Transformer 保存的历史也按 8 位）：

| 模型 | 验证 loss | 8 位权重 | 每路状态 | 单路，文本长 256 / 2048 / 8192 | 16 路同时，256 / 2048 / 8192 |
|---|---|---|---|---|---|
| 脉冲 117M + 三种方法 | 1.278 | 117 MB | 148 KB | 64.5 MB（与长度无关） | 5.3 MB |
| 脉冲 257M + 三种方法 | 1.242 | 257 MB | 221 KB | 140.7 MB | 11.0 MB |

| 脉冲 257M，读两遍 | 1.199 | 257 MB | 221 KB | 141.0 MB | 11.2 MB |
| Transformer 12.4M | 1.357 | 12 MB | 1.0 / 7.9 / 31.5 MB | 11.4 / 18.3 / 41.9 MB | 1.6 / 8.5 / 32.1 MB |
| Transformer 29.9M | 1.245 | 30 MB | 2.1 / 16.8 / 67.1 MB | 29.4 / 44.0 / 94.4 MB | 3.8 / 18.5 / 68.8 MB |
| Transformer 55.1M | 1.190 | 55 MB | 3.3 / 26.2 / 104.9 MB | 55.1 / 78.0 / 156.6 MB | 6.5 / 29.5 / 108.1 MB |

1. **发放情况和此前的估算一致。** 每层每步有 2%–6% 的神经元发放（257M 平均约 3%），所以单路生成时每个 token 只需读全部权重的约 55%。
   16 路同时生成时，"任何一路发放过"的神经元占 34%–44%，比按各路互相独立推算的约 40% 略少。
2. **单路生成时，脉冲网络读得更多。** 读两遍的 257M（1.199）和质量相近的 55.1M Transformer（1.190）相比，

3. **16 路同时生成、文本较长时，脉冲网络读得更少。** 同样这两个模型，脉冲网络每个 token 读 11.2 MB，不随长度变化；
   Transformer 在 256 / 2048 / 8192 个 token 时是 6.5 / 29.5 / 108 MB。文本长 2048 时脉冲网络读的只有它的 38%，8192 时只有 10%。
   这就是README 第 0 节说的"近期可以主张的"场景。但前提是脉冲网络在这么长的文本上质量不掉，而它只用 256 个 token 训练过，这一点还没有验证。
4. **状态**：脉冲网络每路 148–221 KB，固定不变；Transformer 在 2048 个 token 时就要 8–37 MB。

低精度模拟（验证 loss 相对不取整时的变化；256 个 256 token 的验证片段，约 6.5 万个 token）：

1. **8 位权重、8 位总线、24 位膜电位，质量不受影响。** 四个网络合起来的变化都不超过 0.0014，在测量误差范围内。
   也就是说，这些网络不需要重新训练，就能按 FPGA 和数据流加速器常用的整数精度运行。
2. **4 位权重会损失 0.016–0.023**（每 128 个一组缩放；每行一个系数时损失 0.04–0.06），大约是 117M → 257M 收益的一半。
   117M 用 4 位约 59 MB，可以整个放进 AMD V80 的片上存储；要用 4 位，需要在训练时就按 4 位训练来弥补这部分损失，留到以后。
3. **16 位膜电位不行，原因是一部分神经元的膜电位偏得极远。** 校准时，有的层膜电位的绝对值最大达到阈值的约 5 万倍
   （读两遍的 257M 有一层达到约 42 万倍）。按最大值确定范围以后，16 位里几乎没有留给小数的位，舍入误差太大。
   改成按 99.99% 分位数确定范围、超出的部分截断（`V16p`）也不够：读一遍的网络仍损失 0.05–0.09，读两遍的 0.33–1.05。
   原因是分位数本身也很大（多数层在阈值的 100–3000 倍，最大的一层上万倍），也就是说偏得远的神经元不止零星几个。
   要用 16 位，可能需要每个神经元各自一个缩放系数，或者训练时限制膜电位的范围；24 位已经没有损失，
   而且 Loihi 等芯片的膜电位本来就是 24 位，所以这一点优先级不高。

第九批的网络也补算了（`hw_cost.json`、`quant.json`）：
- **每个 token 2 步的 117M**：稠密乘加从 6240 万次增加到 1.21 亿次，但每个 token 要读的显存不变（单路 64.5 MB，16 路 5.2 MB），
  因为每个权重每个 token 仍只读一次（5.20 节开头）。也就是说，在受读取速度限制的 FPGA 上，2 步带来的 0.013 改善几乎不增加读取量，
  多出来的是计算量。3 步时稠密乘加是 1.79 亿次。
- **读两遍、老师过两遍的 257M**（1.184）：单路 140.9 MB、16 路 11.1 MB；8 位权重 + 8 位总线 + 24 位膜电位仍然没有损失（−0.0005）。
- 250M Transformer（1.049）：单路 249 / 304 / 493 MB（文本长 256 / 2048 / 8192），16 路 22.9 / 78.0 / 267 MB。

### 5.21 第九批：每个 token 模拟多步、250M Transformer、更好的老师读两遍

**问题。** 5.19 节留下两种可能来解释"117M → 257M 收益变小"：一是每个 token 只模拟一步，每个神经元对一个 token 最多发一个脉冲，
能传递的信息有限；二是数据集本身，模型越接近 TinyStories 的极限，每翻一倍的收益本来就会变小。

**做法**（`gpu9.sh`）：
- **每个 token 模拟多个时间步**（新选项 `--steps_per_token T`，见 `model.py` 开头的说明）：
  - 每个 token 在网络里停留 T 步，它的输入神经元在这 T 步里每步发放一次，所以每个神经元对一个 token 最多能发 T 个脉冲；
  - 读出神经元在这 T 步里累加、不漏电，读完清零，相当于对 T 步的总线取平均；
  - 时间常数按 token 计的初始值不变；不增加参数，每个 token 的神经元计算量变成 T 倍；T=1 时和原来的代码逐位相同。

  在 117M + 三种方法上试 T=2 和 T=3。
- **250M 的 Transformer 过两遍**（总线 1280，12 层，247.8M），和过两遍的 105M Transformer 比较。
- **目前最好的配置过两遍**：257M、过两遍的老师、学习率 5e-4。

1. **每个 token 2 步有一点帮助，3 步没有。** 2 步使验证 loss 改善 0.013，短上文（k=0）和长上文（k=128）都改善了 0.013–0.019，
   上文收益也略有提高（0.297 → 0.303）；但远距离的净回看没有变好，长故事上 256 以外还略差。3 步反而几乎退回到 1 步的水平。
   所以"每个 token 只能发一个脉冲"确实限制了一点，但不是主要瓶颈。代价是 GPU 上训练慢了约 2.5 倍；
   在 FPGA 上，权重仍然每个 token 只读一次（5.20 节），主要多出来的是前半的稠密计算，第十批会用 `hw_cost.py` 算清楚。
2. **Transformer 在 100M 以上也一样变慢了。** 过两遍时，105M → 250M（参数 2.37 倍）改善 0.042，每翻一倍约 0.034；
   脉冲网络 117M → 257M（2.2 倍）改善 0.039，每翻一倍也约 0.034。两者完全一样。所以 5.15 节第 4 条的"参数加倍收益变小"不是脉冲网络特有的，
   而是这个数据集在这个规模上的共同现象（早先"每翻一倍改善约 0.065"是在 27M–117M 的较小规模上测的）。
   这也意味着：两种网络沿着两条平行的线变好，**单靠扩大规模，"同样质量需要多少倍参数"这个差距不会缩小**，要缩小它只能靠提高每个参数的效率。
3. **更好的老师再次有效。** 257M 读两遍，老师从过一遍换成过两遍（1.139 → 1.091），学生从 1.199 改善到 **1.184**，是目前最好的脉冲网络。
   老师的进步传给学生约三分之一（第八批读一遍时约四分之一）。
4. **和 Transformer 的差距。** 都读两遍时，257M 脉冲网络（1.184）和 105M Transformer（1.091）的差距是 0.093，
   短上文（k=0）差 0.078，上文 128 时差 0.143，比读一遍时（0.089 / 0.163）略小。按读一遍时各个 Transformer 读两遍大约改善 0.045 推算，
   29.9M 和 55.1M 的 Transformer 读两遍约为 1.20 和 1.145，所以这个脉冲网络大约相当于 35M 的 Transformer，参数量是它的 7 倍多。
5. 一个值得注意的现象：读两遍的 257M 在 256 个 token 以外的回看（0.27）比只读一遍的（0.37，5.18 节）差。
   多读一遍 256 个 token 的片段，可能让网络更"习惯"在 256 处结束。如果以后要做长文本，需要用长片段训练（见 5.22 节）。

### 5.22 长文本实验线：PG-19

**为什么做。** 两条理由：一是 5.21 节第 2 条，两种网络在 TinyStories 上都进入了收益变小的区间，更难的数据更能拉开不同结构的差距；
二是README 第 0 节"近期可以主张的"场景（多路并发、长文本）需要证明长文本上的质量，而 TinyStories 的故事平均只有约 200 个 token，做不到。
和 TinyStories 主线并行，分步进行。

- 数据用 **PG-19**：Project Gutenberg 上 1919 年以前出版的书，训练集 28,602 本，每本平均约 40 万字符，
  原论文的分词下约 20 亿 token。它是长距离语言模型的常用测试集，结果可以和文献对照。
- 第一步：下载、为它训练新的分词器、转换成 token（CPU 作业），保留每本书的边界
  （`slurm/pg19_download.sh`、`prepare_pg19.py`；8192 个词的字节级 BPE，在 400 本训练书上训练）。**已完成**：

  | 部分 | 书 | token 数 | 每本书 |
  |---|---|---|---|
  | 训练集 | 28,602 本 | 30.6 亿 | 约 10.7 万 |
  | 验证集 | 50 本 | 457 万 | 约 9.1 万 |
  | 测试集 | 100 本 | 1077 万 | 约 10.8 万 |

  平均每个 token 3.7 个字符。
- 第二步的工具，都在 CPU 上测试过：
  - `train.py --data data/pg19 --tokenizer tok8192.json --vocab 8192` 读 PG-19；
  - Transformer 对照组可以用旋转位置编码（`--rope`），不再受学到的位置向量长度的限制；
  - `eval_long.py` 从每本书的开头读到 8192 个 token，按位置区间（0–64、64–128、……、4096–8192）报告平均 loss。
    脉冲网络分段读、膜电位接着往下传（和一次读完逐位相同）；Transformer 可以用全部上文，或只用最近 W 个 token（滑动窗口）。
    如果 loss 在后面的位置继续下降，说明模型用上了更长的上文。
- 第二步就是第十一批（`gpu11.sh`，已完成）：脉冲网络 125M（117M 的结构，词表变大）两组，一组用 `--carry_state`
  沿书连续读 512 个 token 的片段、膜电位往下传，一组每段从静息开始；Transformer 98M 和 34M 各一组，旋转位置编码、2048 个 token 的片段。
  都读约 10 亿 token（约为训练集的三分之一），暂不用老师。之后用 `eval_long.py` 在测试集的书上读到 8192 个 token，并算硬件代价。

**第十一批的结果。** 训练过程中的验证 loss 是按各自训练片段的长度算的（脉冲网络 512 个 token，Transformer 2048 个），两边不能直接比
（脉冲网络两组平均后的权重为 3.495 / 3.731，Transformer 98M 3.030、34M 3.263）。下面统一用 `eval_long.py` 在测试集上比：
95 本至少 8192 个 token 的书，每本从开头读到第 8192 个 token，按位置区间求平均。脉冲网络用平均后的权重，一路读下去，膜电位一直往下传；
Transformer 用 2048 个 token 的滑动窗口，也就是每个位置最多看前面 2048 个 token。

| 位置 | 脉冲 125M，训练时每段从静息开始 | 脉冲 125M，训练时膜电位跨段传递 | Transformer 98M | Transformer 34M | 脉冲（静息）− TF 98M | 脉冲（静息）− TF 34M |
|---|---|---|---|---|---|---|
| 0–64 | 1.672 | 1.793 | 1.919 | 2.367 | −0.247 | −0.695 |
| 64–128 | 2.447 | 2.658 | 2.117 | 2.411 | 0.330 | 0.036 |
| 128–256 | 2.699 | 2.920 | 2.193 | 2.488 | 0.506 | 0.211 |
| 256–512 | 3.046 | 3.243 | 2.551 | 2.808 | 0.495 | 0.238 |
| 512–1024 | 3.237 | 3.392 | 2.751 | 2.993 | 0.485 | 0.243 |
| 1024–2048 | 3.300 | 3.406 | 2.837 | 3.085 | 0.463 | 0.215 |
| 2048–4096 | 3.335 | 3.444 | 2.883 | 3.126 | 0.452 | 0.209 |
| 4096–8192 | 3.366 | 3.475 | 2.896 | 3.137 | 0.469 | 0.229 |
| 前 8192 个的平均 | **3.301** | 3.418 | **2.841** | 3.086 | 0.460 | 0.215 |

1. **质量差距很大。** 125M 的脉冲网络不如 34M 的 Transformer（平均差 0.215），比 98M 的差 0.46。也就是说，参数量至少差三到四倍。
   在 TinyStories 上，117M 的脉冲网络（不加训练方法）大约相当于 12M 的 Transformer（5.13 节）；换成更难的文本，差距没有缩小。
   这对README 第 0 节的第 1 条目标是一个明确的提醒：只靠把脉冲网络做大，需要的规模会很大，还需要更有效的训练方式或结构。
2. **每个区间的 loss 都是越往后越高，这是文本本身的原因。** 所有模型都这样，Transformer 也一样：书的开头多是书名、目录、说明之类
   比较固定、容易预测的内容，越往后越是正文。所以只有"同一位置上两个模型的差"有意义（表的最后两列）。
3. **差距在 256 个 token 以后基本不变。** 和 34M Transformer 比：64–128 时只差 0.04，到 128–256 拉开到 0.21，之后一直在 0.21–0.24 之间；
   和 98M 比，一直在 0.45–0.51 之间。这说明两件事：
   - 脉冲网络训练时只见过 512 个 token 长的片段，读到第 8192 个 token 也没有变差，膜电位不会因为运行太久而失常；
   - 但在 2048 个 token 以后（这里 Transformer 只能看到最近的 2048 个），差距也没有缩小，所以看不出脉冲网络用上了 2048 个 token 以前的内容。
   差距主要是在前几百个 token 里拉开的：Transformer 从前面几百个 token 里得到的帮助比脉冲网络多。这和 TinyStories 上的观察一致
   （5.19 节：差距有一半随上文变长而拉开）。最前面 0–64 个 token，脉冲网络反而低很多，原因还没有查清，
   可能和书开头的固定格式有关；这一段只占所有位置的不到 1%，不影响上面的结论。
4. **训练时让膜电位跨段传递，反而差了 0.12。** 两组只差这一个选项。"跨段传递"组在所有位置上都更差，只是差距从前面的约 0.2
   缩小到 1024 个 token 以后的约 0.11：跨段传递确实让网络更适应长时间运行后的状态，但整体学得更差。最可能的原因在取样方式上：
   这个选项下，一批的 16 行各自沿一本书往下读，一本书要读约 200 步才换下一本，所以连续约 200 步的训练数据都来自同样的 16 本书，
   不再是从整个训练集里随机抽取的。这种前后相关的数据会让随机梯度下降的效果变差。以后再用这个选项，应该同时维护很多条
   （比如上千条）读书的进度，每一步从中随机抽 16 条，各自的膜电位存起来下次接着用。
5. **Transformer 超出训练长度就会失常，但用滑动窗口就能解决。** 把整本书一次交给 Transformer，2048 个 token 以后 loss 急剧变差
   （98M：3.875、5.113；34M：4.540、5.524），这是旋转位置编码超出训练长度时的常见现象；改用 2048 的滑动窗口就正常了（2.883、2.896）。
   所以在长文本上，公平的 GPU 对照是"带滑动窗口的 Transformer"：它每生成一个 token 最多读 2048 个位置的缓存，代价有上限。
   5.25 节里 8064 个 token 上文的 GPU 测量，代表的是确实需要用到这么长上文的情况；如果脉冲网络本身只用到约 2000 个 token 的上文，
   GPU 一方就应该按 2048 个 token 的上文来比。
6. **硬件代价**（5.20 节的口径，8 位权重）。
   - 脉冲网络 125M：每个 token 6660 万次稠密乘加，加上约 190 万次加法；每路的膜电位 147.5 KB，和上文长短无关；
     每个 token 要读的数据，单路 68.5 MB，16 路同时生成时 5.3 MB。
   - Transformer 34M，上文 2048 个 token 时：每个 token 4610 万次乘加；每路的缓存 16.8 MB；单路读 46.1 MB，16 路 18.6 MB。
     98M 依次是 1.29 亿次、37.7 MB、129.0 MB、43.5 MB。
   - 所以和质量更好的 34M Transformer 比，脉冲网络只有在多路同时生成时读得少（约为它的 3.5 分之一）；单路时读得更多，计算也更多。
   - 低精度：PG-19 比 TinyStories 敏感。8 位权重 + 8 位总线 + 24 位膜电位 + 16 位系数，损失 +0.018（每段从静息开始的那组）和
     +0.004（跨段传递的那组），TinyStories 上只有约 +0.0005；分组的 4 位权重损失 +0.22 和 +0.12，TinyStories 上是 +0.015 到 +0.02。
     文本越难，低精度的代价越大，到 FineWeb 上要重新确认。
7. **决定。** 长文本这条线先停在这里：现在的脉冲网络在一般文本上的质量差距太大，长文本上又看不出它用上了更远的上文，
   所以"长文本上的优势"目前还谈不上。主线放在 FineWeb-Edu 的通用文本上（第十三批），先缩小质量差距；以后回到长文本时，
   先改好跨段传递的取样方式。

### 5.23 第十批：脉冲化总线、257M 每个 token 2 步、250M Transformer 当老师

**问题。**
- 现在每层输入的那一半计算是稠密的：总线是实数，`W_in` 和调节漏电的突触的每个权重每步都要用（5.20 节）。
  把总线也变成脉冲，能省下多少，质量又损失多少？
- 第九批在 117M 上看到的两点改进（每个 token 2 步、更好的老师），在 257M 上还在不在？

**做法**（`gpu10.sh`，都加三种方法、读一遍）：
- **脉冲化总线**（`--spike_bus`，见`docs/running.md`）：每个神经元群之前，总线先经过一组中继 LIF 神经元，每个通道一对，
  一个由 +总线驱动，一个由 −总线驱动，减法复位（没发出去的部分留在膜电位里，下一步继续累积）。
  神经元群读的是它们的脉冲，每个通道每步只能是 −1、0 或 1。读出层仍读实数总线。
  在 117M 上分别用每个 token 1 步和 2 步，和第四批的 117M（1.278）、第九批的 117M 2 步（1.265）比较。
- **257M，每个 token 2 步**（老师过两遍），和第八批"更好的老师"那组（1.229）比较。
- **257M，用 250M Transformer（1.049）当老师**，也和 1.229 比较。

表中数字都用平均后的权重。最后两列是硬件代价（5.20 节的口径）：每个 token 的计算量，以及权重按 8 位时每个 token 要从显存读多少。

| 网络 | 验证 loss | k=0 / k=128 | 上文收益（A） | 净回看 65–128 / 129–256 | 稠密乘加 + 可跳过零的加法 | 读显存：单路 / 16 路 |
|---|---|---|---|---|---|---|
| 117M，1 步（第四批） | 1.278 | 1.798 / 1.319 | 0.297 | 1.47 / 1.10 | 6240 万 + 210 万 | 64.5 / 5.3 MB |
| 117M，1 步，脉冲化总线 | 1.367 | 1.889 / 1.446 | 0.278 | 1.37 / 0.85 | 1050 万 + 3210 万 | 42.6 / 5.2 MB |
| 117M，2 步（第九批） | 1.265 | 1.785 / 1.300 | 0.303 | 1.46 / 1.04 | 1.21 亿 + 310 万 | 64.5 / 5.2 MB |
| 117M，2 步，脉冲化总线 | 1.340 | 1.860 / 1.410 | 0.282 | 1.35 / 0.82 | 1680 万 + 5900 万 | 48.1 / 5.3 MB |
| 257M，1 步，老师过两遍（第八批） | 1.229 | 1.736 / 1.253 | 0.304 | 1.49 / 1.10 | 1.37 亿 + 330 万 | 140.6 / 11.0 MB |
| 257M，2 步 | **1.219** | 1.736 / 1.242 | 0.309 | 1.48 / 1.09 | 2.68 亿 + 480 万 | 140.6 / 10.9 MB |
| 257M，1 步，老师是 250M Transformer | 1.225 | 1.735 / 1.248 | 0.308 | 1.47 / 1.08 | 1.37 亿 + 330 万 | 140.6 / 10.9 MB |

（未平均的验证 loss 依次是 1.380、1.352、1.228、1.234。训练速度：117M 脉冲化总线 1 步每秒 14.8 万 token、2 步 6.3 万（H100 NVL）；
257M 2 步 11.0 万（H200）；257M 换老师 12.2 万（H100 NVL）。）

1. **脉冲化总线损失太大，而且在目标硬件上几乎省不下什么，不再继续。**
   - 质量：1 步时差 0.089，2 步时差 0.075。差距从训练开始就存在，而且一直保持（训练到 5000 步时差 0.07，之后各个检查点都在 0.09 左右），
     说明不是学得慢，而是信息损失：每个通道每步只能传 −1、0、1。短上文（k=0）差 0.09，长上文（k=128）差 0.13，
     远距离净回看从 1.10 降到 0.85，长距离的损失更大。
   - 硬件代价：中继神经元发放得很频繁，第一层约 32%，其余各层约 60%（每步每个通道有六成的概率发出 +1 或 −1）。
     所以单路生成时，每个 token 要读的显存只从 64.5 MB 降到 42.6 MB（少三分之一）；16 路同时生成时，几乎每个通道都至少有一路发放，
     每个 token 仍要读 5.2 MB，和原来一样。稠密乘加从 6240 万次减到 1050 万次，但换来了 3210 万次加法，总计算次数只少了约三分之一。
     在 FPGA 和数据流加速器上，瓶颈主要是读显存，这点节省不值 0.09 的损失。
   - 所以总线保持现在的形式：它是各层脉冲经突触加权后的和（README 的“网络结构”一节），神经元之间仍只传脉冲。这个选项保留在代码里，
     如果以后考虑类脑芯片（README 第 0 节），可以再拿出来。
2. **257M 每个 token 2 步，改善 0.010**（1.229 → 1.219），和 117M 上的 0.013 差不多。和 117M 不同的是，改善主要出现在长上文：
   k=0 没有变化，k=128 改善 0.011；远距离净回看不变。代价是稠密乘加翻倍（1.37 亿 → 2.68 亿次），
   但每个 token 要读的显存不变（单路 140.6 MB、16 路 10.9 MB），在受读取速度限制的硬件上，多出来的主要是计算。
3. **老师从 105M 换成 250M Transformer，学生只改善 0.005**（1.229 → 1.225）。老师改善了 0.042，传给学生的约八分之一；
   之前两次换老师分别传过来约四分之一（第八批）和三分之一（第九批，读两遍）。老师越来越好，学生跟上的比例越来越小，
   说明现在限制学生的主要是它自己的能力，而不是老师。继续换更大的老师意义不大。
4. **小结。** 这一批的三个方向，一个不值得（脉冲化总线），两个各带来 0.005–0.010 的小改善。读一遍时目前最好的 257M 是 1.219（2 步）。
   要缩小和 Transformer 的差距，需要更有效的结构改动。5.19 节显示差距有一半随上文变长而拉开，所以第十二批先试一个针对"保持记忆"的改动（5.24 节）。
5. **低精度。** 两组 257M 的结果和以前一样：8 位权重 + 8 位总线 + 24 位膜电位 + 16 位系数，损失 +0.0005 / +0.0006（2 步 / 换老师）；
   4 位权重（分组）+0.015 / +0.020；16 位膜电位 +0.20 / +0.12，按分位数确定范围（`V16p`）也有 +0.13 / +0.15。
   脉冲化总线的两组没有做低精度模拟（`quant_sim.py` 不支持这个选项；`slurm/hw.sbatch` 现在会自动跳过它们）。

### 5.24 进行中

- **第十一批**（PG-19 上的第一批）：已完成，结果在 5.22 节末尾。
- **第十二批**（`gpu12.sh`，已完成，结果在 5.26 节：两个规模都变差，不再继续）：**输入电流按 (1 − β) 缩放**（新选项 `--leak_gate`，见`docs/running.md`和 `model.py` 开头的说明）：
  `V[t] = β[t]·V[t-1] + (1 − β[t])·I[t]`。
  - 这是 LIF 方程 `τ dV/dt = −V + I` 在一步之内的精确解（I 决定膜电位往哪个值靠拢）。时间常数固定时，它和现在的 `V = β·V + I`
    只差每个神经元一个固定的倍数（可以并进 `W_in`）；但有了调节漏电的突触，β 每步都在变，两者就不一样了。
  - 预期的作用：调节漏电的突触让一个神经元"保持"（β 接近 1）时，它同时也几乎不再接收新的电流，保存的内容不会被后来的输入冲掉；
    让它"快速漏电"时，新的电流完整地进来。一些线性循环网络也把"遗忘"和"写入"这样绑在一起。这针对的是上文越长、差距越大的那一半。
  - 阈值的初始值同时乘以 (1 − β)，所以初始化时和原来的网络完全相同（CPU 上检查过：1 步和 2 步、分段读和一次读完、
    `quant_sim.py` 的逐步计算都一致），只有训练后的行为不同。硬件上每个神经元每步多一次乘法，可以和 β 用同一张查找表，代价可以忽略。
  - 在 117M（和第四批的 1.278 比较）和 257M（和第八批的 1.229 比较）上各一组，之后算硬件代价。

### 5.25 硬件比较的做法：Transformer 在 GPU 上实测，脉冲网络在 FPGA 上估算

**口径**（README 第 0 节第 3 条）：Transformer 用它最擅长的硬件 GPU，用成熟的推理引擎 vLLM 实测；脉冲网络在 FPGA 上按器件参数和实测的发放率估算，
以后有条件再做原型。两边都按"同时服务 B 路、每路逐个生成 token"来比，分别看吞吐量、每个 token 的延迟和每个 token 的能耗。

**Transformer 在 H100 NVL 上的实测**（`bench_gpu.py`，vLLM 0.33，bf16，功耗上限 400 W，空闲约 95 W）。
每个设置连续重复至少 10 秒，读入提示的部分单独测出并扣除；能耗是整块显卡的（括号里是高出空闲功耗的部分）：

1. **少数几路时，GPU 有一个约 1 ms 的下限**：1.2 亿到 4 亿参数的模型，单路每个 token 都要 1.0–1.5 ms，每个 token 耗能 130–240 mJ。
   这时显卡的计算单元大部分闲着，时间主要花在每一步的固定开销上。
2. **几百路、文本短时，GPU 效率很高**：256 路时每个 token 只要 3.4–7.4 mJ，总吞吐每秒 5–7 万 token。
3. **文本变长后，代价明显上升**：每一步都要读所有路的 KV 缓存。SmolLM2-360M 在 8064 个 token 时，256 路总吞吐降到约 5 千，
   每 token 76 mJ；Pythia-410M 在 1920 个 token 时是 38.6 mJ。

**脉冲网络在 FPGA 上的估算**（`fpga_est.py`，读 `hw_cost.json`）。器件按 AMD Alveo V80：HBM 820 GB/s，片上存储 84 MB，
10,848 个 DSP58，热设计功耗最高 190 W。假设：
- 每个 DSP58 每周期做一次 3 元素 INT8 点积，400 MHz，峰值每秒 13 万亿次乘加；脉冲驱动的加法也算在同样的单元上；
- 实际达到峰值带宽和峰值计算的 60%；
- 运行时功耗一律按 190 W 计（GPU 一方用的是实测功耗，所以这一方的估算偏保守）；
- 权重和各路膜电位放得进片上存储的 90% 时留在片上，否则每一步从 HBM 读权重；
- B 路一起生成时，稠密权重每一步读一次，`W_out` 的行只读"任何一路发放过"的神经元；
- 每一步的时间取读数据和计算中较长的一个；膜电位让代价和文本长度无关。

只是为了看数量级，拿 TinyStories 上 257M 的网络（第八批，词表 4096，8 位权重）算一遍。它的质量和上表的模型**不可比**，
真正的比较要等通用文本上质量达标的网络：

| 同时路数 | 吞吐（token/s） | 每 token 延迟 | 每 token 能耗 | 瓶颈 |
|---|---|---|---|---|
| 1 | 3,499 | 0.29 ms | 54 mJ | 读权重 |
| 16 | 44,872 | 0.36 ms | 4.2 mJ | 读权重 |
| 256 | 55,581 | 4.6 ms | 3.4 mJ | 计算 |

从数量级看：少数几路时，FPGA 上的脉冲网络有机会比 GPU 快几倍、省电几倍；几百路、文本短时，两边大致相当；
文本长时，脉冲网络的代价不变，而 GPU 上的 Transformer 越来越贵。这和README 第 0 节第 3 条的要求是对得上的，
但前提是通用文本上质量达标的脉冲网络不要太大。还要注意，GPT-2 的词表有 5 万多个词，读出层本身就有约 5000 万次乘加
（总线 1024 时），对脉冲网络和 Transformer 都是一大块。

### 5.26 第十二批：输入电流按 (1 − β) 缩放

做法见 5.24 节（`--leak_gate`）。其余设置、老师和对照组完全相同，读一遍，都加三种方法（`gpu12.sh`）。数字都用平均后的权重。

| 网络 | 验证 loss | 对照组 | 差 | k=0 / k=128 | 净回看 65–128 / 129–256 |
|---|---|---|---|---|---|
| 117M + 缩放 | 1.292 | 1.278（第四批） | +0.014 | 1.808 / 1.335（对照 1.798 / 1.319） | 1.50 / 1.01（对照 1.47 / 1.10） |
| 257M + 缩放 | 1.287 | 1.229（第八批，老师过两遍） | +0.058 | 1.792 / 1.340（对照 1.736 / 1.253） | 1.52 / 1.02（对照 1.49 / 1.10） |

（未平均的验证 loss 依次是 1.305、1.297。训练速度：117M 在 A100-40 上每秒 6.8 万 token，257M 在 H200 上 11.8 万。）

1. **两个规模都变差，257M 差得更多，没有达到预期。** 原本希望改善远距离的记忆，结果 129–256 一档的净回看反而从约 1.10 降到约 1.01；
   短上文（k=0）和长上文（k=128）也都变差，长上文差得更多。
2. **差距在训练初期就拉开，之后慢慢缩小，但到结束也没有消失。** 117M：第 15000 步时差 0.05，结束时 0.014；
   257M：第 20000 步时差 0.14，结束时 0.06。初始化时两个网络完全相同，所以这是"学得慢"，而不是一开始就差。
3. **可能的原因（没有专门验证）。** 加了缩放以后，调节漏电的突触不只改变神经元忘得多快，还同时改变它接收输入的强弱，而阈值是固定的。
   对时间常数长的神经元，这个影响很大：β 从 0.995 变到 0.9，接收的电流相对阈值就放大了 20 倍。
   于是这些突触的一点变化就会让发放大起大落，训练变得更难；受影响最大的正好是负责长时间记忆的慢神经元。
   另外，缩放也去掉了"β 接近 1 时把输入一直累加起来"（计数）这种用法。
4. **硬件方面有一个好处。** 加了缩放以后，膜电位是过去输入的加权平均，不会越积越大，所以对膜电位的精度不敏感：
   16 位膜电位只损失 +0.014（117M）和 +0.008（257M），不加缩放时是 +0.07 到 +0.20。不过现在每路的膜电位只有一两百 KB，
   24 位已经够用，这个好处暂时不重要。如果以后需要 16 位膜电位（比如为了省片上存储），可以再考虑它，前提是先解决学得慢的问题。
   其余硬件代价和原来的网络基本相同（每个神经元每步多一次乘法）。
5. **决定：不再继续。** 选项保留在代码里（默认关闭）。下一步的重点转到通用文本（第十三批）和训练方式（第十四批的 Muon，以及用 GPT-2 系列当老师）。

### 5.27 第十四批：优化器 Muon

做法见 5.24 节（`--optim muon`）。脉冲网络是 117M + 三种方法（老师和第四批相同），Transformer 是 105M，其余设置和对照组完全相同，
都读一遍（`gpu14.sh`）。脉冲网络的数字用平均后的权重。

| 网络 | 优化器，学习率 | 验证 loss | 对照组（AdamW） | 差 | k=0 / k=128 | 净回看 65–128 / 129–256 |
|---|---|---|---|---|---|---|
| 脉冲 117M | Muon，6e-4 | 1.290 | 1.278 | +0.013 | 1.808 / 1.338（对照 1.798 / 1.319） | 1.42 / 0.87（对照 1.47 / 1.10） |
| 脉冲 117M | Muon，1.2e-3 | 1.300 | 1.278 | +0.023 | 1.813 / 1.349 | 1.42 / 0.86 |
| Transformer 105M | Muon，6e-4 | **1.114** | 1.136（学习率 4e-4，AdamW 最好的一组） | **−0.023** | | 1.56 / 1.18（对照 1.58 / 1.21） |

（未平均的验证 loss：脉冲 1.299、1.321。速度：脉冲在 A100-40 上每秒 7.4 万 token，Transformer 在 H100 NVL 上 11.9 万。）

1. **Muon 让 Transformer 好了 0.023，回看能力不变。** 这和文献里"同样的 loss 需要的 token 更少"一致。
2. **Muon 让脉冲网络变差，损失集中在远距离记忆上。** 学习率 6e-4 时差 0.013，1.2e-3 时差 0.023。
   短上文（k=0）只差 0.01，而 129–256 一档的净回看从 1.10 降到 0.87，是到目前为止降得最多的一次。
   训练曲线上，Muon 一开始更快（第 5000 步时 1.655 对 1.677），到第 15000 步就落后了，之后一直落后。
   也就是说，它让"处理眼前几个词"学得更快，却妨碍了网络学会长距离的存取。
3. **可能的原因（还没有验证）。** Muon 把每次更新矩阵的各个方向拉成一样大。调节漏电的突触决定神经元什么时候保持、什么时候遗忘，
   对它们来说，少数几个方向上的小而准确的调整也许比"各方向一样大"更重要。第十六批检验这一点：
   只让 `W_in`、`W_out` 用 Muon，调节漏电的突触仍用 AdamW；另外再试一个更低的学习率 3e-4。
4. **对比较公平性的影响。** README 第 0 节第 2 条要和"同样数据上训练好的 Transformer"比，所以以后通用文本上的 Transformer 对照组应该用 Muon。
   第十三批的两个 Transformer 用的是 AdamW，按 TinyStories 上的幅度，它们被低估了约 0.02，对比较结论的影响不大，
   但之后新跑的 Transformer 对照组都改用 Muon。脉冲网络暂时继续用 AdamW。

**参考模型在这个验证集上的 loss**（`runs/ref_loss.json`）：GPT-2 124M 3.289，355M 3.011，774M 2.858，1.5B 2.769；

1. **验证 loss：脉冲网络差得很多。** 我们自己的 Transformer 163M 读 25 亿 token 后是 3.310，和 GPT-2 124M（3.289）基本持平，
   说明数据和训练流程本身没有问题。脉冲 212M 是 3.814，比 77M 的 Transformer 还差 0.28，比 163M 的差 0.50；
   而它每个 token 的训练计算量（1.60 亿次乘加）比 163M 的 Transformer（1.33 亿次）还多（`runs/scaling_fineweb.png`）。
   在 TinyStories 上，同样结构的 117M（加三种训练方法）只比 105M 的 Transformer 差约 0.14，通用文本上的差距要大得多。
   随规模的变化：脉冲网络从 138M 到 212M（训练计算量多 1.6 倍）只降了 0.09（3.906 → 3.814），
   Transformer 从 77M 到 163M（多 2.4 倍）降了 0.22（3.535 → 3.310）；在"loss 对训练算力"的图上，两条脉冲网络的曲线也比 Transformer 的平。
   零样本基准上两个脉冲网络几乎一样（五项平均 41.0 和 41.3，LAMBADA 都在 1% 左右）。
2. **零样本基准：除了 LAMBADA，差别都不大。** 五项（HellaSwag、PIQA、ARC-E、ARC-C、WinoGrande）的平均，脉冲网络 41.3，
   GPT-2 124M 42.4，Transformer 163M 43.2；单项的差别大多在 1–2 个百分点，和随机误差同一量级。
   FineWeb-Edu 是教育类文本，我们的三个网络在 ARC-Easy（科学常识题）上都不低于 GPT-2。
   所以离第一条目标（平均 41 左右）的差距主要集中在 LAMBADA 一项上，其次是 HellaSwag（28.1 对 31.1）。
3. **LAMBADA：脉冲网络几乎全错（1%，困惑度约 2.5 万）。** 这个任务给出一段小说，要求预测最后一个词；
   这个词大多在前文里出现过（常常是人物的名字），所以它主要考的是"能不能把几十个 token 之前读到的一个词找回来"。有两个原因：
   - **数据**：FineWeb-Edu 里几乎没有小说，我们的两个 Transformer 也只有 15–20%（GPT-2 是 33%），这一部分和结构无关。
   - **脉冲网络特有的部分**：远距离回看正是它最弱的地方（5.5、5.6 节）。LAMBADA 原论文里，当时的循环网络和 n-gram 模型
     准确率都接近 0，这个任务就是为了区分"能不能利用较远的上文"而设计的；脉冲网络现在的表现和那些模型类似。
   - **会不会是评测出错**：脉冲网络和 Transformer 走的是 `eval_lm.py` 里同一段打分代码，其余五项都正常，所以不太像；
     而 LAMBADA 是六项里唯一按绝对概率打分、并且需要回忆前文的一项。为了确认，新写了 `probe_lambada.py`：
     对每段文字的最后一个词，比较"读完整段"和"只读最后 16 个 token"两种情况下的 loss，并按这个词是否在前文出现过分组，
     同时检查成批计算、单条 float32 计算和逐个 token 计算的结果一致。另外让 `eval_long.py` 也能在 FineWeb-Edu 的文档上
     按位置统计 loss（从文档开头读到 1024 个 token），看差距是集中在前几十个 token 还是越往后越大（`slurm/diag.sbatch`，结果在 5.30 节）。
4. **训练过程中发放率先塌下去、再回升。** 脉冲 212M 的平均发放率在第 500 步约 9%，到第 5000 步降到 2.5%，
   第 2–5 层只有约 1%（4096 个神经元里每个 token 只有约 40 个发放）；之后随着学习率下降慢慢回升，结束时 6.6%。
   训练后半段（第 4 万到 7.6 万步）脉冲网络的验证 loss 只降了 0.11，Transformer 降了 0.22。
   一层里只有 1% 的神经元发放时，这一层每个 token 能往后传的信息很有限。这可能是训练方式上可以改进的地方
   （例如让各层的发放率不低于某个下限），还没有验证。
5. **硬件代价**（`hw_cost.py`、`fpga_est.py`，8 位权重）：脉冲 212M 每个 token 读 112.9 MB（单路）/ 8.4 MB（16 路），
   Transformer 163M 在上文 256 / 2048 / 8192 时是 128 / 161 / 275 MB 和 12 / 46 / 159 MB。
   FPGA 估算（权重放不下片上，从 HBM 读）：单路 0.23 ms、44 mJ 一个 token，16 路 3.2 mJ，256 路 2.75 mJ；
   GPT-2 124M 在 H100 NVL 上用 vLLM 实测：单路约 1.0 ms、129–139 mJ，16 路 11–16 mJ，256 路 3.5–7.6 mJ。
   但README 第 0 节第 3 条要求在质量相当时比较，现在脉冲网络的质量差得多，这组数字还不能当作结论。
   低精度：8 位权重 +0.006、8 位激活 +0.005、24 位膜电位不变；16 位膜电位 +0.094（TinyStories 上约 +0.01），
   4 位权重分组量化 +0.78。和 PG-19 一样，通用文本对低精度更敏感。
6. **下一步。** 先看诊断结果：如果差距主要出在较远的位置和 LAMBADA 这类"找回前文的词"上，就需要一种更强的记忆机制。
   为此已经实现了一个可选的结构改动——**可塑突触**（`--mem_heads`，见`docs/running.md`和 `model.py` 开头的说明）：
   - 每层前面加两小组 LIF 神经元（"键"和"查询"），以及一个固定大小的突触矩阵。某个键神经元发放时，它对应的那一行突触按当前的总线内容加强（赫布式的"同时活动就加强"），并按学到的时间常数慢慢衰减；
     之后查询神经元发放时，把对应的行读出来送回总线。
   - 这样，一个词让某些键神经元发放，后来另一个词让对应的查询神经元发放，就能把当时写进去的内容找回来，不受膜电位漏电的限制。
   - 在硬件上：键和查询都是脉冲，写入和读出都只是加法；突触矩阵和膜电位一样是每路固定大小的状态，不随文本变长而增长，
     所以保留了脉冲网络相对 Transformer 的主要硬件优势。这是对"纯 LIF"的一个偏离（README 第 0 节第 4 条），理由和代价在`docs/running.md`记录。
   - CPU 上检查过：分块并行的训练算法和逐步递推完全一致；整段读、分段带状态读、逐个 token 读三种方式结果一致。

   训练方式上的候选：在通用文本上用 Transformer 163M（或 GPT-2 系列）当老师做蒸馏，以及上面第 4 点的发放率问题。
   计划用较短的训练（约 6.5 亿 token）在 138M 上同时筛选这几项，再把有效的放到完整的 25 亿 token 上。

### 5.29 第十五批：中间层蒸馏

做法见 5.24 节（`--hint_weight`）。117M + 三种方法，老师、学习率和其余设置都和第四批相同，只多了中间层的提示项，读一遍（`gpu15.sh`）。
数字都用平均后的权重。

| 提示的权重 | 验证 loss | 和第四批（1.278）的差 | k=0 / k=128 | 净回看 65–128 / 129–256 |
|---|---|---|---|---|
| 0.1 | 1.269 | −0.008 | 1.785 / 1.309 | 1.45 / 1.01 |
| 1.0 | **1.262** | **−0.015** | 1.785 / 1.298 | 1.40 / 0.97 |
| （第四批，没有提示） | 1.278 | | 1.798 / 1.319 | 1.47 / 1.10 |

（未平均的验证 loss 依次是 1.282、1.274。提示项的误差按老师残差流的大小归一，开始时是 1.0，结束时是 0.33 和 0.21。
提示项本身几乎不增加训练时间：两组在 H100 NVL 和 A100-40 上的速度和这个网络平时在同类显卡上的速度一致。
权重 1.0 的一组在 3 小时处中断过一次，由接力的下一段跑完。）

1. **loss 略有改善。** 权重 1.0 时好了 0.015。在 117M 上试过的训练方式改动里，这是少数有效的（Muon +0.013，输入电流缩放 +0.014）。
   短上文（k=0）和长上文（k=128）都变好了，长上文好得多一点（0.021 对 0.013）。
2. **但远距离的净回看变差了。** 129–256 一档从 1.10 降到 1.01 和 0.97，权重越大降得越多。
   也就是说，学生整体上更接近老师了，但"把很久以前出现过的某个词找回来"这一点没有学到，反而更弱。
   一个可能的解释（没有验证）：学生只能用一个线性映射，从自己的总线去拟合老师的残差流。容易拟合的是变化慢、概括性的那部分内容；
   "此刻要找回前文的哪个词"这类精确的信息，脉冲网络的膜电位本来就存不住，拟合不了。提示项还占用了学生的一部分学习能力。
3. **对后面的意义。** 通用文本上的差距看来主要在回忆前文上（LAMBADA，见 5.28 节，诊断还在跑），中间层蒸馏对这一点没有帮助，
   所以它不作为主攻方向。它的代价很小（蒸馏时老师本来就要算），以后在通用文本上，如果输出分布的蒸馏本身有效，再把它作为附加项一起试。

### 5.30 通用文本上的差距出在哪里：诊断

第十三批的四个网络（脉冲网络用平均后的权重）跑了 5.28 节第 3 点说的两项诊断（`slurm/diag.sbatch`，`runs/lambada_probe.json`、
`runs/g13_*/long_valid*.json`）。

**LAMBADA 的最后一个词**（`probe_lambada.py`，5153 段，平均每段 84 个 token）。81.5% 的段落里，最后一个词在前文出现过。
对每个词比较两种 loss：读完整段时的，和只读最后 16 个 token 时的；两者之差叫"收益"，即读完整段带来的帮助。
"净收益"是出现过的词的收益减去没出现过的词的收益，扣掉"读得多一般会好一点"的部分，剩下的才是"把前文那个词找回来"的效果。

| 网络 | 准确率 | 出现过的词：loss（只读 16 个 token） | 收益 | 没出现过的词：loss（只读 16 个 token） | 收益 | 净收益 |
|---|---|---|---|---|---|---|
| 脉冲 212M | 1.0% | 10.47（11.80） | 1.33 | 8.52（9.38） | 0.86 | **0.47** |
| 脉冲 138M | 1.3% | 10.73（11.91） | 1.18 | 8.77（9.52） | 0.75 | **0.42** |
| Transformer 163M | 19.7% | 5.42（11.14） | 5.72 | 7.45（8.87） | 1.42 | **4.31** |
| Transformer 77M | 14.7% | 6.65（11.53） | 4.88 | 8.08（9.28） | 1.21 | **3.67** |
| GPT-2 124M | 32.1% | 2.99（9.60） | 6.61 | 5.91（7.91） | 2.00 | **4.61** |
| GPT-2 355M | 41.9% | 2.36（9.19） | 6.83 | 4.85（7.34） | 2.50 | **4.33** |

（单位 nat。整段文字的平均 loss：脉冲 212M 4.49，Transformer 163M 4.13，GPT-2 124M 3.65。）

1. **脉冲网络在 LAMBADA 上失败，是因为找不回前文的词。** 目标词在前文出现过时，Transformer 读完整段能把 loss 降 5–6 nat
   （概率提高一两百倍），脉冲网络只降 1.2–1.3 nat。净收益是 0.4–0.5 对 3.7–4.3。
2. **我们的 Transformer 比 GPT-2 低，原因不在回忆。** 它的净收益（4.31）已经接近 GPT-2（4.61），
   差别主要在"只读 16 个 token"时就已经存在（11.14 对 9.60）：小说里的人名和用词对只读过教育类网页的模型来说很陌生，是数据造成的。
3. **评测本身没有问题。** 集群上的核对发现，脉冲网络成批计算（bf16）和单条计算（float32）在个别段落上最多差约 1 nat。
   本地检查：同样精度下成批和单条完全一致（差 2e-6），所以补齐没有问题；差别来自 bf16 的舍入，接近阈值的神经元会因此改变是否发放，之后的计算跟着不同。
   在 TinyStories 的网络上，bf16 和 float32 逐个 token 比较：平均差 −0.004（没有偏向），平均绝对差 0.19，最大 1.4。
   整个验证集上两者的 loss 只差 0.001（`quant_sim.py`），所以结论不受影响，只是单个词的 loss 有这么大的波动。

**FineWeb-Edu 文档中各位置的 loss**（`eval_long.py --length 1024`，验证集里至少 1025 个 token 的 2528 篇文档，每篇从开头读起）：

| 网络 | 0–64 | 64–128 | 128–256 | 256–512 | 512–1024 |
|---|---|---|---|---|---|
| 脉冲 212M | 3.931 | 3.699 | 3.691 | 3.729 | 3.796 |
| 脉冲 138M | 4.024 | 3.796 | 3.787 | 3.824 | 3.887 |
| Transformer 163M | 3.581 | 3.255 | 3.211 | 3.213 | 3.233 |
| Transformer 77M | 3.817 | 3.485 | 3.441 | 3.437 | 3.458 |
| 差（脉冲 212M − Transformer 163M） | 0.35 | 0.44 | 0.48 | 0.52 | 0.56 |

4. **差距随位置变大**：前 64 个 token 差 0.35，512–1024 差 0.56。前 64 个 token 里也已经有 0.35 的差距，
   说明并不全是"远距离"的问题；在几十个 token 之内，Transformer 也能原样找回刚出现过的词（专有名词、术语、数字）。
5. **脉冲网络读到 256 个 token 以后，loss 反而上升**（212M：3.691 → 3.796），Transformer 只升了约 0.02。
   可能有两个原因：长文档后半部分的内容更依赖重复前文出现过的词（Transformer 也略有上升），或者脉冲网络的状态在长时间阅读后变差。
   训练时每个 1024 token 的片段都从静息状态、文档中的任意位置开始，"静息后读了几百个 token"的情况在训练中是见过的，所以第二种原因的可能性较小。
   后来（5.32 节）确认是第一种：只看最近几十到几百个 token 的 Transformer 在同一段也升约 0.13。
6. **结论**：通用文本上的差距，主要是脉冲网络不能把前文的具体内容原样找回来，这和 5.28 节"规模变大收益很小"也对得上：
   多加神经元并不带来这种能力。所以第十七批的重点是可塑突触和蒸馏。

**脉冲网络相当于"能看多远的 Transformer"**（`diag13w`：同样的 2528 篇文档，让 Transformer 只看最近 W 个 token，
窗口每次滑动 W/2，所以每个 token 能看到的上文在 W/2 到 W 个之间）：

| 网络 | 全部上文 | 只看最近 16 个 | 64 个 | 256 个 |
|---|---|---|---|---|
| Transformer 163M | 3.249 | 3.986 | 3.518 | 3.318 |
| Transformer 77M | 3.475 | 4.165 | 3.731 | 3.542 |
| 脉冲 212M（全部上文） | 3.768 | | | |
| 脉冲 138M（全部上文） | 3.862 | | | |

7. **脉冲 212M 的水平，大约相当于只能看最近二三十个 token 的 Transformer 163M**（介于 16 和 64 之间），
   或者能看三四十个 token 的 77M。按位置看更清楚：文档的前 64 个 token 里，脉冲 212M（3.931）和只看 8–16 个 token 的 163M（3.924）几乎一样。
   这只是粗略的对照，因为两种网络处理眼前几个词的能力本身也不同。
8. **能争取的收益主要在几十到两百多个 token 的范围里。** Transformer 163M 从"只看 16 个"到"看全部"，loss 降了 0.74：
   其中 0.47 来自 16 → 64，0.20 来自 64 → 256，只有 0.07 来自 256 个以外。也就是说，脉冲网络缺的主要不是"非常远"的记忆，
   而是对最近几十、几百个 token 里具体内容的准确回忆。可塑突触的衰减时间常数初始化在 8–1024 个 token 之间，正好覆盖这个范围。

### 5.31 第十六批：Muon 为什么对脉冲网络无效

做法见 5.24 节（`experiments/gpu16.sh`）。117M + 三种方法，老师和其余设置都和第四批相同，读一遍。数字都用平均后的权重。

| 优化器设置 | 验证 loss | 和 AdamW（1.278）的差 | k=0 / k=128 | 净回看 65–128 / 129–256 |
|---|---|---|---|---|
| 全部用 Muon，学习率 6e-4（第十四批） | 1.290 | +0.013 | 1.808 / 1.338 | 1.42 / 0.87 |
| Muon，但调节漏电的突触仍用 AdamW，6e-4 | 1.294 | +0.016 | 1.808 / 1.345 | 1.37 / 0.88 |
| 全部用 Muon，学习率 3e-4 | 1.318 | +0.040 | 1.832 / 1.380 | 1.37 / 0.87 |
| AdamW（第四批） | **1.278** | | 1.798 / 1.319 | 1.47 / 1.10 |

（未平均的验证 loss 依次是 1.299、1.305、1.325。两组都在 A100-40 上，每秒约 7.5 万 token。）

1. **5.27 节的猜测不成立。** 让调节漏电的突触继续用 AdamW，结果几乎没有变化（1.294 对 1.290），远距离的净回看同样从 1.10 降到 0.88。
   所以问题不在调节漏电的突触上，而在 `W_in`、`W_out` 本身用 Muon 时。
2. **降低学习率更差**（1.318），短上文和长上文都变差，不是"学习率太大"的问题。
3. **决定：脉冲网络继续用 AdamW，Muon 这条线到此为止。** 原因没有查清。可以确定的是，Muon 会让 `W_in`、`W_out` 的更新在各个方向上
   大小一样，这对脉冲网络学会远距离的存取不利。Transformer 对照组仍用 Muon（5.27 节），让比较对 Transformer 一方公平。


### 5.32 第十七批：可塑突触和蒸馏（通用文本上的短训练筛选）

做法见 5.24 节（`experiments/gpu17.sh`）。都是 138M 的形状，各读 6.55 亿 token（20,000 步），学习率按 20,000 步安排。
脉冲网络的数字用平均后的权重（Transformer 没有平均）。零样本基准的单位是 %，"5 项"是除 LAMBADA 外五项的平均。

| 做法 | 参数 | 验证 loss | 和对照的差 | LAMBADA 准确率 / 困惑度 | 零样本平均 6 项 / 5 项 |
|---|---|---|---|---|---|
| 对照（学习率 6e-4） | 138.5M | 4.195 | | 0.2 / 80,340 | 33.2 / 39.8 |
| 学习率 3e-4 | 138.5M | 4.345 | +0.150 | 0.1 / 93,802 | 32.6 / 39.1 |
| 可塑突触（`--mem_heads 8`） | 157.4M | 4.029 | −0.166 | 3.7 / 10,328 | 33.9 / 39.9 |
| 蒸馏（老师：第十三批的 Transformer 163M） | 138.5M | 4.073 | −0.122 | 0.5 / 49,252 | 33.3 / 39.8 |
| 可塑突触 + 蒸馏 | 157.4M | **3.892** | −0.303 | 4.5 / 6,428 | 34.3 / 40.2 |
| Transformer 163M（Muon） | 163.0M | 3.446 | | 15.7 / 785 | 38.1 / 42.6 |

参照（读 25 亿 token，5.28 节）：脉冲 138M 3.906、212M 3.814，Transformer 163M 3.310。

1. **可塑突触的效果很大，而且越训越大。** 训练中途的验证 loss（平均后的权重），加和不加的差：第 5,000 步 +0.09（加了反而差），
   第 10,000 步 −0.09，第 15,000 步 −0.15，第 20,000 步 −0.17。开始时可塑突触的输出突触是 0，网络要先学会用它；学会以后收益一直在扩大，
   所以训满 25 亿 token 时差距可能更大。
2. **和蒸馏能叠加。** 两者单独是 −0.166 和 −0.122，一起是 −0.303，比两者之和（−0.288）还略多。只读 6.55 亿 token 的"可塑突触 + 蒸馏"（3.892）
   已经好过读 25 亿 token 的旧配方 138M（3.906）。
3. **LAMBADA 动了，但还远远不够。** LAMBADA 要找回前文出现过的词：困惑度从 8 万降到 1 万（加蒸馏 6,400），准确率从 0.2% 升到 4%。
   方向是对的，但离 Transformer（15.7%，困惑度 785）还很远，说明记忆已经在起作用，但还不够好用。其他五项各组基本相同，
   这些任务主要靠常识和短上文，在这个训练量下差别都在误差范围内。
4. **和 Transformer 的差距缩小了四成。** 同样读 6.55 亿 token，对照组比 Transformer 差 0.75，"可塑突触 + 蒸馏"差 0.45。
5. **学习率 3e-4 明显更差**（+0.150）。它的发放率确实没有塌下去（硬件代价里测的平均发放率 11.1%，6e-4 时 6.4%），但 loss 更差。
   所以 5.28 节第 4 点说的"发放率在学习率最高时塌下去"并不是坏事，问题不在学习率太高；下一批反过来试更高的 1.2e-3。
6. **代价**：
   - 参数多 19M（+14%）；每个 token 的稠密乘加从 71.4M 增加到 90.7M（+27%）。
   - 状态从 110.6 KB 增加到 1.33 MB（每层 8 组，每组 64 × 64 个突触，24 位）。它仍是固定大小，比 Transformer 在上文 256 个 token 时的
     4.7 MB 还小（上文 2048 个 token 时是 37.7 MB）。
   - FPGA 上的估算（`fpga_est.py`，8 位权重，和 5.25 节同样的假设）：每个 token 的能耗，16 路并行时从 2.12 mJ 增加到 2.51 mJ，
     单路从 28.5 mJ 增加到 35.5 mJ，延迟从 0.18 ms 增加到 0.21 ms（16 路）。GPT-2 124M 在 H100 上实测 16 路约 11–16 mJ，
     差距仍在 4 倍以上。64 路以上时，每路 1.3 MB 的状态放不下片上存储，要放进 HBM（已计入）。
   - 训练变慢：同一种卡（A100-80）上，不加时每秒 15.9 万 token（学习率 3e-4 那组），加了是 8.5 万，慢了将近一半；显存多约 9.5 GB，
     在 46 GB 的卡上放不下（以后用 `--accum 2` 把每批分成两份算）。训练时的可塑突触是用 PyTorch 分段计算的，以后可以写专门的 GPU 核函数来加速。
   - 第一步加速（2026-11-16）：`model.plastic_scan` 原来逐段循环（每段 128 个 token），现在所有段一起算，只有段与段之间的突触还一段一段往下传。
     结果完全相同（前向逐位一致；梯度只有衰减参数在 float32 求和顺序上差 4e-7），`experiments/bench_scan.py` 在 H100（MIG 3g.47gb，每批 16 条）上：
     可塑突触这一步 5.5 → 2.0 ms，整个训练步 203 → 177 ms（每秒 8.1 万 → 9.3 万 token，快 15%），显存不变；不加可塑突触是 96 ms。
     所以剩下的额外开销主要不在这一步，而在键、查询神经元和几组投影上。
     顺带发现：集群上的 "h100-47" 是一张 H100 NVL 切出来的 MIG 3g.47gb，不是整张卡，所以这类卡上的训练一直只有 h100-96 的一半左右快。
7. 中途的检查：前 2,000 步梯度范数在 0.4–1.35 之间，没有发散（CPU 上用 `mem_eps` 解决过的问题在 GPU 上没有再出现）。

**诊断（diag17：LAMBADA 的回看探针和 FineWeb-Edu 文档里按位置的 loss，做法同 5.30 节）。**

- LAMBADA 的最后一个词在前文出现过时（占 82%），读完整段比只读最后一小段能把这个词的 loss 降低多少，减去没出现过时的同一数字，
  就是"净回看收益"（单位 nat）：

  | 网络 | 出现过：loss（读完整段降低） | 没出现过：读完整段降低 | 净回看收益 |
  |---|---|---|---|
  | 对照 | 11.75（+0.49） | +0.50 | −0.01 |
  | 蒸馏 | 11.22（+0.68） | +0.61 | +0.07 |
  | 可塑突触 | 9.32（+2.76） | +0.74 | +2.02 |
  | 可塑突触 + 蒸馏 | 8.82（+2.95） | +0.88 | +2.08 |
  | Transformer 163M（Muon，同样训练量） | 6.39（+4.94） | +1.20 | +3.74 |
  | GPT-2 124M | 2.99（+6.61） | +2.00 | +4.61 |

  没有可塑突触时，脉冲网络完全不会"找回前文的词"（净收益约为 0，学习率和蒸馏都不改变这一点）；加了以后净收益 +2.0，
  是同样训练量的 Transformer 的一半多。这直接证实了可塑突触在做设计它时想让它做的事。
- FineWeb-Edu 里长度至少 1024 个 token 的文档，按位置分段的平均 loss：

  | 网络 | 0–64 | 64–128 | 128–256 | 256–512 | 512–1024 |
  |---|---|---|---|---|---|
  | 对照 | 4.320 | 4.090 | 4.080 | 4.115 | 4.178 |
  | 可塑突触 | 4.273 | 3.952 | 3.911 | 3.929 | 3.985 |
  | 可塑突触 + 蒸馏 | 4.125 | 3.813 | 3.777 | 3.794 | 3.848 |
  | Transformer 163M（Muon） | 3.731 | 3.396 | 3.345 | 3.346 | 3.369 |
  | 差（可塑突触 + 蒸馏 − Transformer） | 0.39 | 0.42 | 0.43 | 0.45 | 0.48 |

  - 可塑突触的收益集中在后面：前 64 个 token 只有 −0.05，128 个 token 以后是 −0.17 到 −0.19。
  - **剩下的差距在各个位置几乎一样大**（0.39 → 0.48）。5.30 节里旧配方 212M 和 Transformer 的差距随位置从 0.35 涨到 0.56，
    现在随位置增长的那一部分大多已经补上；剩下的主要是前 64 个 token 就已存在的差距，也就是对很近的上文的利用，
    这需要别的办法（可塑突触管的是"找回较早的具体内容"）。
  - 所有脉冲网络的曲线在 256 个 token 以后都重新往上走（可塑突触 + 蒸馏：3.777 → 3.848），比 Transformer（3.345 → 3.369）明显。
    **原因已经查清：这是"能用的上文有限"本身的样子，不是状态读久了变差。** 5.30 节里只让 Transformer 163M 看最近 W 个 token 的结果
    （`runs/g13_tf163/long_valid_w*.json`）有同样的形状。下表是从 128–256 到 512–1024 这一段 loss 升了多少：

    | 网络 | 128–256 | 512–1024 | 上升 |
    |---|---|---|---|
    | Transformer 163M，全部上文 | 3.211 | 3.233 | +0.02 |
    | 同一个 Transformer，只看最近 256 个 | 3.211 | 3.340 | +0.13 |
    | 只看最近 64 个 | 3.431 | 3.560 | +0.13 |
    | 只看最近 16 个 | 3.901 | 4.039 | +0.14 |
    | 脉冲 138M（第十三批，25 亿 token） | 3.787 | 3.887 | +0.10 |
    | 对照（第十七批） | 4.080 | 4.178 | +0.10 |
    | 可塑突触 | 3.911 | 3.985 | +0.07 |
    | 可塑突触 + 蒸馏 | 3.777 | 3.848 | +0.07 |

    长文档的后半部分更多地依赖几百个 token 以前出现过的内容。看得见全部上文的模型可以把它找回来，所以几乎不升；
    看不见的模型（不管窗口是 16 还是 256）都升约 0.13。脉冲网络升 0.10，介于两者之间；加了可塑突触升 0.07，
    大约补上了"全部上文"和"短窗口"之间一半的差别。所以这一段上升正好可以当作"利用远处上文的程度"的一个粗略指标，
    不需要另外的修补（比如在长时间阅读中途重置状态）。

**可塑突触学到了什么**（`experiments/mem_stats.py`，平均后的权重；数字在 `runs/g17_mem138/mem_stats.json` 等）：

- **每层都有一两组变成了极短的记忆。** 初始时间常数是 8、16、32……1024 个 token。训练后，几乎每一层最短的一两组都缩到了
  0.5–2 个 token（只记住最近一两个 token），其余各组分散在十几到几千个 token 之间（可塑突触 + 蒸馏的第 4 层有一组到了 24,385）。
  也就是说，网络自己拿出一部分记忆来做"准确取回刚刚读过的一两个 token"。这和上面"剩下的差距从前 64 个 token 就开始"对得上：
  对很近的上文，网络缺的是准确的存取，而不只是更长的记忆。
- **越深的层用得越多。** 每层可塑突触的输出（W_o 乘读出增益的大小）和这一层神经元自身输出（W_out）之比，第 0–4 层约 0.15–0.2，
  第 9–11 层升到 0.43–0.62。这一组最短的记忆在前几层占的权重也最大。
- 两个网络（加不加蒸馏）的这些特点几乎一样。

**另一个 CPU 上的小试验：读出前把总线归一化**（没有采用）。现在读出神经元直接读总线，logits 的大小（预测有多"确定"）跟着发放的神经元多少变化；
设想是在读出前把每个 token 的总线缩放到均方根为 1（再乘一个可学习的增益），只在不发放脉冲的读出处做一次。在 CPU 上用 TinyStories 的小网络
（总线 128，4 层，2,500 步）对比：验证 loss 2.796 对 2.789（平均后的权重 2.794 对 2.782），没有改善，所以没有拿到 GPU 上，代码也没有留下。

**CPU 上的合成回忆测试和"纠错式写入"。** 等结果的时候，在 CPU 上试了可塑突触的另一种写法，并做了一个小的合成任务来检验
（`experiments/recall_toy.py`）：每条序列先列出若干个"键、值"对，再按随机顺序把键重问一遍，只考察能不能在每个键后面说出它的值。
网络是 2 层、总线 64 的小脉冲网络，2 组可塑突触。

- **纠错式写入**（DeltaNet 里的 delta 规则）：现在的写法是把新值直接加在发放的键神经元那几行上，同一组键下写过的多个词会叠在一起，
  读出来是它们的混合。纠错式写入先读出这几行现在存的内容，只写入新值和它的差，理论上能减少记忆之间的互相干扰。
  实现在提交 c138343（和逐步计算的参考实现、梯度、一次读完和逐个 token 生成都核对过）。
- 结果（准确率，猜对的概率在简单任务里约 3%，困难任务里约 0.8%）：

  | 任务 | 不加可塑突触 | 现在的写法 | 纠错式写入 |
  |---|---|---|---|
  | 简单：16 对，每组 32 个键神经元，第 1,000 步 | 9.0% | 98.9% | 97.4% |
  | 困难：64 对，每组 16 个键神经元，第 3,000 步 | | 42.7% | 12.5%（开始时写入调弱：第 2,200 步 10.7%） |

- 简单任务两种写法都能学会；困难任务里纠错式写入学得慢得多。所以没有拿到 GPU 上试，代码已删掉（留在提交 c138343 里）。
- 困难任务里现在的写法到第 2,600 步左右就停在 43% 上下，说明这时限制它的是记忆的容量（键神经元太少），而不是学不会。
  这也是第十八批试"更多键神经元"和"更多组"的原因。

**决定**：可塑突触 + 蒸馏作为新的配方。第十八批（5.24 节）用它训满 25 亿 token（138M 和 212M 两个规模），同时用短训练试更大的记忆、
更高的学习率、只在一半的层加可塑突触，以及更强的老师（GPT-2 355M）。

### 5.33 第十八批：记忆的大小、学习率、更强的老师

设置见 5.24 节（`gpu18.sh`）。先是四组短训练（138M 的形状，20,000 步、6.55 亿 token，滑动平均后的权重），然后是训满的两组和更强的老师。

| 网络 | 参数 | 验证 loss | 和可塑突触（8 组 × 64）比 | LAMBADA | 六项平均 | 除 LAMBADA 外五项平均 |
|---|---|---|---|---|---|---|
| 对照（不加可塑突触，第十七批） | 138.5M | 4.195 | +0.166 | 0.2 | 33.2 | 39.8 |
| 可塑突触 8 组 × 64 个键神经元（第十七批） | 157.4M | 4.029 | 0 | 3.7 | 33.9 | 39.9 |

1. **每组的键神经元多，有效；组多，反而变差。** 256 个键神经元在训练的每个阶段都比 64 个好（第 2,500 步就低 0.19），
   梯度范数一直平稳（0.6–0.8，没有尖峰）。16 组从一开始就落后（第 2,500 步高 0.28），中途还有一次梯度尖峰（第 6,500 步梯度范数 386，
   loss 从 4.57 跳到 5.13），之后一直比 8 组差约 0.14，到最后几乎和不加可塑突触一样。
   一种解释：读出时，一组里每个键模式是 m 个神经元上的一个稀疏的 0/1 向量，m 越大，不同的键越不容易互相重叠，
   同一组里能分开存的内容越多（这和 CPU 回忆测试里"限制在容量"一致）；组数多只是多了几份小记忆，每份都同样容易互相干扰。
   代价：256 个键神经元时，每层的键和查询神经元有 4,096 个（和这一层的主神经元群 3,072 个差不多），每个 token 的稠密乘加从 90.7M 增加到 120.1M，
   每路状态从 1.33 MB 增加到 4.98 MB。
2. **学习率 1.2e-3 更差**，而且平均发放率掉到约 2%（6e-4 时 4–5%）。加上第十七批 3e-4 也差 0.15，6e-4 仍是这个形状最好的学习率。
3. **只在一半的层加，反而更好**（−0.054），代价也小：每个 token 的稠密乘加 81.0M（每层都加是 90.7M，不加是 71.4M），
   每路状态 719 KB（每层都加是 1.33 MB）。可塑突触在第 2、4、……、12 层前面（第 5.32 节里，越深的层用得越多，最后一层也在其中）。
   每层都加时，也许是各层的记忆互相重复、互相干扰，或者让训练更难；具体原因没有验证。这给下一批留了一个方向：
   只在一部分层加、但每组键神经元更多。
4. 零样本基准在这个训练量下都在随机误差之内（LAMBADA 和验证 loss 的排序一致：256 个键 4.5%，64 个键 3.7%，16 组 2.2%）。
5. 16 组和学习率 1.2e-3 两组都用了 `--accum 2`。为了排除它的影响，CPU 上用同一个随机种子把一个小网络分别按 1 份和 2 份训练 40 步：
   每一步的 loss 都只差千分之一左右（浮点舍入），所以这两组变差不是 `--accum` 造成的。

**训满 25 亿 token：可塑突触 + 蒸馏，138M 和 212M**（`g18_kdmem138` 在 H100-96 上、`g18_kdmem212` 在 H200 上，分段接力；
老师是第十三批的 Transformer 163M）。和第十三批的旧配方读同样的 token、用同样的学习率安排。零样本基准用平均后的权重，单位 %。

|---|---|---|---|---|

   LAMBADA 的准确率从 1% 升到 9% 多，困惑度降低了一个数量级，但仍不如 Transformer 77M。其余五项基本不变（这些任务主要靠常识和短上文）。
2. **138M 的收益一直保持，212M 的收益在后半程缩小了。** 和旧配方在同一步的差（平均后的权重）：

   | 第几步 | 10,000 | 20,000 | 40,000 | 60,000 | 76,300 |

   212M 的梯度范数平时约 0.3，第 6,000 步突然到 117，第 16,500 步到 88，第 49,000–53,000 步之间又反复到 5–9，

**更强的老师：GPT-2 355M**（`g18_kd355mem`，138M + 可塑突触 8 组 × 64，20,000 步；老师在这个验证集上 3.010，Transformer 163M 是 3.310）：

接力重跑那一段时（换了一次算法实现，1d86633）只剩一次 227，之后只有几次小的。这是 64 个键、原来写法的不稳定（5.34 节），不是老师造成的。
**结论**：在这个训练量下，更强的老师帮助很小，代价大，长训练暂时仍用 Transformer 163M 当老师。

**CPU 上的小试验：按位置写入的记忆（没有采用）。** 5.32 节发现，剩下的差距在前 64 个 token 里就已经有 0.39，
可塑突触又按内容写入，没法按"几个词之前"去取，所以试了能不能让网络准确取回最近几个词。

- **先确认这是不是短板**：新写的 `experiments/lag_toy.py`。输入是一串随机词（32 种，等概率），每个位置都要说出正好 k 个词之前的那个词，
  猜对的概率约 3%；Transformer 靠位置编码很容易做到。网络同 `recall_toy.py`（2 层、总线 64、每层 256 个神经元），训练 2,000 步。
- **按位置写入的组（"时钟组"）**：一圈 m 个时钟神经元，第 t 个位置时第 (t mod m) 个发放（一串首尾相连、固定权重的 LIF 神经元就能做到）；
  它代替这一组的键神经元，所以第 t 个词写在第 (t mod m) 行。查询神经元除了读总线，还经过一组可学习的突触接收时钟神经元的脉冲，
  这样网络能学会"读 k 个位置以前写的那一行"。每组状态只有 m × dv 个数（m = 32），写入和读出仍然只有加法。

| 往回 k 个词 | 不加可塑突触 | 2 组按内容写入（现在的写法） | 1 组时钟 + 1 组按内容 |
|---|---|---|---|
| 1 / 2 / 4 | 100 / 99.9 / 96.6% | | |
| 8 | 84.1% | 72.0% | **100%**（第 500 步） |
| 16 | 48.7% | 29.6% | **100%** |
| 32 | 12.6% | 13.9% | **96.0%** |

- 不加可塑突触时，这个小网络能准确记住最近约 4 个词，再往前就快速变差；按内容写入的可塑突触在这里帮不上忙
  （要找的词本身未知，没有内容可以拿来匹配）；时钟组在 32 个词以内几乎全对。
- **但在真实文本上没有收益**：TinyStories 的小网络（总线 128、4 层、每层 512 个神经元，2,500 步，每组 32 个键、值 32 维，平均后的权重）：

  | 设置 | 验证 loss（种子 0 / 种子 1） |
  |---|---|
  | 不加可塑突触 | 2.782 |
  | 4 组按内容写入 | 2.670 / 2.673 |
  | 5 组按内容写入 | 2.677 |
  | 4 组按内容写入 + 1 组时钟 | 2.697 / 2.682 |
  | 4 组里 1 组换成时钟 / 2 组换成时钟 | 2.692 / 2.702 |

  两个种子之间只差约 0.003，加时钟组反而差约 0.02。所以至少在 TinyStories 上，"按位置准确取回最近几个词"不是现在的限制，
  有用的是按内容取回。代码（`--mem_clock`）没有留下，在提交 c0868f9 里；`lag_toy.py` 留着，可以用来检查以后的改动。
  FineWeb-Edu 上近处的差距要靠别的办法。

### 5.34 可塑突触训练中的梯度尖峰

**现象。** 训练日志每 500 步记一次梯度范数（裁剪前）。把第十三批以来所有 GPU 训练里大于 2.5 的记录数出来
（这类网络的梯度范数平时在 0.3–0.8 之间）：

| 训练 | 可塑突触 | 记录数 | 大于 2.5 的次数 | 最大 |
|---|---|---|---|---|
| 第十三到十七批里所有不加可塑突触的（脉冲和 Transformer，共 16 组） | 无 | 每组 39–155 | 0 | |
| `g17_mem138` | 8 组 × 64 | 39 | 3 | 8.2 |
| `g17_kdmem138`、`g18_k256`、`g18_e2` | 8 组 × 64 / 8 组 × 256 / 隔层 | 39–43 | 0 | |
| `g18_lr12`（学习率 1.2e-3） | 8 组 × 64 | 39 | 6 | 9.1 |
| `g18_h16` | 16 组 × 64 | 39 | 7 | 386 |
| `g18_kdmem212`（212M，训满） | 8 组 × 64 | 163 | 13 | 117 |

尖峰只出现在加了可塑突触的网络里；组越多、学习率越高、网络越大，越常见。尖峰的那一步 loss 往往也明显偏高
（212M 第 6,000 步 5.11，前后几步约 4.25），之后要几千步才恢复（5.33 节第 2 点）。梯度裁剪（阈值 1）限制了每一步更新的大小，
但这一步的更新方向几乎完全由出尖峰的那部分参数决定。

**猜测的原因（待验证）。** 可塑突触的读出 r = Sᵀq 在进入总线前被缩放到均方根约为 1，所以前向的输出大小有界；
但反向时，没有发放的查询神经元 j 也能通过替代梯度（fast_sigmoid 的尾巴很长）得到梯度，大小正比于 S 的第 j 行。
一个键神经元如果在很多个 token 上都发放（比如重复的文本、列表、表格），时间常数又很长，它那一行就会累加到约 τ 倍于一个值的大小
（τ 可到几千）。前向的缩放挡不住这个，于是查询神经元的输入突触、进而整个网络收到一个很大的梯度。
CPU 上 TinyStories 的小网络（4 层，每层 4 组，片段只有 128 个 token）里已经能看到这种不均匀：第 3 层一个值的大小（范数的中位数）约 15，
S 各行的中位数约 22，最大的一行约 1,800，是中位数的 80 倍。

**诊断**（`experiments/grad_spikes.py`）：用 212M 训练完的权重（不更新）在 300 个随机训练批次和尖峰那几步的原批次上
（训练时取批次的随机数种子是固定的，可以原样重现）算梯度，按参数和按序列分解。同时 `train.py` 从现在起把超过最近 200 步中位数
5 倍的每一步都记下来（最大的几个参数梯度和这批数据的位置），只记录，不改变训练。

**诊断结果**（`runs/g18_kdmem212/grad_spikes.json`，H200 上约 2 分钟）：

- **整批的尖峰没有重现。** 用训练完的权重，300 个随机批次的梯度范数中位数 0.39，最大 1.44（3.7 倍），没有一批超过 5 倍；
  训练时出尖峰的 7 个批次原样重算，梯度都在 0.36–0.44 之间，loss 也正常。所以尖峰不是某些"坏数据"本身造成的，
  而是训练到那一刻的权重碰上某段文本时才出现。
- **单条序列的尖峰很常见，而且几乎都在可塑突触上。** 把梯度最大的 4 个批次逐条序列拆开：每批的 32 条里，各有一条的梯度是中位数的
  9–25 倍（最大 44.8，中位数约 1.8），其余的大部分来自读出层（head），和平常一样。这几条出尖峰的序列，梯度集中在某一层
  键、查询神经元的输入突触上（第 0、2、11 层的 `mems.*.kq_in`），其次是第 0 层可塑突触的读出增益和第 0 层神经元群的偏置。
  这几段文本看不出特别之处（讲座位安排、地质、澳大利亚历史、地名），重复程度也和别的序列一样。
- **S 里的数确实很大。** 时间常数长的组里，S 最大的一行在 35,000–56,000 之间（第 2、3、4、6、7 层的后几组），
  读出 r 未缩放前的均方根到 2,000–30,000；时间常数短的组和后几层的各组只有 30–500。前向在缩放后看不出这个差别，
  但反向时查询神经元得到的梯度正比于这些行。这和上面的猜测一致：尖峰出在键、查询神经元上，而它们的梯度被巨大的 S 放大了。
  （它对硬件也不利：S 的数值范围越大，存储需要的位数越多。）

**一个修正的候选：按 (1 − λ) 缩放写入**（`--mem_write_avg`）。写入 (1 − λ)·v 而不是 v，S 就是过去写入的加权平均，不再是累加和，
每一行的大小不超过值本身。λ 训练完就固定了，所以推理时这个系数可以直接并进 W_v：网络和硬件完全不变，只是训练时换了一种参数化。

  先在 CPU 上确认它不伤害质量（TinyStories，同 5.33 节的小网络，每层 4 组，2,500 步，平均后的权重）：

  | 写法 | 验证 loss（种子 0 / 种子 1） | S 最大的一行 ÷ 一个值的大小（4 层） |
  |---|---|---|
  | 原来的写法 | 2.670 / 2.673 | 10 / 33 / 131 / 67 |
  | 按 (1 − λ) 缩放 | **2.666 / 2.667** | 8 / 12 / 14 / 21 |

  略好一点（两个种子之间约差 0.003），各行的大小也均匀得多。网络没有把 W_v 放大来抵消这个缩放：值本身从 4–20 变成约 0.5，
  所以读出大多处在 r 小于 1、不做缩放的范围里。这个小网络本来就没有尖峰，所以它只说明这种写法不伤害质量；能不能消除尖峰要在 212M 上看。

  GPU 上的检验是第二十一批（5.24 节）：212M 用同样的随机种子重训一遍，直接对比训练曲线和尖峰的次数。

  **它对"按内容取回"的影响，以及另一个候选。** (1 − λ) 缩放把只写过一次的内容也压小了 τ 倍，而准确取回某个只出现过一次的词，
  正是可塑突触要做的事。所以又试了一种只压"写过很多次的行"的写法：每个键神经元另带一个衰减计数 n_j（和这一组同样的时间常数，
  每发放一次加 1），读出时第 j 行除以 max(1, n_j)（`--mem_count_norm`，类似生物上的突触缩放；硬件上每个键神经元多一个计数器，
  每读一行多一次乘法）。写过一次的行保持原样，写过上千次的行变成平均值。三种写法在 CPU 上比较（合成回忆测试见 5.32 节）：

  | 写法 | TinyStories 验证 loss（种子 0 / 1） | 简单回忆，第 1,000 步 | 困难回忆，第 600 / 1,800 / 3,000 步 |
  |---|---|---|---|
  | 原来的写法 | 2.670 / 2.673 | 98.7% | 7.6 / 37.1 / **43.4%** |
  | 按 (1 − λ) 缩放（`--mem_write_avg`） | **2.666 / 2.667** | 95.0% | 1.9 / 12.3 / 24.6% |
  | 按写入次数归一化（`--mem_count_norm`） | 2.670 / 2.679 | **99.7%** | 7.3 / 29.6 / 36.0% |

  - 按 (1 − λ) 缩放，回忆明显学得慢（困难任务到第 3,000 步只有 24.6%），和上面的担心一致；但 TinyStories 上反而略好。
  - 按次数归一化，简单回忆最好，困难回忆和 TinyStories 稍差。
  - 小任务上两者都不是全面更好。它们都能把查询神经元的梯度限制在一个值的大小以内，真正要回答的是 212M 上尖峰会不会消失、质量和 LAMBADA
    会怎样。第二十一批先试按 (1 − λ) 缩放；如果它让 LAMBADA 明显变差，再试按次数归一化。按次数归一化的代码（`--mem_count_norm`，
    和逐步计算的参考实现核对过，误差 5e-7）留在下面的提交里，暂时从代码中删掉。

3. **省硬件的折中**：只在第 4、8、12 层加 256 个键（3.980）比每层都加 64 个键（4.029）好，状态一样大（1.33 MB），乘加还少 8%。
4. **256 个键神经元和蒸馏能叠加**：一起是 3.795，比"蒸馏 + 64 个键"好 0.098（不加蒸馏时 256 个键好 0.082）。LAMBADA 6.0%。
5. **每组 512 个键不再有用**：8 组 × 512（3.945）和 8 组 × 256（3.947）一样，参数多 38M、乘加多 33%、状态翻倍。
   键神经元从 64 到 256 好 0.08，从 256 到 512 不再变化，所以每组 256 个就够了（至少在读 6.55 亿 token、138M 这个规模上）。
6. **最短的时间常数从 1 个 token 起，好 0.018**（3.930）。第十七批里，几乎每层最短的一两组在训练中都缩到了 0.5–2 个 token，
   这次直接从 1 开始（各组仍按对数均匀分布到 1,024），网络和硬件不变，只是初始值不同。差距不大，但不花任何代价，可以并进配方。
7. **时间常数从 1 起和蒸馏能叠加**（第二十三批）：蒸馏 + 256 个键时 3.795 → 3.772（−0.023，不蒸馏时 −0.018），LAMBADA 6.0% → 7.2%。
   这是读 6.55 亿 token 的 138M 里最好的结果。
8. **加蒸馏后，只在三层加可塑突触差得更多**：3.841，比每层都加（3.772）差 0.069（不蒸馏时差 0.033）。它的状态只有约四分之一、乘加少 30%，
   和"每层 64 个键、按 (1 − λ) 缩放写入"（3.816，同样 1.33 MB 状态）相比，也差 0.025。所以要省状态，每层少放键比只在少数层放更好。
9. 还在跑：GPT-2 355M 当老师（第十八批）。

**给长训练的选择**（138M、6.55 亿 token、蒸馏）：每组 256 个键 + 时间常数从 1 起是质量最好的（3.772），代价是乘加 120M、状态 5 MB；
每组 64 个键 + 按 (1 − λ) 缩放写入是省硬件的（3.816，乘加 91M、状态 1.3 MB）。两者差约 0.04。长训练的目标是质量（目标 1、2），用前者；
硬件比较时，后者作为省状态的版本一并报告。

**一个顺带的发现：不加蒸馏时，梯度范数在训练后半段一直在涨。** 每 500 步记的梯度范数（裁剪前）：

| 训练 | 前 1/4 | 一半 | 最后 |
|---|---|---|---|
| 脉冲 138M，不加可塑突触、不蒸馏，训满 76,300 步（`g13_snn138`） | 0.6 | 0.9 | 1.9–2.2 |
| Transformer 163M，训满（`g13_tf163`） | 0.6 | 0.7 | 1.0 |
| 8 组 × 256，不蒸馏，20,000 步（`g18_k256`、`g19_tau1`、`g19_k512`） | 0.65 | 0.8 | 1.35–1.4 |
| 蒸馏 + 可塑突触，20,000 步（`g17_kdmem138`、`g19_kdk256`、`g21_kdwa138`） | 0.3–0.6 | 0.3–0.4 | 0.4 |
| 蒸馏 + 可塑突触，训满（`g18_kdmem138`） | 0.3 | 0.3 | 0.4 |

梯度裁剪的阈值是 1，所以不蒸馏的脉冲网络在后 30–40% 的训练里每一步都被裁剪，最后实际的更新只有学习率表规定的一半左右。
蒸馏的训练没有这个问题（老师给的软目标让梯度小而稳定），而现在的配方都带蒸馏，所以它暂时不影响主线。
文献里对这种"训练后期梯度变大"有一个解释（Defazio，2025，arXiv 2506.02285）：对后面接归一化的权重，梯度和权重垂直，
权重的大小由权重衰减和学习率共同决定一个平衡点；学习率按表下降时，这个平衡点上"梯度与权重之比"随之变大，于是梯度范数上涨。
文中的修正（AdamC）是让这些权重的衰减和学习率按同一比例下降，在 FineWeb-Edu 上训练的 120M 模型里基本消除了这种上涨，loss 也更低。
我们的网络里哪些权重后面接了归一化、是否同样适用，还没有核对。如果长训练要去掉蒸馏或换成更弱的蒸馏，再回来试。

### 5.36 词的输入和读出：换一种脉冲编码，让词表不再撑大网络（进行中）

**问题。** 词表有 50,304 个词，网络两头各有一块和它一样大的突触：输入端每个词一个输入神经元（一行突触，即词向量），
输出端每个词一个读出神经元。两块合起来占参数的 42–56%（138M 的旧配方里，去掉词表只剩 61M）。两者的代价不一样：
- 输入端每个词只用一行，几乎不花计算，只占存储；
- 读出端每个词都要把 5 万个读出神经元全算一遍，占每个词稠密乘加的 30–54%，单路生成时也占读权重字节的约四成；
  读出神经元不发脉冲，这部分脉冲的稀疏帮不上忙，对脉冲网络和 Transformer 一样贵。

**先试过的：输入、输出共用同一个矩阵**（像 GPT-2 那样，读出 = g × 词向量矩阵）。CPU 上（TinyStories，4 层、总线 256、
每层 1,024 个神经元、4 组 × 32 个键的可塑突触，1,500 步，平均后的权重）明显变差：

| 读出 | 验证 loss |
|---|---|
| 不共用（基准，种子 0 / 1） | 2.714 / 2.699 |
| 共用，g 可学习 | 3.657（梯度范数 10–160：g 的梯度极大，梯度裁剪把其余参数的更新都压小了） |
| 共用，g 固定 | 3.139 |
| 共用，读出前再加一个 d × d 的线性变换，g 固定 | 2.974 |

共用以后，读出的是总线上的电流，而总线里本来就有这个词自己的词向量，读出端天然偏向"下一个词还是这个词"；加线性变换也只挽回一部分。
没有保留这部分代码。

**新的做法：换编码方式**（`model.py` 的 `in_groups`、`out_classes`，`experiments/word_classes.py`）：
- **两级读出**（`--out_classes C`）：把词分成 C 类，每类最多 m 个词。先由 C 个"类读出神经元"给出下一个词在哪一类的概率，
  选定一类后只用这一类的 m 个"词读出神经元"给出类内的概率。P(词) = P(类) × P(词 | 类) 仍是全词表上的完整分布，训练、蒸馏、评测都照常；
  生成时每个词只算 C + m 个读出神经元（50,304 个词分 225 类时是 449 个，约少 100 倍）。存储不变。
- **组合输入**（`--in_groups 2`）：两群各 n 个输入神经元（50,304 个词时 n = 225），每个词让每群里各一个神经元发放，注入两行突触之和。
  输入突触从 50,304 行降到 450 行。默认按词的编号的两位"数字"分配；`--in_class_file` 按聚类分配：第一群表示"这个词在哪一类"，
  第二群表示"它在类里的第几个"。
- 分类（`word_classes.py`）：按词频，或者用训练好的网络的读出行（或输入行）做均衡的 k-means（每类一样多），让同一类的词彼此相似。

CPU 上的比较（同上的网络和训练）：

| 输入 / 读出 | 验证 loss | 和基准的差 |
|---|---|---|
| 每个词一个输入神经元 / 全词表读出（基准，种子 0 / 1） | 2.714 / 2.699 | |
| 两级读出，按编号分类 | 2.846 | +0.13 |
| 两级读出，按词频分类 | 2.826 | +0.11 |
| 两级读出，按训练好的读出行聚类 | **2.743** | +0.03 |
| 组合输入（2 个脉冲），按编号的两位数字 | 2.818 | +0.10 |
| 组合输入（3 个脉冲），按编号的三位数字 | 2.884 | +0.17 |
| 组合输入（2 个脉冲），按训练好的输入行聚类 | **2.745** | +0.03 |
| 两者都用（编号的数字 / 聚类读出） | 2.842 | +0.13 |
| 两者都用（都按聚类） | 2.763 | +0.05 |

- **怎么分类最要紧**：按编号或词频分类要差 0.1 以上，按训练好的网络聚类只差约 0.03（两个种子之间约差 0.015）。
  聚类后同一类里是用法相近的词（比如人名和形容词在一类，词的碎片在一类），共享一部分输入电流、先猜"哪一类"都比较自然。
- 两者一起用，代价大致相加（+0.05）。
- 这个小网络的词表只有 4,096 个词，两块词表只占参数的约 40%；FineWeb 的 5 万词表上，读出节省的比例大得多，代价是否同样小要在 GPU 上看。

**硬件上的效果**（`hw_cost.py` 已按新的读出计算：类读出神经元各路共用，词读出神经元每路只读自己选中那一类的）：以 138M + 可塑突触 + 蒸馏
（`g21_kdwa138`，每个 token 稠密乘加 90.7M、单路读权重 92 MB）为例，两级读出把读出部分从 38.6M 降到约 0.34M，
稠密乘加和单路读权重都约少四成；组合输入再省约 3,860 万个权重的存储，4 位权重从约 79 MB 降到约 59 MB，可以整体放进 FPGA 的片上存储
（`fpga_est.py` 按约 75 MB 可用计），单路生成不必再读片外显存。两级读出 Transformer 也可以用，所以硬件比较里要说明这部分节省不是脉冲带来的。

**GPU 上的检验（第二十五批）**：138M + 蒸馏 + 每层 64 个键 + 按 (1 − λ) 缩放写入，20,000 步，和 `g21_kdwa138` 读同样的批次。
分类都用老师 Transformer 163M 的读出行（或输入行）做均衡 k-means，225 类。平均后的权重：

| 输入 / 读出 | 参数 | 验证 loss | 和基准的差 | 稠密乘加 | 4 位权重 | LAMBADA | 六项 / 五项平均 |
|---|---|---|---|---|---|---|---|
| 每个词一个输入神经元 / 全词表读出（`g21_kdwa138`） | 157.4M | 3.816 | | 90.7M | 78.7 MB | 4.9 | 34.4 / 40.3 |
| 两级读出（`g25_cls`） | 157.6M | 3.887 | +0.071 | 52.4M | 78.8 MB | 4.5 | 33.4 / 39.2 |
| 组合输入（`g25_inc`） | 119.1M | 3.839 | +0.024 | 90.7M | 59.5 MB | 4.3 | 34.0 / 40.0 |
| 两者都用（`g25_io`） | 119.3M | 3.906 | +0.091 | 52.4M | 59.7 MB | 4.2 | 33.8 / 39.7 |
| 两级读出 + 短名单 2,048 个词（`g27_cls2k`，第二十七批） | 157.6M | 3.874 | +0.058 | 53.9M | 78.8 MB | 4.2 | 33.5 / 39.4 |

- **组合输入的代价小**：+0.024，零样本基本不变，参数少 24%，4 位权重 59.5 MB，可以整体放进 FPGA 的片上存储。
  未平均的权重和基准的差在第 7,500 步最大（+0.035），之后缩小到 +0.024。
- **两级读出的代价比 CPU 上大**：+0.071（CPU 上 +0.03），而且从第 5,000 步起一直在 +0.07 到 +0.09 之间，缩小得很慢。
  它让每个 token 的稠密乘加少了 42%（90.7M → 52.4M）。训练时每秒的 token 数少约 23%（要算全词表的概率）。
- **两者一起用，代价大致相加**：+0.091（两者分开是 +0.071 和 +0.024）。

**两级读出为什么差：所有的词都要经过"先猜类、再猜类里的词"。** 一类的真实概率是类里所有词的概率之和，
而两级读出里它是总线的一个线性读出，表达不了这种"求和"；最常见的词（"the"、逗号、句号……）也要经过这一步，
而它们占了大部分 token。

**改进：常见的词不分类（"短名单"，即 adaptive softmax 的做法）。**
- `--out_short S`：训练数据里最常见的 S 个词各有自己的读出神经元，和 C 个类读出神经元一起做一次 softmax；只有其余的词分类。
  生成时每个 token 算 S + C + m 个读出神经元，S = 2,048 时约 2,500 个，仍只有全词表的 5%。
- `--in_short S`：对组合输入做同样的事，S 个常见的词各有自己的输入神经元（一行突触），其余的词用"类 + 类里的序号"两个脉冲。
  S = 2,048 时输入突触约 2,500 行，仍只有原来的 5%。

CPU 上（同上的网络和训练，64 类，短名单 256 个词，覆盖训练数据中 77% 的 token；分类用训练好的 TinyStories 网络 `runs/main` 的行）：

| | 无短名单 | 短名单 256 个词 |
|---|---|---|
| 两级读出 | 2.750 | **2.717** |
| 组合输入 | 2.745 | **2.717** |
| 两者都用 | 2.763 | **2.720** |

基准（每个词一个输入神经元、全词表读出）是 2.714 / 2.699（两个种子）。有了短名单，两种编码各自只差约 0.01，两者一起也只差约 0.015，
都在两个种子之间的差别（0.015）附近。

**分类要来自训练好的网络。** 起初用只训了 1,500 步的小网络的行来分类，结果差得多：两级读出 2.859，组合输入 2.828。
同样的做法改用训练好的网络，就是上表的 2.750 和 2.745。短名单能补回大部分（读出：短名单 256 个词 2.708，1,024 个词 2.692；
输入：短名单 256 个词 2.788），也就是说，有了短名单，读出端对分类不再那么敏感。GPU 上的分类来自训练好的老师 Transformer 163M。
GPU 上的检验：第二十七批（`gpu27.sh`）。

**第二十七批的中途结果**（138M，设置同第二十五批，只加短名单；平均后的权重，每次评估 40 批，所以和上表最后的完整验证集略有不同）：

| 输入 / 读出 | 2,500 步 | 5,000 | 7,500 | 10,000 | 15,000 | 20,000 |
|---|---|---|---|---|---|---|
| 每个词一个输入神经元 / 全词表读出（`g21_kdwa138`） | 4.431 | 4.120 | 3.995 | 3.922 | 3.837 | 3.805 |
| 两级读出，无短名单（`g25_cls`） | 4.504 | 4.211 | 4.084 | 4.006 | 3.916 | 3.877 |
| 两级读出，短名单 2,048 个词（`g27_cls2k`） | 4.479 | 4.187 | 4.066 | 3.992 | 3.903 | 3.863 |
| 两级读出，短名单 8,192 个词（`g27_cls8k`） | 4.456 | 4.160 | 4.037 | 3.964 | | |
| 两者都用，无短名单（`g25_io`） | 4.502 | 4.221 | 4.100 | 4.025 | 3.936 | 3.897 |
| 两者都用，短名单各 2,048 个词（`g27_io2k`） | 4.448 | 4.180 | 4.065 | 3.996 | | |

- **读出的短名单要大一些**：2,048 个词只补回约五分之一（第 10,000 步和第 20,000 步都只好 0.014）；
  8,192 个词在第 10,000 步好 0.042，和全词表读出的差从 0.084 减半到 0.042，而且从第 2,500 步起每次评估都比 2,048 个词好 0.023–0.029。
- **输入的短名单 2,048 个词就够了**：`g27_io2k` 和只改读出的 `g27_cls2k` 只差 0.004（没有短名单时组合输入要多 0.019）。
- 对硬件网络的意义：短名单和类的读出神经元放在片上（每一步都要算），8 位时短名单 8,192 个词共 6.5 MB，2,048 个词 1.7 MB；
  片上的权重从 43.3 MB 变成 48.1 MB，加 16 路的状态 69.3 MB，仍然放得下。所以第二十九批的硬件网络用读出 8,192 个词、输入 2,048 个词的短名单
  （这个组合本身没有单独训过，但输入端和读出端的短名单作用在网络的两头，上表里看起来可以相加）。
- `g27_cls2k` 训完：完整验证集 3.874，比没有短名单的 `g25_cls`（3.887）好 0.013，零样本基本不变（六项 / 五项平均 33.5 / 39.4，`g25_cls` 33.4 / 39.2）。
- `g27_cls8k` 和 `g27_io2k` 在第 10,000 步时排在第二十八批后面等卡，停了约 2.5 小时，预计 11 月 18 日凌晨训完。

### 5.37 第二十六批：长训练（98 亿 token）

**目的**：阶段目标 1（追上 GPT-2 124M、Pythia-160M 这一档）和目标 2（质量随训练量提高）。到这里为止，通用文本上最长的训练是 25 亿 token
（76,300 步）；GPT-2 124M 在 FineWeb 上的复现一般读 100 亿 token。这一批读 300,000 步 × 32 × 1024 = 98 亿 token，约等于把训练集读一遍。

| 训练 | 网络 | 卡 | 预计训练时间 |
|---|---|---|---|
| `g26_snn212` | 脉冲，212M 的形状，每层前面 8 组 × 256 个键神经元的可塑突触，最短时间常数从 1 起，原来的写法；蒸馏；274.8M 参数 | H200 | 约 35 小时（约 79k token/s） |
| `g26_tf163` | Transformer 163M（GPT-2 small 的形状，即老师 `g13_tf163` 的形状），同样的数据和学习率表，不蒸馏 | H100-96 | 约 11 小时（约 250k token/s） |

**为什么是这个配方**：
- 每组 256 个键 + 时间常数从 1 起 + 蒸馏，是 138M 短训练里最好的组合（3.772，5.35 节第 7 点）。
- 212M 在每组 256 个键时训练稳定，按 (1 − λ) 缩放写入也不再有帮助（5.34 节，第二十三批：3.703 对 3.707），所以用原来的写法。
- 学习率表用 `--schedule wsd`：学习率保持不变，最后 20%（60,000 步）按 1 − √进度 降到 0。第二十四批在 138M 上核对过：比余弦加平均权重差约 0.016，
  但学习率保持不变的这段可以随时分出"降学习率"的分支（`gpu26_branch.sh`）。分支的起点和终点如下：

  | 起点（另存的检查点） | 终点 | 读过的 token |
  |---|---|---|
  | 30,000 步 | 37,500 步 | 12 亿 |
  | 60,000 步 | 75,000 步 | 25 亿 |
  | 120,000 步 | 150,000 步 | 49 亿 |
  | 180,000 步 | 225,000 步 | 74 亿 |

  每个分支同样用最后 20% 降学习率。加上主训练本身的终点（300,000 步，98 亿 token），一次训练给出 5 个训练完的点，多花约三成算力。
  其中 75,000 步的分支正好和第十三到二十一批的长度（76,300 步）可比。第 240,000 步（开始降学习率的地方）的检查点也留着，以后可以接着训得更长。
- 学习率在高处停留得久，梯度尖峰更多（第二十四批：37 次，最大 296），所以加 `--spike_skip 10`：
  梯度范数超过最近中位数 10 倍的那一步不更新（第二十三批的 212M 在 20,000 步里有 4 次这样的步，最大 45 倍）。

**老师的问题**：
- 现在的老师 `g13_tf163` 读了 25 亿 token，验证 loss 3.310。蒸馏的目标九成是老师给的分布，学生越接近老师，老师自己的错误就越成为学生的上限。
- 按 212M 从 6.55 亿到 25 亿 token 的进步粗略外推，`g26_snn212` 读完 98 亿 token 大约在 3.4 附近，已经离 3.31 不远。
- 文献里（Busbridge 等，2025，arXiv 2502.08606）也是这样的结论：已有老师时，蒸馏比直接训练好，但只到一定的训练量为止，这个量随学生的大小增长。
- 所以同时训的 `g26_tf163` 有两个用处：
  - 在同样的数据上和脉冲网络比较；
  - 当一个更强的老师。
- 它训完以后（约 11 小时），`g26_snn212` 从下一个另存的检查点（预计第 120,000 步）起换它当老师：停掉接力，用同样的命令、改 `--teacher runs/g26_tf163/ckpt.pt` 重新提交。检查点里不带老师。
- 因此 37,500 和 75,000 步的两个分支用的是原来的老师。第 120,000 步的检查点分出两个分支，除老师外完全相同：
  `g26_snn212_b150000` 用原来的老师（和前两个分支同一条"质量随训练量"的曲线），`g26_snn212_b150000_t26` 用新老师
  （`SUFFIX=_t26 bash experiments/gpu26_branch.sh snn212 120000 runs/g26_tf163/ckpt.pt`），两者的差直接就是"老师强 0.15"对学生的作用。
  主训练从第 120,000 步起换新老师，所以 225,000 步的分支和主训练的终点都用新老师，画图时要注明。

**硬件**：这个网络 274.8M 参数，4 位权重约 137 MB；即使换成组合输入（5.36 节）也约 112 MB，放不进 FPGA 的片上存储（约 75 MB）。

### 5.38 按 4 位权重训练

**问题**：给 FPGA 比较用的网络（138M + 每层 64 个键 + 组合输入和两级读出，各带 2,048 个词的短名单，约 1.21 亿个权重）只有用 4 位权重才能
整个放进片上存储（约 60 MB；AMD V80 片上约 84 MB，留一成余量和膜电位）。但训练完再把权重取整到 4 位，代价随数据变大：
TinyStories 上 +0.016–0.023（5.20 节），FineWeb 上 +0.78（5.28 节，`g13_snn212`）。所以要在训练时就让网络适应 4 位权重。

**做法**（`train.py --wbits 4 [--wgroup 128 --wbits_from s]`，`docs/running.md`）：
- 每一步在前向和反向计算之前，把所有权重矩阵取整为 4 位对称整数（−7 到 7），每 128 个输入共用一个缩放系数，
  系数取这一组里绝对值最大的权重（和 `quant_sim.py` 的 `W4g128` 相同）；
- 梯度按取整后的网络计算，更新加在全精度的权重上（"直通估计"：取整这一步的导数当作 1）。
  这样，单步的小更新虽然改不动取整后的值，却会在全精度的权重里累积，累积够了，取整后的值就会跳到相邻的整数；
- 检查点里存全精度权重；载入时（`sample.load`）自动取整，所以之后的评估、零样本基准、硬件代价都是 4 位的网络。
- 神经元自身的参数（β、θ、γ、偏置）不取整：它们每个神经元一个，存储可以忽略，硬件里按 16 位以上存。

**CPU 上的比较**（TinyStories，5.2M 参数：4 层 × 1024 个神经元，每层 4 组 × 32 个键，1,500 步；平均权重；
640 个 128 token 的验证片段，各设置用同样的片段，所以差值是配对的，误差约 0.002）：

| 做法 | 验证 loss（4 位权重） | 和全精度训练的差 |
|---|---|---|
| 全精度训练（对照） | 2.693 | — |
| 训练完再取整，每 128 个一组 | 2.727 | +0.034 |
| 训练完再取整，每 64 个一组 | 2.721 | +0.028 |
| 训练完再取整，系数按最小均方误差截断（每组在绝对值最大值的 50%–100% 里选） | 2.731 | +0.038 |
| 从头就按 4 位训练 | 2.726 | +0.033 |
| 前 1/3 全精度，后 2/3 按 4 位训练 | 2.711 | +0.018 |
| 前 2/3 全精度，后 1/3 按 4 位训练 | 2.710 | +0.017 |
| 前 5/6 全精度，后 1/6 按 4 位训练 | 2.711 | +0.018 |
| 前 2/3 全精度，后 1/3 按 4 位训练，每 64 个一组 | **2.707** | **+0.014** |
| （8 位，训练完再取整） | 2.694 | +0.000 |

1. **先全精度、最后一段按 4 位训练，代价减半**（+0.034 → +0.017）。从哪里开始影响不大（后 1/6 到后 2/3 都一样）。
2. **从头就按 4 位训练没有用。** 训练前期权重变化大、取整的误差相对也大，网络学得慢，最后和训练完再取整差不多。文献里也常把这一段放在训练的最后。
3. **截断最大的权重反而更差。** 对一般的网络，把每组的缩放系数取得比最大值小一些、让少数大权重饱和，可以降低整体的取整误差；
   这里反而多损失 0.004。脉冲网络里，一个大权重往往决定某个神经元会不会发放，把它截小的代价比让其余权重粗一点更大。
4. **每 64 个一组再好一点**（+0.014），存储多 0.125 位 / 权重（16 位系数）。
5. **哪类权重最敏感**（全精度训练的网络，只把某一类取整到 4 位）：

   | 输入行 | 读出 | W_in | W_out | 调节漏电的突触 | 可塑突触（键和查询 / 值 / 输出） |
   |---|---|---|---|---|---|
   | +0.010 | +0.011 | +0.007 | +0.002 | −0.001 | +0.003 / +0.002 / +0.002 |

   这个小网络里输入行和读出各占约 20% 的参数，GPU 上的网络里它们的比例不同（组合输入只有 190 万个权重，读出约 3,900 万），
   所以只能当参考。片上存储还剩约 15 MB，大约可以让 3,000 万个权重改用 8 位。
6. **混合精度**（`--wbits8`：名字匹配的矩阵用 8 位，其余 4 位；都是后 1/3 按取整后的网络训练）：

   | 留在 8 位的 | 权重的存储（含系数） | 验证 loss | 和全精度训练的差 |
   |---|---|---|---|
   | 没有（全部 4 位） | 2.58 MB | 2.710 | +0.017 |
   | 输入行、读出 | — | 2.700 | +0.007 |
   | 输入行、读出、W_in | 4.27 MB | **2.698** | **+0.005** |

   最后一段按取整后的网络训练 + 最敏感的几类留在 8 位，4 位的代价几乎消失。GPU 上的网络里读出的词读出神经元有 3,700 万个权重，
   全部留在 8 位要多 18 MB，放不下，所以要先在 GPU 上看哪几类最敏感（`wbits_sens.py`）再定。
7. **只在最后降学习率的那一段按 4 位训练也一样好。** 长训练用的学习率表（`--schedule wsd`，5.37 节）最后 20% 降到 0，
   如果按 4 位训练只放在这一段里，硬件网络就可以像长训练那样，从中途另存的检查点分出"降学习率 + 按 4 位训练"的分支，
   不用为 4 位单独再训一次。同样的网络和批次，学习率表换成 wsd（最后 300 步降到 0）：

   | 做法 | 验证 loss（部署时的权重） | 和全精度训练的差 |
   |---|---|---|
   | 全精度训练（对照，wsd） | 2.667 | — |
   | 训练完再取整到 4 位 | 2.695 | +0.028 |
   | 最后 1/5（只在降学习率的那一段）按 4 位训练 | 2.685 | +0.018 |
   | 最后 1/3 按 4 位训练 | 2.685 | +0.018 |
   | 最后 1/5 按 4 位训练，输入行、读出、W_in 用 8 位 | **2.669** | **+0.002** |

   和余弦学习率表上的结果（第 1、6 点）一致：按 4 位训练让代价减半，从降学习率开始时才按 4 位训练就够了；再把最敏感的几类留在 8 位，代价几乎为 0。
   （这个小网络上 wsd 本身比余弦好 0.026，第二十四批的 138M 上则差 0.016，学习率表的比较不在这里展开。）

**词表不必放在片上**：有了两级读出，每一路每个 token 只用到词表的一小块——它这个词的输入行，和它抽中的那一类的约 215 个词读出神经元
（约 16.5 万个权重，8 位时 165 KB）。这些"词表"（输入行和词读出神经元，约 3,900 万个权重）可以放在 FPGA 板上的 HBM 里按需读，
16 路时每步读约 2.6 MB，HBM 只需约 5 微秒，远小于计算时间。必须放在片上的只是每一步都要用的部分：各层的突触、可塑突触和共用的读出神经元
（短名单 + 类），约 8,150 万个权重：全部 4 位约 41 MB，W_in 和可塑突触的键、查询输入用 8 位也只约 60 MB，都放得下。
`hw_cost.py` 现在记录词表的大小（`table_weights`），`fpga_est.py` 判断能否放在片上时不算它们，另外按每路每步读自己那几行计入 HBM 读取量。

**GPU 上训练完再取整**（`slurm/wbits.sbatch`，完整验证集，平均权重；每 128 个一组）：

| 网络 | 全精度 | 8 位 | 4 位 |
|---|---|---|---|
| 138M + 蒸馏 + 64 个键（`g21_kdwa138`） | 3.816 | +0.0005 | +0.148 |
| 212M（`g21_wa212`，训满 25 亿 token） | 3.541 | +0.0006 | +0.173 |
| 138M + 两级读出（`g25_cls`） | 3.887 | +0.0004 | +0.122 |
| 138M + 组合输入（`g25_inc`） | 3.839 | +0.0006 | +0.153 |
| 138M + 两者（`g25_io`） | 3.906 | +0.0003 | +0.129 |

- 8 位仍然没有损失。
- 4 位损失 0.12–0.17：比旧配方的 212M（+0.78）小得多，但仍是 CPU 上小网络（+0.034）的 4–5 倍。即使按 4 位训练能减半，也还剩约 0.07。
- 所以另外看哪类权重最敏感（`experiments/wbits_sens.py`）：片上存储还剩约 15 MB，可以让最敏感的那几类留在 8 位。
  CPU 上的小网络里，读出、输入行和 W_in 三类（占 60% 的权重，多用 1.7 MB）留在 8 位，4 位的损失从 +0.031 降到 +0.001。

**GPU 上哪类权重最敏感**（`experiments/wbits_sens.py`，训练完再取整，每 128 个一组；验证集里固定的 640 段、65.5 万个 token，
所以"全精度"一列和上表略有不同；各设置用同样的 token，差值是配对的）。只把某一类取整到 4 位、其余保持全精度时 loss 增加多少：

| 网络 | 全精度 | 读出 | W_in | 输入行 | W_out | 可塑突触（键和查询 / 值 / 输出） | 调节漏电的突触 | 全部 4 位 |
|---|---|---|---|---|---|---|---|---|
| `g21_kdwa138` | 3.822 | **+0.098**（3,860 万个权重） | +0.018 | +0.013 | +0.008 | +0.002 / +0.003 / +0.003 | +0.000 | +0.148 |
| `g25_io`（组合输入 + 两级读出） | 3.913 | **+0.071**（3,890 万） | +0.021 | +0.016（35 万） | +0.013 | +0.002 / +0.002 / +0.004 | +0.001 | +0.131 |
| `g21_wa212` | 3.546 | **+0.142**（5,150 万） | +0.012 | +0.005 | +0.010 | +0.002 / +0.003 / +0.002 | +0.001 | +0.175 |

再把最敏感的几类留在 8 位、其余 4 位：

| 网络 | 读出留 8 位 | 再加 W_in | 再加可塑突触的值输入和输出 |
|---|---|---|---|
| `g21_kdwa138` | +0.050 | +0.029 | +0.025 |
| `g25_io` | +0.045（输入行也留 8 位） | +0.019 | — |
| `g21_wa212` | +0.035 | +0.018 | — |

1. **4 位的损失大部分来自读出**：只把读出取整就占了全部损失的约 55%–80%。读出神经元的膜电位直接就是每个词的 logit，
   取整误差直接变成 5 万个词之间的打分误差，没有后面的层来"消化"。语言模型的量化文献里也通常把输出层留在高精度。
2. 其次是 W_in（+0.012–0.021），然后是输入行和 W_out；可塑突触和调节漏电的突触每类只有 0.000–0.004。
3. **对硬件网络来说，读出留在 8 位几乎不占片上存储**：两级读出里，词读出神经元（3,700 万个权重）本来就放在 HBM 里，
   每路每步只读抽中那一类的约 215 个（前面"词表不必放在片上"的估算已经按 8 位算）；片上只多了短名单和类的读出神经元（175 万个权重）多出的 0.9 MB。
4. 片上存储的账（138M + 64 个键 + 组合输入和两级读出、各带 2,048 个词的短名单；每 128 个权重一个 16 位系数）：

   | 留在 8 位的 | 片上的权重 | 加 16 路的膜电位（每路 1.33 MB） | 能否放进约 75.6 MB |
   |---|---|---|---|
   | 没有 | 42.4 MB | 63.6 MB | 能 |
   | 读出、输入行 | 43.3 MB | 64.5 MB | 能 |
   | 读出、输入行、W_in | 57.4 MB | 78.6 MB | 16 路放不下，13 路以内可以 |
   | 再加可塑突触的值输入和输出 | 62.2 MB | 83.4 MB | 10 路以内可以 |

   每路的状态里，可塑突触的状态（12 层 × 8 组 × 64 个键 × 64 个值通道，24 位）占了约九成。
   所以 W_in 留在 8 位的代价是同时生成的路数从 16 降到 13；值不值得，要看按 4 位训练以后 W_in 还剩多少损失。

**GPU 上的检验**（第二十八批，`gpu28.sh`）：在 `g27_io2k`（组合输入 + 两级读出，都带短名单）上，最后 25%（5,000 步）按 4 位训练，
一个全部 4 位，一个读出和输入行留在 8 位（`--wbits8 '^head\.,^embed\.'`；原计划的"每 64 个一组"在开始前换成了这一组，
因为上面的敏感度结果说明读出才是主要问题）。这两个起初是从头训的（前 15,000 步全精度，等于把 `g27_io2k` 再训一遍），
但每人最多同时用两张 A100-40，它们占着卡，第二十七批的两个训练排在后面等。所以 11 月 17 日晚把它们停了，改成从 `g27_io2k` 自己第 15,000 步
另存的检查点分出来，只训最后 5,000 步：省掉四分之三的算力，而且和 `g27_io2k` 的起点完全相同（权重、优化器状态、平均权重都一样），
两者的差就是 4 位的代价；同时把第二十一到二十七批全精度训练的网络取整到 8 位和 4 位后评估（`slurm/wbits.sbatch`），
看现在的配方（可塑突触、蒸馏）在 FineWeb 上训练完再取整要损失多少。

### 5.39 第二十九批：硬件网络训满

**目的**：阶段目标 3（在 FPGA 上和 GPU 上的 Transformer 比较）需要一个能整个放进 FPGA 片上存储、又训练充分的脉冲网络。
到这里为止，能放进片上的版本都只训了 20,000 步（6.55 亿 token），而比较要在质量相当时做（5.28 节）。这一批把它训满 25 亿 token，
并且按最终部署的精度训练，得到一个"能直接搬上 FPGA"的网络和它的质量。

**网络**（和 `g27_io2k` 相同，只是读出的短名单换成 8,192 个词，5.36 节第二十七批的中途结果）：
- 138M 的形状（12 层，每层 768 → 3072 个 LIF 神经元），每层前面 8 组 × 64 个键的可塑突触，写入按 (1 − λ) 缩放；
- 组合输入带 2,048 个最常用词的短名单，两级读出带 8,192 个（5.36 节）；
- 蒸馏，老师 `g13_tf163`（和第二十七、二十八批相同，便于对照；更强的老师 `g26_tf163` 在长训练里单独检验）。

**精度**：权重 4 位（每 128 个一组，各有一个 16 位系数），读出和输入行留在 8 位（5.38 节：读出占 4 位损失的大部分，留在 8 位在片上只多 0.9 MB）。
片上的权重 48.1 MB，加 16 路的膜电位和可塑突触状态（每路 1.33 MB）共 69.3 MB，放得进 AMD V80 可用的约 75.6 MB。

**学习率表和按 4 位训练的时机**：`--schedule wsd`，学习率保持不变，最后 20% 降到 0（同第二十六批）。按 4 位训练只在降学习率的那一段
（`--wbits_from` 设在降学习率开始处）。CPU 上核对过，这样和更早开始一样好（5.38 节第 7 点），而且前 80% 是全精度，
可以从同一个检查点分出全精度和不同精度的分支，配对比较。第二十八批（从 `g27_io2k` 第 15,000 步分出的两个 4 位分支）
会在这个训练进入 4 位阶段之前给出 GPU 上的第一组结果，如果有问题还来得及改。

| 训练 | 起点 → 终点 | 读过的 token | 精度 | 用来回答什么 |
|---|---|---|---|---|
| `g29_hw`（主训练） | 0 → 75,000 步 | 25 亿 | 4 位，读出和输入行 8 位 | 硬件网络本身；另存第 30,000 和 60,000 步的检查点 |
| `g29_hw_fp_b75000` | 60,000 → 75,000 | 25 亿 | 全精度 | 同一个网络在 25 亿 token 时 4 位的代价 |
| `g29_hw_m8w_b75000` | 60,000 → 75,000 | 25 亿 | 4 位，读出、输入行和 W_in 8 位 | W_in 留在 8 位值不值得（片上 62.2 MB，只能同时 10 路） |
| `g29_hw_q_b37500` | 30,000 → 37,500 | 12 亿 | 同主训练 | 硬件网络自己的"质量随训练量"的第二个点 |

- 75,000 步正好和第十三到二十一批的长度可比：同样形状、全词表、全精度的 `g18_kdmem138` 训满是 3.621。
- 分支都按主训练的做法在最后 20% 降学习率（`gpu29.sh branch START NAME`，终点是起点的 1.25 倍）。
- 训完以后：`fpga_est.py` 按实测的发放率估算 FPGA 上的吞吐和能耗，和 GPU 上实测的 Transformer 163M 比较（5.25、5.28 节的做法）。

**预计时间**：H100-96 上约 75–80k token/s（同形状、全词表读出的 `g21_kdwa138` 是 105k，两级读出训练时慢约四分之一），
主训练约 9 小时，从 60,000 步起的分支各约 1.8 小时，从 30,000 步起的约 0.9 小时。
